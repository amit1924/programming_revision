Phase 1 — Landing Page on S3

No servers needed for a static site. Create the bucket, turn on website hosting, and upload index.html.

1

Create & publish the S3 site

s3 mb → s3 website → s3 cp
Commands
awslocal s3 mb s3://www.amit.com
awslocal s3 website s3://www.amit.com --index-document index.html
awslocal s3 cp index.html s3://www.amit.com/
🏁
The "hello, world" of the stack

mb creates the bucket, website enables static website hosting with index.html as the default page, and cp uploads the file. On Floci the website config is real — the bucket reports its IndexDocument right back.

Phase 1 — run it live

Phase 2 — Serverless API with Lambda

The "backend": a Python function that answers /api/hello. On Floci this actually executes — the handler runs and returns real JSON.

2

Create & invoke the API function

zip → create-function → invoke
Commands
zip api.zip api.py
awslocal lambda create-function --function-name amit-api --runtime python3.12 --role arn:aws:iam::000000000000:role/lambda-exec --handler api.handler --zip-file fileb://api.zip
awslocal lambda invoke --function-name amit-api --cli-binary-format raw-in-base64-out --payload '{"route":"/api/hello"}' /tmp/api-out.json
cat /tmp/api-out.json
⚡
Code, not servers

Same recipe as Chapter 11: package code in a zip, register the function, then invoke it with an event. The handler reads route, builds a response, and returns it — and Floci really runs the Python. That response is your API.

Phase 2 — run it live
Remember the flag Keep --cli-binary-format raw-in-base64-out — the AWS CLI v2 default that works on real AWS, and required on Floci for the event to arrive.

Phase 3 — Web Tier on ECS

For pages that need a long-running server (not just static files), you spin up a container. Floci starts a real container here.

3

Create cluster → register task def → run the task

create-cluster → register-task-definition → run-task
Commands
awslocal ecs create-cluster --cluster-name amit-prod
awslocal ecs register-task-definition --family amit-web --network-mode awsvpc --cpu 256 --memory 512 --requires-compatibilities FARGATE --container-definitions '[{"name":"web","image":"nginx:latest","portMappings":[{"containerPort":80,"protocol":"tcp"}]}]'
awslocal ecs run-task --cluster amit-prod --task-definition amit-web:1 --launch-type FARGATE --count 1
🚢
Containerized web serving, for real

Cluster = the home, task definition = the blueprint (nginx image, port 80, Fargate), run-task = launch one copy. On Floci you can prove it: the task reports RUNNING and a real floci-ecs-…-web container appears in docker ps — exactly the ECS behavior you'd see on AWS.

Phase 3 — run it live

Phase 4 — DNS with Route 53

Give your stack a domain. Create a hosted zone for amit.com, then an A record for www pointing at your servers.

4

Hosted zone + www record

create-hosted-zone → change-resource-record-sets
Commands
awslocal route53 create-hosted-zone --name amit.com --caller-reference capstone-001
awslocal route53 change-resource-record-sets --hosted-zone-id /hostedzone/ZKVUNVVNTBBI2WZ --change-batch '{"Changes":[{"Action":"CREATE","ResourceRecordSet":{"Name":"www.amit.com","Type":"A","TTL":300,"ResourceRecords":[{"Value":"203.0.113.10"},{"Value":"203.0.113.11"}]}}]}'
🌐
Naming the stack

A hosted zone is the container for your domain's DNS records. The A record maps www.amit.com to two IPs (a multi-value/weighted-style answer — Route 53's "multiple answers per name"). The change goes INSYNC immediately on Floci.

Phase 4 — run it live

Phase 5 — CDN with CloudFront

Serve the S3 site from edge locations around the world. Create a distribution whose origin is the S3 bucket.

5

Create the distribution

create-distribution (S3 origin)
Command
awslocal cloudfront create-distribution --distribution-config '{"CallerReference":"capstone-cf-001","Comment":"amit.com CDN","Enabled":true,"Origins":{"Quantity":1,"Items":[{"Id":"s3-origin","DomainName":"www.amit.com.s3.amazonaws.com","S3OriginConfig":{"OriginAccessIdentity":""}}]},"DefaultCacheBehavior":{"TargetOriginId":"s3-origin","ViewerProtocolPolicy":"allow-all","AllowedMethods":{"Quantity":2,"Items":["GET","HEAD"]},"ForwardedValues":{"QueryString":false,"Cookies":{"Forward":"none"}},"MinTTL":0,"TrustedSigners":{"Enabled":false,"Quantity":0}}}'
⚡
Fast everywhere

The distribution bundles your origin (the S3 bucket) with a cache behavior (GET/HEAD, no query strings). Floci returns a .cloudfront.net domain instantly — on real AWS the same command takes a few minutes to reach Deployed.

Phase 5 — run it live

Phase 6 — Observe & Tear Down

First, see the whole stack in CloudWatch. Then tear it down in dependency order.

6

Watch the logs, then clean up

describe-log-groups → teardown chain
Commands
awslocal logs describe-log-groups --query "logGroups[].logGroupName"
# teardown — children first, parents last
awslocal cloudfront update-distribution ... --distribution-config '{"Enabled":false,...}'  # disable first
awslocal cloudfront delete-distribution --id EXHK8XLRTVGX55
awslocal route53 delete-hosted-zone --id /hostedzone/ZKVUNVVNTBBI2WZ
awslocal ecs stop-task --cluster amit-prod --task <task-id>
awslocal ecs delete-cluster --cluster amit-prod
awslocal ecs deregister-task-definition --task-definition amit-web:1
awslocal lambda delete-function --function-name amit-api
awslocal s3 rb s3://www.amit.com --force
🔭
See everything, then destroy everything

Every service you created logs into its own CloudWatch group (Lambda and ECS both do this on Floci) — one command shows the whole estate. Teardown follows the children-first rule: disable/delete the CDN before the S3 bucket, stop tasks before deleting the cluster, and so on. Real engineers tear down in this exact order so nothing gets orphaned.

Phase 6 — run it live
The teardown order is the test I hit DistributionNotDisabled while cleaning up this capstone — CloudFront refuses to delete a live distribution. Disable it (Enabled: false), let it reach Deployed, then delete. Same "children before parents" discipline as ECS's ClusterContainsTasksException and Route 53's HostedZoneNotEmpty. If your teardown runs clean the first time, you've internalized it.
