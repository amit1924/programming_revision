What Is EC2?

EC2 (Elastic Compute Cloud) is AWS's virtual server service. You ask AWS for a computer, and it hands you one — an instance — with the CPU, memory, and disk you chose, running the operating system you chose, placed in the network you built in Chapter 2. In seconds.

💻
Instance = a virtual machine

An instance is a computer running on AWS's physical hardware, isolated from all other customers. It behaves exactly like a real machine: it has an OS, you can install software, run services, open ports — but it's created with a command and destroyed with a command.

Where an EC2 lives (from Chapter 2)
🌍 Region (us-east-1)
 └── 🏙️ VPC 10.0.0.0/16
      └── 🏘️ Public subnet 10.0.1.0/24
           └── 💻 EC2 instance  ← the computer you rent
                ├── CPU + RAM (you pick the size)
                ├── OS (Amazon Linux / Ubuntu / Windows)
                └── 🛡️ Security Group (who can reach it)
Why "Elastic"? You can scale up (bigger instance), scale out (more instances), and scale down (fewer / smaller) — any time, automatically or by hand. Elastic = your computing can stretch like a rubber band, and you only pay for the stretched amount.

AMIs — the Recipe for Your Server

When you create an EC2 instance, AWS needs to know what operating system and software to install. You answer that with an AMI — Amazon Machine Image. Think of it as a recipe + photo of the hard drive: "a fresh Amazon Linux 2 with these settings."

🧑‍🍳
The recipe analogy

An AMI is like a baking recipe card. The instance is the cake you bake using it. The same AMI can bake any number of cakes (instances), each an exact copy. AWS pre-bakes many popular AMIs: Amazon Linux, Ubuntu, Windows Server — or you can save your own customized AMI and re-use it.

AMI → Instances
AMI (the recipe)
 amzn2-ami-...-x86_64-gp2
 │
 ├── 🎂 Instance 1   (same OS, same settings)
 ├── 🎂 Instance 2
 └── 🎂 Instance 3  ...as many as you want

Instance Types — Picking the Engine Size

An AMI says what OS. The instance type says how big the computer is — how many CPUs, how much RAM, what kind of storage. AWS names them like t2.micro: a family letter + generation number + size.

Name partMeaningExample
t / m / c / rFamily: t=cheap "burst", m=general, c=compute-heavy, r=RAM-heavyt2, m5, c5, r6
2/3/5/6Generation (newer = better hardware)t2 vs t3
micro/small/largeSize = how much CPU/RAMmicro = 1 vCPU, 1 GB
The one you'll use forever: t2.micro t2.micro = 1 vCPU + 1 GB RAM — the smallest, cheapest, and the classic AWS free-tier instance. Perfect for learning. Every course and tutorial uses it.

Key Pairs — the Key to Your Server

Your server needs to know who you are when you connect over SSH. Instead of passwords (which bots brute-force), Linux servers use key pair authentication: a matched pair of files.

Private key

The file AWS downloads for you (demo-key.pem). You keep it secret. It proves "I am me."

Public key

AWS installs this on the server at launch. The server checks your private key against it when you try to log in.

How SSH key auth works
You                          Server (EC2)
 │  private key demo-key.pem    │  has your public key
 │                              │
 │  ssh -i demo-key.pem ...     │
 │ ────────────────────────────→ │  "prove you have the
 │ ←──────────────────────────── │   matching private key"
 │  (only the real private key   │
 │   can answer correctly)       │
 ✓  Connected, safe, no password
Two rules to never break 1. AWS shows the private key only once at creation — if you lose it, you can't SSH in. 2. On Linux/macOS set permissions chmod 400 demo-key.pem or SSH refuses to use the key. We'll do both.

Create a key pair with Floci

This is Step 1 of every server you'll ever build in AWS:

Create a key pair (create → chmod → verify)
Breaking down the command
create-key-pair --key-name demo-key
Creates a new key pair named demo-key and returns the private key text.
--query "KeyMaterial" --output text > demo-key.pem
Extracts just the private key (KeyMaterial) and redirects it into a file with >.
chmod 400 demo-key.pem
Makes the file read-only by you. SSH refuses keys that are too permissive (security).

Security Groups — Who Can Reach Your Server

Remember the bodyguard from Chapter 2? Now it protects your actual server. A security group attached to your instance decides which ports are open from where. By default: nothing in, everything out. You must explicitly open the ports you need.

PortServiceWhy you open it
22SSHLog into a Linux server (NEVER to 0.0.0.0/0 in real life)
80HTTPServe a website to the world
443HTTPSServe a secure website
3306MySQLDatabase access (usually restricted to specific IPs)

User Data — Auto-Configure Your Server

A fresh server is empty. You don't want to log in and manually install everything every time. User data is a script AWS runs automatically the first time your instance boots. It turns "launch a server" into "launch a server that is already set up."

🎁
The one-time startup script

You pass a shell script as user data. On the first boot, the OS runs it as root. This is how modern teams bake configuration into instances — no manual clicking. (We'll meet this again in ECS and with tools like Terraform, where whole servers are built this way.)

What user data does
  awslocal ec2 run-instances \
     --user-data "#!/bin/bash
     yum install -y httpd
     echo hello > /var/www/html/index.html"
     │
     ▼  (instance boots)
┌──────────────────────────────┐
│  1. Server starts up         │
│  2. AWS runs your script     │  ← automatic
│  3. Apache installed ✅      │
│  4. Website content written  │
└──────────────────────────────┘
  Ready to serve — no manual steps!
Note for our course User data works on real EC2. On Floci the script is accepted (the instance remembers it) but the OS inside isn't actually booted, so the install doesn't run. The commands and outputs are real; the script is the real-world setup you'd use on AWS. We teach the exact syntax now so it's yours forever.

EC2 Pricing Models

EC2 pricing is a classic interview + exam topic. Four main ways to pay for a server:

ModelPayBest forCost
On-DemandPer second/hour, no commitmentShort, unpredictable workloads; learningHighest per-hour
Reserved / Savings Plan1–3 year commitmentSteady, predictable serversUp to ~70% cheaper
SpotBid on spare capacityFault-tolerant batch jobs (2am render jobs)Up to ~90% cheaper (can be reclaimed anytime)
Dedicated HostRent a whole physical serverLicensing / compliance needsMost expensive
For this course You'll use On-Demand against Floci — and it costs $0.00, because Floci emulates everything locally. When you try real AWS, the free tier gives you 750 hours of t2.micro every month for a year — basically free forever for learning.

Launch Your First EC2 — Command by Command

Time to combine everything. We'll create a key pair, open SSH+HTTP, and launch an actual instance on Floci — exactly the 4 steps you'd take on real AWS. Every command below works against your Floci right now (I verified them).

1

Create Your Key Pair

The key that lets you SSH into the server
Command
awslocal ec2 create-key-pair --key-name demo-key --query "KeyMaterial" --output text > demo-key.pem

chmod 400 demo-key.pem
🤔
What is a key pair?

A matched pair of cryptographic keys. AWS keeps the public key (installed on your server), and you keep the private key (in demo-key.pem). When you SSH in, your private key proves you're allowed — no password needed.

Run it live
Breaking down the command
awslocal ec2 create-key-pair --key-name demo-key
Asks AWS to create a new key pair called demo-key and return the private key text.
--query "KeyMaterial" --output text > demo-key.pem
Grabs just the private key (KeyMaterial) and redirects it (>) into a file. This is the only time AWS shows it.
chmod 400 demo-key.pem
Sets file permissions to read-only, owner only. SSH refuses loose permissions — this is mandatory.
2

Create a Security Group

The bodyguard deciding who can knock on the door
Commands
SG=$(awslocal ec2 create-security-group --group-name web-sg --description "Web SG" --query "GroupId" --output text)

awslocal ec2 authorize-security-group-ingress --group-id $SG --protocol tcp --port 22 --cidr 0.0.0.0/0
awslocal ec2 authorize-security-group-ingress --group-id $SG --protocol tcp --port 80 --cidr 0.0.0.0/0
🛡️
What is a security group?

A firewall attached to your instance. It's stateful: allowed-in traffic's replies flow back automatically. Default: deny all inbound. We open port 22 (SSH) so we can log in, and port 80 (HTTP) so the server can serve a website.

Breaking down the command
create-security-group --group-name web-sg --description "Web SG"
Creates the empty firewall in your account. Returns a GroupId (sg-...) stored in $SG.
authorize-security-group-ingress --group-id $SG
Adds an inbound rule ("ingress" = incoming) to the group $SG.
--protocol tcp --port 22 --cidr 0.0.0.0/0
"Allow TCP port 22 from anywhere." (0.0.0.0/0 = the whole internet.)
--port 80 ... --cidr 0.0.0.0/0
Second rule: allow port 80 (HTTP) from anywhere — so browsers can load your site.
Real-world habit Never open port 22 to 0.0.0.0/0 on a real server — bots scan the whole internet for open SSH. Use --cidr YOUR_IP/32 instead. We open it here only to show syntax; on Floci nothing is listening anyway.
3

Launch the Instance

The magic moment — a real server, in seconds
Command
IID=$(awslocal ec2 run-instances --image-id ami-0abcdef1234567890 --instance-type t2.micro --key-name demo-key --security-group-ids $SG --query "Instances[0].InstanceId" --output text)

echo "$IID"
🚀
What does run-instances do?

This is the one command that creates your server. It takes the AMI (which OS), the instance type (how big), the key pair (who can log in), and the security group (who can reach it) — and hands you a running computer. AWS returns an instance ID (i-...).

What you just assembled
AMI     ami-0abcdef1234567890  (Amazon Linux 2)
Type    t2.micro               (1 vCPU / 1 GB — free tier)
Key     demo-key               (your SSH login key)
SG      web-sg                 (SSH + HTTP open)
   │
   ▼
💻 i-0a1b2c3d...  ← your server, launching now
Run it live
Breaking down the command
run-instances
The action: "launch a new server." It's the EC2 equivalent of "power on a machine."
--image-id ami-0abcdef1234567890
Which AMI (operating system) to use — here Amazon Linux 2.
--instance-type t2.micro
How big: 1 vCPU + 1 GB RAM, the classic free-tier size.
--key-name demo-key
Which key pair to install so you can SSH in.
--security-group-ids $SG
Which firewall to attach (the one we opened for SSH + HTTP).
--query "Instances[0].InstanceId"
The response lists instances; grab the first one's ID and store it in $IID.
4

Verify, Then Clean Up

Check your server — then release it so you stop "paying"
Commands
awslocal ec2 describe-instances --instance-ids $IID --query "Reservations[].Instances[].[InstanceId,State.Name,PublicIpAddress]" --output text

awslocal ec2 terminate-instances --instance-ids $IID
🧹
Why clean up?

Every running instance is a meter that keeps counting. The cloud's promise is pay only for what you run — so when you're done, terminate. On Floci it's free anyway, but the habit is the same: launch → use → terminate.

Run it live
Breaking down the command
describe-instances --instance-ids $IID
"Tell me about this specific server." We read off its state (pending → running) and public IP.
terminate-instances --instance-ids $IID
Permanently deletes the server. On real AWS this stops the bill. There is no "undo" — but that's the point of the cloud.
Your mental architecture now
KEY PAIR (demo-key.pem) → who can log in
SECURITY GROUP (web-sg) → SSH(22) + HTTP(80) open
AMI (Amazon Linux 2) → the operating system
TYPE (t2.micro) → the engine size
  │
  ▼
💻 INSTANCE (i-...) → your server, alive & billable
Complete EC2 build — copy & paste everything at once 
# 1. Key pair (your SSH key)
awslocal ec2 create-key-pair --key-name demo-key --query "KeyMaterial" --output text > demo-key.pem
chmod 400 demo-key.pem

# 2. Security group — open SSH + HTTP
SG=$(awslocal ec2 create-security-group --group-name web-sg --description "Web SG" --query "GroupId" --output text)
awslocal ec2 authorize-security-group-ingress --group-id $SG --protocol tcp --port 22 --cidr 0.0.0.0/0
awslocal ec2 authorize-security-group-ingress --group-id $SG --protocol tcp --port 80 --cidr 0.0.0.0/0

# 3. Launch the instance
IID=$(awslocal ec2 run-instances --image-id ami-0abcdef1234567890 --instance-type t2.micro --key-name demo-key --security-group-ids $SG --query "Instances[0].InstanceId" --output text)
echo "$IID"

# 4. Check it's running, then clean up
awslocal ec2 describe-instances --instance-ids $IID --query "Reservations[].Instances[].[InstanceId,State.Name]" --output text
awslocal ec2 terminate-instances --instance-ids $IID
Final mental model — an EC2 is a pizza, ordered by command
AMI         = the recipe (Amazon Linux / Ubuntu / Windows)
Instance     = the pizza (your server)
Type         = the size (t2.micro = small, m5.large = big)
Key pair    = the key to the delivery box (SSH)
Security grp = who's allowed at the door (firewall)
User data   = the note "extra cheese" (startup script)
Terminate    = eating it (you stop paying!)

Glossary — Chapter 3

EC2

AWS's virtual server service. "Elastic Compute Cloud."

Instance

A single virtual machine you rent, with chosen CPU, RAM, OS.

AMI

Amazon Machine Image — a snapshot/recipe of an OS you launch instances from.

Instance type

The size of the machine (CPU/RAM), e.g. t2.micro.

Key pair

A private/public key pair used for SSH login without passwords.

Security Group

A stateful firewall attached to instances. Allow rules only.

User data

A shell script AWS runs automatically on the instance's first boot.

On-Demand

Pay per second/hour with no commitment. Most flexible, most expensive.

Spot Instance

Bid on spare capacity for up to ~90% off; AWS can reclaim anytime.

SSH

Secure Shell — the protocol to securely log into a Linux server.

Instance ID

Unique identifier for your server (i-...), used in every command.
