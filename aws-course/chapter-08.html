S3 — Simple Storage Service

Back in the very first chapter you created an S3 bucket. Now you'll actually understand it. S3 is AWS's object storage — the place for images, videos, backups, and static files. It's the "image storage" of your www.amit.com story, and it's the most-used service in all of AWS.

Why Object Storage?

Your EC2 server has a disk, your RDS database has tables. But websites need another kind of storage: files that don't change often and just need to be fetched — product photos, user avatars, videos, backups, PDFs.

Where does S3 fit in www.amit.com?
   EC2  = the computer (code, apps)
   RDS  = the database (users, orders)
   S3   = the warehouse 🏭 (photos, videos, backups)
        │
        ├─ product-photos/   (thousands of images)
        ├─ user-avatars/
        └─ backups/          (database dumps, old files)
📦
Object storage vs a hard drive

A hard drive works like a folder tree on one computer. Object storage is different: every file is a self-contained object (data + metadata + a unique key) living in a bucket. Buckets are unlimited in size, replicated across servers for durability (99.999999999% — "eleven 9s"), and accessible over the internet via a URL. You don't mount S3 like a disk — you put and get objects.

Why "eleven 9s" matters 99.999999999% durability means S3 is designed to lose essentially nothing, ever. Files are automatically stored across at least 3 availability zones. For backups and treasured data, this is the entire point.

The Bucket Model

Two levels, that's it: bucket (the warehouse) and object (one item with a key).

Bucket → folder → object
   Bucket: amit-photos      (globally unique name)
     └─ hello.txt              (object at the root)
     └─ notes/readme.md      (object with a "folder" in its key)

   URL: https://amit-photos.s3.amazonaws.com/notes/readme.md
ConceptWhat it means
BucketThe container. Its name is globally unique (shared across all AWS accounts). Holds unlimited objects.
KeyThe object's "path" — actually just its name. notes/readme.md looks like a folder but it's really one key.
ObjectA file plus its metadata. Objects live inside buckets.
ETagA hash of the object's content — how you verify a copy is identical.
VersionIdAn object's version number (appears when versioning is on).
Bucket names are global Because bucket names live in one worldwide namespace, amit-photos must be unique among every AWS customer on Earth. If it's taken, pick another. (On Floci, name conflicts work a bit more loosely — but the rule is real AWS fact.)

Storage Classes & Lifecycle

Not all files need the same speed. S3 has storage classes — cheaper tiers for data you rarely touch. Same object, same bucket, different cost.

ClassAccess speedCostUse for
STANDARDInstantHighestActive files — photos people view every day.
STANDARD_IAInstantLower + retrieval feeRarely read but need fast access (old backups).
GLACIERMinutes–hoursVery lowLong-term archives you rarely open.
DEEP_ARCHIVEUp to 12 hoursLowestCompliance archives kept for years.
⏳
Lifecycle rules = auto-declining costs

You don't want to manually move 10,000 files between classes. A lifecycle rule says: "after 30 days, move everything under notes/ to STANDARD_IA; after 90 days, to GLACIER." S3 does it automatically, every day, forever. Set it once, forget it.

Versioning — The Undo Button

By default, uploading a file with the same key replaces the old one. With versioning on, every upload becomes a new version, and old versions survive. Overwrote a file by mistake? Restore the previous version. Deleted a file? Versioning keeps it (as a delete marker) until you want it gone.

Versioning in action
   hello.txt v1  "hello from s3"
        │  (upload v2)
        ▼
   hello.txt v2  "version two"     ← currently served
        │  (delete)
        ▼
   delete marker  (file disappears, v1+v2 still stored)
        │  (restore v1)
        ▼
   hello.txt v1  "hello from s3"   ← back!
The two kinds of "delete" With versioning on, a normal s3 rm only adds a delete marker (a tombstone hiding the file). To truly erase a specific version, you delete by version ID. This is why versioned buckets are the safe default for backups — accidents become recoverable.

Security — Policies & Access

Buckets are private by default. Two tools control who gets in (this links straight back to IAM in Chapter 5):

MechanismWho it applies toExample
IAM policiesUsers/roles (people & services)Rahul (IAM user) can read this bucket.
Bucket policiesAnyone — even anonymous *"Everyone on the internet can GetObject here" (public site).
ACLsSimple grants on bucket/objectGive one account write access.
The two decisions
   "Who is asking?"   →  IAM policy  (is this user allowed?)
   "What can the public do?" →  bucket policy  (is it world-readable?)

   Both must say yes for the request to succeed (IAM + bucket policy overlap).
Public ≠ private — read carefully A bucket policy with "Principal": "*" and "Action": ["s3:GetObject"] makes objects public. That's how static websites work (you want the world to read), but it's also how people accidentally leak private data. Only make public what you truly want public.

Static Website Hosting

S3 can serve static websites — HTML, CSS, JS — for pennies, with no servers at all. You just configure an index document (the home page) and an error document, and S3 turns your bucket into a website.

Static hosting on S3
   Bucket: amit-photos  (website mode ON)
     └─ index.html   ← visited when you hit /
     └─ error.html   ← shown when a page is missing

   User → https://amit-photos.s3-website-us-east-1.amazonaws.com → index.html

   No EC2. No servers. S3 just serves the files. 🎉
🏗️
When to use S3 website hosting

Perfect for landing pages, docs, single-page apps (the frontend of your app!) — anything with no backend logic. In Chapter 9 you'll put CloudFront in front of S3 to make these sites fast worldwide. Static site + S3 + CloudFront = one of the most popular architectures on the internet.

Hands-On: Your Image Store on Floci

Let's build the warehouse for www.amit.com — command by command. Create a bucket, upload, download, turn on versioning, add a website, and clean up.

1

Create a Bucket

The warehouse for your files
Command
awslocal s3 mb s3://amit-photos
🏗️
What did this just do?

s3 mb = make bucket — the friendly CLI shortcut. You created a container named amit-photos. Buckets are free to create (you pay only for what's stored), they're region-specific, and the name must be globally unique on real AWS. The s3:// prefix is just the CLI's way of saying "this is an S3 path."

Run it live
Breaking down the command
s3 mb s3://amit-photos
make bucket — the friendly CLI shortcut for s3api create-bucket.
s3://amit-photos
The S3-style path: scheme + bucket name.
s3api list-buckets
The API-level command — shows name + creation date.
mb vs s3api
s3 commands are friendly & human; s3api returns raw JSON. You'll use both.
2

Upload an Object

Put your first file in the warehouse
Commands
awslocal s3 cp hello.txt s3://amit-photos/hello.txt
awslocal s3api put-object --bucket amit-photos --key notes/readme.md --body hello.txt --query "ETag"
📤
Two ways to upload

s3 cp is the friendly copy command — nice progress bar, same syntax as copying files locally. s3api put-object is the low-level API: it returns the object's ETag (a hash of the content). Notice notes/readme.md looks like a nested folder — it's really just a key with a slash in its name. S3 has no real folders.

Run it live
Breaking down the commands
s3 cp hello.txt s3://amit-photos/hello.txt
Copy a local file into the bucket. The --recursive flag copies whole folders.
s3api put-object --bucket ... --key notes/readme.md --body hello.txt
Raw API upload. --key is the object's name/path.
ETag
A content hash — proves the object uploaded intact.
s3 ls s3://amit-photos/ --recursive
List everything in the bucket, including "subfolders."
3

Download an Object

Fetch files back to your machine
Commands
awslocal s3 cp s3://amit-photos/hello.txt downloaded.txt
awslocal s3api get-object --bucket amit-photos --key hello.txt --query "ContentLength" file.bin
📥
The reverse of upload

s3 cp s3://... . copies an object back to your local disk. get-object is the API version — you give it a --query to see a field like ContentLength and a local filename to write to. Getting files out of the warehouse is as easy as putting them in.

Run it live
Breaking down the commands
s3 cp s3://amit-photos/hello.txt downloaded.txt
Copy an object out to your local disk.
s3api get-object ... file.bin
Raw API download — the last argument is the local filename.
ContentLength
Metadata showing the object's size in bytes.
4

Turn On Versioning

Give your warehouse an undo button
Commands
awslocal s3api put-bucket-versioning --bucket amit-photos --versioning-configuration Status=Enabled
awslocal s3api get-bucket-versioning --bucket amit-photos --query "Status"
🔁
What changed?

Versioning is now Enabled for this bucket. From this point, every upload creates a new version instead of replacing the old one. Overwrite hello.txt? Both versions exist. Delete it? A delete marker hides it, but the file survives. You can even download an old version by its VersionId — a full undo button.

Run it live
Breaking down the commands
s3api put-bucket-versioning ... Status=Enabled
Turns on versioning — one-way on real AWS (you can suspend, not fully undo).
s3api get-bucket-versioning
Verify the bucket's versioning state.
s3api list-object-versions
See every version of an object + which is latest.
VersionId
A unique ID per version — you can get-object --version-id any of them.
Versioning only protects from this point Objects uploaded before versioning was enabled don't get version numbers automatically (they're the "null" version). Turn versioning on for buckets you care about before bad things can happen — it's the classic "wish I'd enabled it" setting.
5

Move an Object to a Cheaper Class

STandard → STANDARD_IA for rarely-read files
Command
awslocal s3api copy-object --bucket amit-photos --copy-source amit-photos/notes/readme.md --key notes/readme-glacier.md --storage-class STANDARD_IA
💸
Copy to change class

S3 doesn't "edit" an object's class in place — you copy it (even onto itself) with --storage-class STANDARD_IA. The result: cheaper storage for data you rarely read. For the classic GLACIER archive tier, you'd use --storage-class GLACIER and accept minutes-to-hours retrieval times.

Run it live
Breaking down the command
s3api copy-object --copy-source amit-photos/notes/readme.md
Copies within the bucket — source path in bucket/key form.
--key notes/readme-glacier.md
The new object's key (can be same or different).
--storage-class STANDARD_IA
The cheaper Infrequent Access tier.
s3api head-object
Fetch an object's metadata without downloading the whole file.
Automate it with lifecycle rules For thousands of files you'd never run this by hand. A lifecycle rule — put-bucket-lifecycle-configuration — says "after 30 days move notes/* to STANDARD_IA" and S3 does the rest automatically. Set once, forget forever.
6

Turn the Bucket Into a Website

index.html + a public-read policy
Commands
awslocal s3api put-bucket-website --bucket amit-photos --website-configuration '{"IndexDocument":{"Suffix":"index.html"},"ErrorDocument":{"Key":"error.html"}}'
awslocal s3api put-bucket-policy --bucket amit-photos --policy '{"Version":"2012-10-17","Statement":[{"Sid":"PublicRead","Effect":"Allow","Principal":"*","Action":["s3:GetObject"],"Resource":["arn:aws:s3:::amit-photos/*"]}]}'
🌐
The two pieces of a public website

put-bucket-website tells S3 which file is the home page (and which is the error page). But a website is no good if nobody can read it — so put-bucket-policy makes the objects public via a bucket policy: Principal: "*" (anyone), Action: s3:GetObject (read). These two together are how S3 serves a static site.

Run it live
Breaking down the commands
s3api put-bucket-website
Sets which object serves as the index (home) page and error page.
IndexDocument.Suffix: index.html
Visitors hitting / get index.html.
s3api put-bucket-policy
A JSON permission document on the bucket itself.
"Principal": "*"
Applies to everyone — this is what makes it public.
"Action": ["s3:GetObject"]
Only read — nobody can write or delete.
"Resource": ["arn:aws:s3:::amit-photos/*"]
Applies to every object in the bucket (the * wildcard).
Remember Chapter 5's IAM lesson This bucket policy is an Allow for the whole world. It's correct for a public website — but it's the exact same mechanism people misuse to leak private files. Always ask: "does this data deserve Principal: *?" If not, use IAM roles (Chapter 5) instead.
7

Clean Up — Empty Then Delete

A bucket must be empty before it can be deleted
Commands
awslocal s3api delete-bucket-policy --bucket amit-photos
awslocal s3 rm s3://amit-photos/ --recursive
awslocal s3 rb s3://amit-photos
🧹
Delete in order

Bucket policies, objects, then the bucket. s3 rm --recursive empties everything, and s3 rb (remove bucket) only works on an empty bucket. Same create → use → delete habit, one more time — on real AWS, leftover S3 data quietly bills you forever.

Run it live
Breaking down the cleanup
s3api delete-bucket-policy
Removes the public-read policy first.
s3 rm s3://amit-photos/ --recursive
Deletes all objects in the bucket.
s3 rb s3://amit-photos
Remove bucket — only succeeds on an empty bucket.
Complete S3 flow — copy & paste 
# 1. Create a bucket + upload
awslocal s3 mb s3://amit-photos
echo "hello from s3" > hello.txt
awslocal s3 cp hello.txt s3://amit-photos/hello.txt
awslocal s3api put-object --bucket amit-photos --key notes/readme.md --body hello.txt

# 2. Download it back
awslocal s3 cp s3://amit-photos/hello.txt downloaded.txt
awslocal s3api get-object --bucket amit-photos --key hello.txt file.bin

# 3. Turn on versioning (the undo button)
awslocal s3api put-bucket-versioning --bucket amit-photos --versioning-configuration Status=Enabled
echo "version two" > v2.txt
awslocal s3 cp v2.txt s3://amit-photos/hello.txt
awslocal s3api list-object-versions --bucket amit-photos --prefix hello.txt

# 4. Cheaper storage class for rarely-read files
awslocal s3api copy-object --bucket amit-photos --copy-source amit-photos/notes/readme.md --key notes/readme-glacier.md --storage-class STANDARD_IA
awslocal s3api head-object --bucket amit-photos --key notes/readme-glacier.md

# 5. Static website: home page + public read
awslocal s3api put-bucket-website --bucket amit-photos --website-configuration '{"IndexDocument":{"Suffix":"index.html"},"ErrorDocument":{"Key":"error.html"}}'
awslocal s3api put-bucket-policy --bucket amit-photos --policy '{"Version":"2012-10-17","Statement":[{"Sid":"PublicRead","Effect":"Allow","Principal":"*","Action":["s3:GetObject"],"Resource":["arn:aws:s3:::amit-photos/*"]}]}'

# 6. Clean up (policy, objects, then bucket)
awslocal s3api delete-bucket-policy --bucket amit-photos
awslocal s3 rm s3://amit-photos/ --recursive
awslocal s3 rb s3://amit-photos
Final mental model — S3 in one picture
S3 = the unlimited, indestructible warehouse for files.

   Bucket    = the warehouse (globally unique name)
   Object    = one file + its key + metadata
   Key       = the file's name (slashes = fake folders)
   Versioning= the undo button (keep old copies)
   Classes   = pay less for cold data (STANDARD → GLACIER)
   Policy    = who can read/write (IAM users + bucket policy)

   Name it, put it, get it. That's S3.
Honest note — what Floci does & doesn't support I tested this live. S3 on Floci supports buckets, upload/download, versioning (enable + list versions), delete markers, storage-class copies, static website config, and bucket policies — every command above ran against the emulator. Not implemented on Floci: real ACLs, presigned URLs, cross-region replication, and true object lifecycle execution (the config saves fine, but objects won't literally move tiers over time offline). Also, since there's no public internet, the static website won't actually respond at a URL here — the config is real, the serving isn't. Commands are 100% accurate for real AWS.

Glossary — Chapter 8

S3

Simple Storage Service — AWS's object storage (the warehouse for files).

Bucket

A container for objects, with a globally unique name.

Object

A file stored in S3: data + metadata + a key.

Key

The object's name/path (slashes make it look like folders).

ETag

A content hash used to verify an object copied intact.

Versioning

Keeps old versions of objects — an undo button for your data.

VersionId

A unique ID for each version of an object.

Delete marker

With versioning on, a "delete" just adds a tombstone hiding the file.

Storage class

The cost/speed tier of an object — STANDARD, STANDARD_IA, GLACIER...

Lifecycle rule

Automatically moves objects between storage classes over time.

Bucket policy

A JSON permission document applied to a bucket (can make objects public).

Durability

"Eleven 9s" — 99.999999999% designed durability via multi-AZ replication.
