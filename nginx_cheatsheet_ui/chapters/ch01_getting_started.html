What is NGINX?

nginx (pronounced "engine x") is a web server that has gained incredible popularity among the most highly visited websites on the internet.

It isn't fair to think of nginx as just a web server. It can do so much more — it can serve HTTP and HTTPS traffic, proxy to Rails, PHP or Node applications, run as a software load balancer, HTTP cache, off-load SSL, or even act as an SMTP, POP3, and IMAP mail server.

Most people think of nginx as a replacement to Apache. According to Netcraft, as of March 2015, nginx is used by 21% of the top 1 million busiest websites on the internet.

Core Concept

At its very core, nginx is an HTTP router — a living, breathing part of the web stack that gives developers the flexibility to build and deploy web apps easier than ever before.

Installing from Source

While it's possible to run nginx on Windows, it's not recommended. This guide assumes you're installing on a common distribution of Linux.

You have two installation options: directly from source or a pre-built package for your operating system. While installing the package is much more convenient, it's typically an outdated version. Fortunately, nginx.org publishes their own set of up-to-date packages.

Stable vs Mainline Versions

Stable

Even-numbered release (e.g. "1.4", "1.6"). Recommended production version. Lags behind major feature development but gets critical bug fixes backported.

Mainline

Odd-numbered release (e.g. "1.9"). Active development, still pretty stable. Receives new features and faster bug fixes. Many choose to run mainline in production.

Building from Source

Head to nginx.org and download the source. Once you have the tarball:

$ tar -zxvf nginx-1.9.2.tar.gz
$ cd nginx-1.9.2
$ ./configure
$ make
$ sudo make install

Installing Build Tools

If you don't have the basic build tools installed:

Ubuntu / Debian
$ apt-get install build-essential
RedHat / CentOS
$ yum group install "Development Tools"

Dependencies

nginx's default build configuration depends on 3 libraries:

PCRE

Used by the HTTP Rewrite module for regular expressions

Zlib

Used by the HTTP Gzip module for compression

OpenSSL

Required for HTTPS protocol support

Install dependencies on Ubuntu/Debian:

$ apt-get install libpcre3-dev zlib1g-dev libssl-dev

Install Location

By default, make install installs nginx and all related files into /usr/local/nginx/. The binary is located at:

/usr/local/nginx/sbin/nginx

Test that everything is working:

$ /usr/local/nginx/sbin/nginx -V
nginx version: nginx/1.9.2
built by gcc 4.8.2 (Ubuntu 4.8.2-19ubuntu1)
configure arguments:

Specifying Install Location

You can change the installation path with --prefix and --conf-path flags. For example, to place the binary in /usr/sbin and configuration in /etc/nginx:

$ ./configure --prefix=/usr --conf-path=/etc/nginx

Modules in nginx

nginx is an extremely modular piece of software. Even seemingly "built-in" features such as gzip or SSL are built as modules that can be enabled or disabled during build time.

One benefit of building from source is specifying exactly which modules you want. The downside: if you need something later that you didn't include, you'll have to rebuild.

By default, nginx comes with the following modules — some enabled and some disabled by default:

Enabling Modules

Enable modules by passing --with-http_module flags to the configure script. For example, to enable SSL:

$ ./configure --with-http_ssl_module

A recommended build with SSL, SPDY, RealIP, and Stub Status:

$ ./configure --with-http_ssl_module \
               --with-http_spdy_module \
               --with-http_realip_module \
               --with-http_stub_status_module
$ make
$ sudo make install

Third Party Modules

In addition to the many built-in modules, nginx has a massive library of third party modules that aren't packaged with the main distribution.

You can find the modules on wiki.nginx.org. There are over 100 third party modules, including everything from embedded Lua scripting to upload progress bars.

Installing from a Package

Installing nginx from your distribution's package manager is easier and faster compared to building from source. The tradeoff is that distribution packages are often outdated and you won't be able to install third party modules.

That being said, nginx provides its own up-to-date pre-built packages for many popular Linux distributions, including RedHat, CentOS, Debian, Ubuntu, and SLES.

Another advantage of packages is that they come with the necessary init or upstart scripts to easily run nginx as a daemon or automatically start after a reboot.

RedHat / CentOS Package

$ sudo yum install nginx

Ubuntu / Debian Package

$ sudo apt-get install nginx

Installing nginx.org Package (Ubuntu/Debian)

First, grab the nginx signing key so the package manager can validate authenticity:

$ wget http://nginx.org/keys/nginx_signing.key
$ sudo apt-key add nginx_signing.key

Find your Ubuntu/Debian codename:

$ lsb_release -a
No LSB modules are available.
Distributor ID: Ubuntu
Description: Ubuntu 14.04.1 LTS
Release: 14.04
Codename: trusty

For Ubuntu, add to /etc/apt/sources.list:

deb http://nginx.org/packages/ubuntu/ codename nginx
deb-src http://nginx.org/packages/ubuntu/ codename nginx

For Debian, add to /etc/apt/sources.list:

deb http://nginx.org/packages/debian/ codename nginx
deb-src http://nginx.org/packages/debian/ codename nginx

Update apt and install:

$ apt-get update
$ apt-get install nginx

Verify the installation:

$ nginx -V
nginx version: nginx/1.9.2 (Ubuntu)
built by gcc 4.8.2 (Ubuntu 4.8.2-19ubuntu1)
TLS SNI support enabled
configure arguments:

Exercises

Test your understanding of NGINX installation and modules:

1

What does NGINX stand for and what is it?

Explain what nginx is, what it can do, and what percentage of the top 1 million busiest websites use it.

nginx (pronounced "engine x") is a web server used by highly visited websites. It can serve HTTP/HTTPS, proxy to Rails/PHP/Node, act as a load balancer, HTTP cache, SSL offloader, and mail server. As of March 2015, it was used by 21% of the top 1 million busiest websites.
2

Stable vs Mainline

What is the difference between the stable and mainline versions of nginx?

Stable (even-numbered, e.g. 1.6) is the recommended production version with critical bug fixes backported. Mainline (odd-numbered, e.g. 1.9) is active development — still stable but receives new features and faster bug fixes.
3

Build from Source Steps

List the four commands to build and install nginx from source.

(1) ./configure, (2) make, (3) sudo make install. Plus before that: tar -zxvf nginx-*.tar.gz and cd into the folder.
4

Build Dependencies

Name the three libraries that nginx depends on for its default build configuration.

PCRE (HTTP Rewrite module), Zlib (HTTP Gzip module), and OpenSSL (HTTPS protocol support).
5

Check nginx Version

What command do you use to check the nginx version and compile-time build options?

nginx -V (capital V). It prints the version number, compiler info, and configure arguments.
6

Module Enablement

What configure flag would you use to enable the SSL module in nginx?

--with-http_ssl_module. Modules are enabled at build time by passing extra flags to ./configure.
7

Package vs Source Tradeoffs

What are the tradeoffs between installing nginx from a package manager vs building from source?

Package manager is easier and includes init scripts, but versions are often outdated and you cannot install third-party modules. Building from source gives full control over modules and latest version, but requires build tools and manual management.
8

Adding nginx.org Repository

Describe the steps to add the nginx.org package repository on Ubuntu.

(1) wget the nginx signing key, (2) sudo apt-key add the key, (3) add "deb http://nginx.org/packages/ubuntu/ codename nginx" and "deb-src ..." to /etc/apt/sources.list, (4) apt-get update, (5) apt-get install nginx.
9

Custom Install Path

How would you configure a build of nginx to install the binary in /usr/sbin and the configuration files in /etc/nginx?

Run ./configure with --prefix=/usr and --conf-path=/etc/nginx. The --prefix flag changes the base installation directory and --conf-path specifies the config file location.
10

Modules Architecture

Why is nginx considered "extremely modular"? Give two examples of features that are actually built as modules.

Even "built-in" features like gzip and SSL are implemented as modules that can be enabled/disabled at build time. This lets you build a minimal nginx with only the modules you need.
