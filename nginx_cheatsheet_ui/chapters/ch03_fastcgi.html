How CGI Works

CGI (Common Gateway Interface) was officially born in 1997. It is a programming language–independent interface for web servers to communicate with programs or scripts on the web server.

CGI gave programmers the ability to write dynamic web applications by extending the web server software. When a web server receives a request for a CGI script, it simply executes the script directly and returns the output to the browser.

#!/usr/bin/php

<?php

echo "Content-Type: text/plain\n";
echo "PHP-CGI Script! Woohoo<br>";
echo time();
?>

The cgi-bin directory designates which programs are safe to run. CGI passes the HTTP request context to the script as environment variables, allowing the script to access things like the Request URI, Client IP Address, or Server Host.

Variable Definition Example
GATEWAY_INTERFACE The version of the CGI protocol being used by the web server. CGI/1.1
SERVER_SOFTWARE The name of the web server software making the CGI call. nginx
QUERY_STRING The HTTP query string of the web request. foo=bar&foobar=1
REQUEST_METHOD The HTTP request method. POST
CONTENT_TYPE The HTTP Content-Type. text/plain
CONTENT_LENGTH The Length of the HTTP Request. 100
SCRIPT_FILENAME The path of the CGI script being executed. /var/www/cgi-bin/test.php
SCRIPT_NAME The virtual path of the CGI script. /cgi-bin/test.php
REQUEST_URI The path to the requested file by the client. /cgi-bin/test.php?foo=bar
DOCUMENT_URI The path part of the URL to the CGI script. /cgi-bin/test.php
DOCUMENT_ROOT The root path of the server. /var/www/html
SERVER_PROTOCOL The type of protocol being used by the client/server. HTTP/1.0
REMOTE_ADDR The IP Address of the client. 108.22.12.23
REMOTE_PORT The port of the client. 9583
SERVER_ADDR The IP Address of the server. 192.168.10.1
SERVER_PORT The port of the server. 80
SERVER_NAME The server hostname. app01
# Passing CGI environment variables from the command line
REMOTE_IP=127.0.0.1 ./script.php

What is FastCGI?

nginx does not support regular, old-school CGI. In the traditional CGI model, the web server forks and executes the script for each request — a slow and expensive system call.

Traditional CGI

Web server executes script directly. Slow performance (fork per request). Insecure: any script in cgi-bin can be executed.

FastCGI

Web server talks to a FastCGI server daemon instead. Long-running process, handles many connections. Better performance and security.

With FastCGI, the web server makes a TCP or Unix Socket request to the FastCGI server, which runs the script and returns the result. The FastCGI server is typically long-running and does not need to fork for each request.

PHP-FPM (PHP FastCGI Process Manager) has been built into PHP since version 5.3 and handles almost all FastCGI details automatically.

Two ways to use nginx with a backend

FastCGI — primarily for PHP applications. Reverse Proxy — for Ruby, Node, Go, and most other languages.

FastCGI Basic Config

Consider a simple PHP script:

<?php

echo "Running a script from nginx<br>";
echo time();
?>

Install and configure PHP-FPM:

  • Install: apt-get install php5-fpm
  • Config: /etc/php5/fpm/pool.d/www.conf
  • Start: service php5-fpm start

Basic FastCGI config that matches a single PHP script:

location ~ script.php {
  fastcgi_pass unix:/var/run/php5-fpm.sock;
  fastcgi_index index.php;
  include fastcgi_params;
}

The FastCGI server uses the SCRIPT_FILENAME parameter to determine which PHP script to execute. By default it is set to:

SCRIPT_FILENAME = $document_root$fastcgi_script_name

$fastcgi_script_name is set automatically by nginx based on the request URI path:

  • If URI ends in /, the fastcgi_index value is appended (e.g. /foobar/ becomes /foobar/index.php)
  • Otherwise, $fastcgi_script_name is simply set to the request URI

Watch out for old syntax!

Please be warned about something important! Most nginx/PHP tutorials online are wrong and can expose backdoors. Pay close attention to cgi.fix_pathinfo and fastcgi_split_path_info — they are critical for security.

Many Individual PHP Files

In the real world, one common FastCGI/PHP configuration is when you have many individual PHP files in a single directory and want them to all be individually executable. This pattern is straightforward with the basic FastCGI configuration using a \.php$ location block.

Route All Requests Through index.php

The other typical scenario, especially for modern PHP frameworks such as Zend Framework or Laravel, is to have all requests go through a central index.php file:

server {
  location / {
    try_files $uri $uri/ index.php$is_args$args;
  }

  location ~ \.php$ {
    try_files $uri /index.php =404;
    fastcgi_pass upstream;
    fastcgi_index index.php;
    fastcgi_split_path_info ^(.+\.php)(.*)$;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_scriptName;
  }
}

Don't trust the nginx/PHP Tutorials!

Most websites and tutorials for configuring nginx and PHP are wrong. More than wrong, in fact, they unknowingly expose you to a backdoor — a misconfigured nginx server can allow non-PHP files to be executed as PHP. An attacker could upload their own PHP file (e.g. through an image uploader) and convince PHP-FPM to execute it.
