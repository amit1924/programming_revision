Chapter 2: Docker Commands

Every Docker command explained simply — with real terminal output

docker run docker ps docker stop docker rm docker images docker rmi docker pull docker run ubuntu docker exec Attach / Detach
docker run

Start a Container

The docker run command creates and starts a container from an image. Think of it like: "Take this image and spin up a living container from it."

Basic command:

$ docker run nginx
Unable to find image 'nginx:latest' locally
latest: Pulling from library/nginx
Digest: sha256:2f7c7b4e5f5e5b2f0a1b3c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3e4f
Status: Downloaded newer image for nginx:latest
... (nginx starts and runs in foreground, blocking the terminal)
What happened? Docker looked for the nginx image locally, didn't find it, so it pulled it from Docker Hub layer-by-layer, then started the container. The container runs in the foreground (attached mode) — your terminal is now hooked to nginx's output.
docker ps

List Running Containers

docker ps shows containers that are currently running. Add -a to see all containers — including stopped ones.

Running containers only:

$ docker ps
CONTAINER ID   IMAGE     COMMAND                  CREATED         STATUS         PORTS     NAMES
a1b2c3d4e5f6   nginx     "/docker-entrypoint.…"   2 minutes ago   Up 2 minutes   80/tcp    silly_sammet

All containers (including stopped):

$ docker ps -a
CONTAINER ID   IMAGE     COMMAND                  CREATED             STATUS                     PORTS     NAMES
a1b2c3d4e5f6   nginx     "/docker-entrypoint.…"   2 minutes ago       Up 2 minutes               80/tcp    silly_sammet
b2c3d4e5f6a7   redis     "docker-entrypoint.s…"   About an hour ago   Exited (0) 5 minutes ago             focused_edison
Columns explained: Each container gets a random CONTAINER ID and NAME. The STATUS column shows Up if running or Exited if stopped.
docker stop

Stop a Container

docker stop sends a SIGTERM signal to the main process inside the container, giving it time to shut down gracefully. It's like saying "please finish your work and exit." 

$ docker stop silly_sammet
silly_sammet
Docker echoes back the container name to confirm. After stopping, docker ps no longer shows it — but docker ps -a still will, with status Exited (0).

Verify with docker ps -a:

$ docker ps -a | head -3
CONTAINER ID   IMAGE     STATUS                      NAMES
a1b2c3d4e5f6   nginx     Exited (0) 2 seconds ago   silly_sammet
docker rm

Remove a Container

docker rm permanently deletes a container. This is different from docker stop — stopping keeps the container around (you can restart it). Removing is like throwing it in the trash. The image is not affected — just the container instance. 

$ docker rm silly_sammet
silly_sammet

The container is now completely gone — even docker ps -a won't show it:

$ docker ps -a | grep silly_sammet
(no output — container is deleted!)
Pro tip: Need to remove a running container? Use docker rm -f container_name (force remove, which stops it first).
docker images

List Downloaded Images

docker images lists all images you've pulled (or built) on your machine. Each image has a REPOSITORY (name), TAG (version, latest by default), IMAGE ID, CREATED, and SIZE. 

$ docker images
REPOSITORY   TAG       IMAGE ID       CREATED       SIZE
nginx        latest    a1b2c3d4e5f6   2 weeks ago   109MB
redis        latest    b2c3d4e5f6a7   3 weeks ago   107MB
ubuntu       latest    c3d4e5f6a7b8   4 weeks ago   112MB
alpine       latest    d4e5f6a7b8c9   4 weeks ago   4.14MB
Notice: Alpine Linux is only 4.14 MB vs Ubuntu at 112 MB. Alpine is a stripped-down Linux distro — perfect for minimal Docker images. Nginx and Redis are both around 100+ MB.
docker rmi

Remove Images

docker rmi deletes an image from your machine. You must remove any containers (stopped or running) that depend on the image first — Docker won't let you delete an image that's in use. 

$ docker rmi nginx
Untagged: nginx:latest
Untagged: nginx@sha256:2f7c7b4e5f5e5b2f0a1b3c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3e4f
Deleted: sha256:a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2
Deleted: sha256:b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2c3
Deleted: sha256:c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2c3d4
What's with all the SHA256 hashes? Docker images are built from layers. Each Deleted: sha256:... line is one layer being removed. If two images share a layer, Docker won't delete it until both images are gone.
docker pull

Download an Image (Without Running)

docker pull downloads an image from a registry (like Docker Hub) but does not start a container. Think of it like "download the installer but don't run it yet." 

$ docker pull nginx
Using default tag: latest
latest: Pulling from library/nginx
a603fa5e3b41: Pull complete
c2e42a3e1a2b: Pull complete
3d3b3c9a4a5b: Pull complete
Digest: sha256:2f7c7b4e5f5e5b2f0a1b3c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3e4f
Status: Downloaded newer image for nginx:latest
docker.io/library/nginx:latest
pull vs run: docker run nginx = docker pull nginx + docker start container. If the image is already cached locally, run skips the pull step.
docker run ubuntu

Running Ubuntu — Why It Exits Immediately

When you run docker run ubuntu, the container starts and immediately exits. This confuses a lot of beginners! Here's why:

Ubuntu exits instantly — no process to keep it alive:

$ docker run ubuntu
(nothing happens — container starts and exits immediately)

$ docker ps -a | grep ubuntu
CONTAINER ID   IMAGE   STATUS                     NAMES
e5f6a7b8c9d0   ubuntu  Exited (0) 3 seconds ago   romantic_goldberg

Make it stay alive with sleep:

$ docker run ubuntu sleep 5
(waits 5 seconds, then exits)

$ docker ps -a | grep ubuntu
CONTAINER ID   IMAGE   STATUS                     NAMES
f6a7b8c9d0e1   ubuntu  Exited (0) 2 seconds ago   priceless_morse
Why? A container lives only as long as its main process is running.
— nginx runs a web server process that stays alive → container stays up.
— ubuntu has no default process (it's just an OS filesystem) → container exits immediately.
— sleep 5 runs for 5 seconds → container lives 5 seconds.
docker exec

Execute a Command in a Running Container

docker exec lets you run a command inside a container that's already running. It's like SSH'ing into the container — without actually needing SSH. 

$ docker exec silly_sammet cat /etc/hosts
127.0.0.1   localhost
172.17.0.2  a1b2c3d4e5f6
Use cases: Check config files, inspect logs, run diagnostic tools, or open an interactive shell with docker exec -it silly_sammet /bin/bash.
attach / detach

Attached vs Detached Mode

By default, docker run runs in attached mode — your terminal is hooked to the container's output. Use -d (detach) to run in the background and reclaim your terminal.

Attached (foreground) — blocks your terminal:

$ docker run kodekloud/simple-webapp
 * Serving Flask app 'app'
 * Running on http://0.0.0.0:5000/ (Press CTRL+C to quit)
172.17.0.1 - - [20/May/2026 10:15:32] "GET / HTTP/1.1" 200 -
172.17.0.1 - - [20/May/2026 10:15:33] "GET / HTTP/1.1" 200 -
(terminal is blocked — you can see live logs)

Detached (background) — get your terminal back:

$ docker run -d kodekloud/simple-webapp
a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2c3
$ (terminal is free — container runs in background)

Re-attach to a detached container:

$ docker attach a1b2c3d4e5f6
172.17.0.1 - - [20/May/2026 10:16:00] "GET / HTTP/1.1" 200 -
172.17.0.1 - - [20/May/2026 10:16:01] "GET / HTTP/1.1" 200 -
(you're now re-connected to the container's output)
Analogy: Attached mode is like watching a movie in the theater (you're locked in). Detached mode is like starting a movie on a server and walking away — it plays without you. Use -d for production services that should run in the background.
