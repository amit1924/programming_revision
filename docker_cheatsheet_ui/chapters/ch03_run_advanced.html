1. Run with Tags

A tag is a version label for a Docker image. When you run a container without specifying a tag, Docker automatically uses the latest tag — which points to the most recent version.

Default tag — latest
$ docker run redis
Unable to find image 'redis:latest' locally
latest: Pulling from library/redis
... (pulls the latest Redis 7.x)
Specific tag — 4.0
$ docker run redis:4.0
Unable to find image 'redis:4.0' locally
4.0: Pulling from library/redis
... (pulls the older Redis 4.0)

Different versions may have different features, configs, and security patches. Always pin a specific tag in production so your app doesn't unexpectedly upgrade.

2. Run with STDIN (-i, -it)

Some applications need keyboard input — like a prompt asking for your name. Three different ways to run:

No flags — detached from STDIN
$ docker run kodekloud/
simple-prompt-docker
What is your name?
Hello (empty — no input provided)
-i — interactive (can type)
$ docker run -i kodekloud/
simple-prompt-docker
What is your name?
(type:) Amit
Hello Amit
-it — interactive + TTY terminal
$ docker run -it kodekloud/
simple-prompt-docker
What is your name?
(full terminal:) Amit
Hello Amit

-i keeps STDIN open so you can type input. -t allocates a pseudo-TTY which gives you a proper terminal experience (shell prompt, colors, etc.). Use -it together for most interactive apps.

3. Port Mapping (-p)

Every container gets an internal IP on your machine (like 172.17.0.2). But that internal IP is only accessible from the host — not from your browser or the outside world. Port mapping bridges this gap.

Basic port mapping
$ docker run -p 80:5000 kodekloud/simple-webapp
* Running on http://0.0.0.0:5000/ (Press CTRL+C to quit)
# Now visit http://localhost:80 in your browser
Three real examples:
$ docker run -p 3306:3306 mysql

Host port 3306 → container 3306 (default MySQL port)

$ docker run -p 8306:3306 mysql

Host port 8306 → container 3306 (custom host port)

$ docker run -p 8000:5000 webapp1
$ docker run -p 8001:5000 webapp2

Two web apps on ports 8000, 8001 → both use internal 5000

Analogy: Think of an apartment buzzer system. Your container's internal port (5000) is like an apartment unit number. The host port (80) is the main building address. You dial the building address + the apartment number to reach the specific unit. Without port mapping, nobody can reach your apartment from outside.

4. Volume Mapping (-v)

Containers are ephemeral — when you delete one, all its data vanishes. Volume mapping lets you store data on your host machine so it survives container restarts and removals.

Mount host directory /opt/datadir to MySQL's data directory
$ docker run -v /opt/datadir:/var/lib/mysql mysql
# MySQL now writes all database files to /opt/datadir on your host
# Delete the container: docker rm container_id
# Start a new one with the same -v flag — all your data is still there!

Analogy: Imagine your container is a laptop and the volume is an external hard drive. If your laptop breaks (container deleted), you just plug the external drive into a new laptop (new container) and all your files are still there. Format: host_path:container_path.

5. docker inspect

docker inspect returns a massive JSON document with every possible detail about a container. Use it when you need to troubleshoot or understand a container's configuration.

Basic usage
$ docker inspect container_name
Partial output (key fields shown)
[
"Id": "abc123...",
"Name": "/my_container",
"Path": "python",
"Args": ["app.py"],
"State": {
"Status": "running",
"Running": true,
"StartedAt": "2025-01-15T..."
},
"Mounts": [{ "Source": "/opt/data", "Destination": "/var/lib/data" }],
"Config": { "Entrypoint": ["python3"], "Env": ["APP_COLOR=blue"] },
"NetworkSettings": { "IPAddress": "172.17.0.2" }
}]

Key fields: Id, Name, State.Status, Mounts, Config.Entrypoint, NetworkSettings.IPAddress. Highlighted lines above are the most commonly inspected.

6. docker logs

docker logs shows everything your application printed to the console — useful for debugging or checking if a service started correctly.

View logs of a running container
$ docker logs webapp
* Running on http://0.0.0.0:5000/ (Press CTRL+C to quit)
* Restarting with stat
Enter a number to play the game: 5
Enter a color: blue
[INFO] User chose blue — starting game...

Pro tip: Use docker logs -f container_name (--follow) to stream logs in real time — like tail -f.
