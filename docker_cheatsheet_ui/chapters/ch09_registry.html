Docker Registry

Chapter 9 — Storing and Sharing Docker Images

Docker Hub Third-Party Private Registry Deploy Your Own

1. Docker Hub (docker.io)

Think of Docker Hub as the "App Store" for Docker images. It is the default public registry that Docker uses when you don't specify a registry URL. When you run docker run nginx, Docker automatically pulls from Docker Hub.

Pulling from Docker Hub

# Pull the official nginx image (latest tag by default)
$ docker pull nginx
Using default tag: latest
latest: Pulling from library/nginx
... digest: sha256:abc... status: downloaded

# Run a container from the image
$ docker run -d -p 8080:80 --name my-nginx nginx
a1b2c3d4e5f6...

$ curl localhost:8080
<!DOCTYPE html>
<title>Welcome to nginx!</title>

Image Naming

# Full image name breakdown:
registry/user/image:tag

# For Docker Hub, "library" is the default user
# for official images:
docker.io/library/nginx:latest

# Official images maintained by Docker & vendors
$ docker run python:3.12-slim # Python official
$ docker run ubuntu:22.04 # Ubuntu official
$ docker run node:20-alpine # Node.js official

Key points: Docker Hub hosts over 100,000 container images. Official images are verified, regularly updated, and follow best practices. You can also push your own images to Docker Hub for free (one private repo, unlimited public).

2. Third-Party Registries

Other registries work just like Docker Hub — they store images at a different URL. You specify the registry hostname as part of the image name.

Registry URL Used by
Google Container Registry gcr.io Google Cloud Platform
Amazon ECR 123456789.dkr.ecr.us-east-1.amazonaws.com AWS
Azure Container Registry myregistry.azurecr.io Microsoft Azure
Red Hat / Quay.io quay.io Red Hat / community

Example: Pulling from gcr.io

# Format: registry_url/user_or_project/image_name
# Pull a Kubernetes e2e test image from Google's registry:
$ docker pull gcr.io/kubernetes-e2e-test-images/dnsutils:1.3
1.3: Pulling from kubernetes-e2e-test-images/dnsutils
... digest: sha256:def... status: downloaded

# Run it:
$ docker run --rm gcr.io/kubernetes-e2e-test-images/dnsutils:1.3 nslookup google.com

3. Private Registry

Companies host private registries to store internal images that shouldn't be public. You authenticate with docker login, then push/pull just like Docker Hub.

Login to Private Registry

$ docker login private-registry.io
Username: mycompany
Password: ********
Login Succeeded

# Credentials stored here (unencrypted!):
$ cat ~/.docker/config.json
{
"auths": {
"private-registry.io": {
"auth": "bXl1c2VyOm15cGFzcw=="
}
}
}

Warning: Your password is stored as base64-encoded (not encrypted!) in ~/.docker/config.json. Anyone with access to your machine can decode it.

Run from Private Registry

# Format: registry_hostname/path:tag
$ docker run private-registry.io/apps/internal-app:2.1
Unable to find image 'private-registry.io/apps/internal-app:2.1' locally
2.1: Pulling from apps/internal-app
... status: downloaded

# Push your own image to private registry:
$ docker tag my-app:latest private-registry.io/apps/my-app:latest
$ docker push private-registry.io/apps/my-app:latest

Why private registries? Security (keep proprietary code internal), speed (host registry on your network), and control (manage access, retention, scanning).

4. Deploy Your Own Registry

Run a private registry in seconds using the official registry:2 image. Perfect for local development, CI/CD pipelines, or air-gapped environments.

Full Workflow

# Step 1: Deploy the registry container
$ docker run -d -p 5000:5000 --name registry registry:2
a1b2c3d4e5f6...
Unable to find image 'registry:2' locally
2: Pulling from library/registry... status: downloaded

# Step 2: Verify it's running
$ docker ps --filter name=registry
CONTAINER ID IMAGE COMMAND STATUS PORTS
a1b2c3d4e5f6 registry:2 "/entrypoint.sh /etc…" Up 2 minutes 0.0.0.0:5000->5000/tcp

# Check the registry API (should return {})
$ curl http://localhost:5000/v2/
{}

Tag & Push

# Tag an existing image for the local registry
$ docker image tag nginx localhost:5000/my-nginx

# Push it to the local registry
$ docker push localhost:5000/my-nginx
The push refers to repository [localhost:5000/my-nginx]
... layer(s) pushed

# Verify with the API
$ curl http://localhost:5000/v2/_catalog
{"repositories":["my-nginx"]}

Pull & Remote Access

# Pull from local registry (no docker login needed)
$ docker pull localhost:5000/my-nginx
Using default tag: latest
latest: Pulling from my-nginx
... status: downloaded

# From another machine on the network:
$ docker pull 192.168.56.100:5000/my-nginx
... Pulling from my-nginx ...

Note on security: The default registry runs without TLS (HTTP). For production, add TLS certificates or use a reverse proxy (like Nginx) with HTTPS. Docker requires HTTPS for external (non-localhost) registries unless you configure insecure-registries in /etc/docker/daemon.json.

Commands Summary

docker run -d -p 5000:5000 --name registry registry:2
Start the registry
docker tag IMAGE localhost:5000/NAME
Tag for local registry
docker push localhost:5000/NAME
Push image
docker pull localhost:5000/NAME
Pull image
curl localhost:5000/v2/_catalog
List images in registry
docker stop registry && docker rm registry
Stop & clean up

Key Takeaways

Docker Hub is the default public registry. docker run nginx pulls from docker.io/library/nginx.
Third-party registries (gcr.io, ECR, ACR) work identically but use their own URL prefix.
Private registries require docker login — credentials are stored in ~/.docker/config.json.
Local registry is a single docker run registry:2 away. Tag → push → pull.
