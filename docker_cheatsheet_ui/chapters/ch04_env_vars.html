Chapter 4: Environment Variables

Making your containers configurable without changing code

What are ENVs? Hardcoded App App with ENV Docker -e Flag Inspect ENV

What are Environment Variables?

Environment variables are configuration values passed to your application at runtime. Think of them as settings you can tweak without ever touching the source code.

Simple Analogy

Imagine you're going out. You can choose your shirt color before leaving — red, blue, or green. You don't need to buy a new shirt; you just pick the option available to you. That's what environment variables are — a choice you make at startup, not at manufacturing time.

App without ENV (Hardcoded)

Without environment variables, your application's behavior is baked into the code. To change anything, you must edit the source and rebuild.

app.py 
# Hardcoded — always red, forever
from flask import Flask
app = Flask(__name__)

color = "red"

# The app will always display red
# If you want blue, you edit this file
# Then you redeploy the whole app

Problem: To change the color from red to blue, you must edit app.py and redeploy the entire application. That's rigid, error-prone, and slow.

App with ENV Variable

With environment variables, the same code behaves differently based on what you pass in at runtime.

app.py (with ENV) 
import os
from flask import Flask
app = Flask(__name__)

# Read color from environment, default to "red"
color = os.environ.get('APP_COLOR', "red")

# Same code, any color you want!
# export APP_COLOR=blue  → app is blue
# export APP_COLOR=green → app is green
# no export               → app is red (default)

You set the variable before running your script:

$ export APP_COLOR=blue
$ python app.py      # app runs with BLUE background

Same code, different behavior. No edits, no rebuilds — just pass a different value at runtime.

ENV Variables in Docker

Docker makes this incredibly easy. Use the -e flag with docker run to set environment variables:

$ docker run -e APP_COLOR=blue simple-webapp-color

Want a different color? Just change the value — same image, different behavior:

Blue App

APP_COLOR=blue

Green App

APP_COLOR=green

Pink App

APP_COLOR=pink

Simple Analogy

It's the same microwave, but you can set the time to 30 seconds for reheating coffee or 5 minutes for popcorn. The microwave doesn't change — your settings (environment variables) do.

Inspect Environment Variables

Use docker inspect to see all environment variables a running container was launched with:

$ docker inspect container_name

The output is a large JSON object. Look under Config → Env for the array of environment variables:

"Config": {
  "Env": [
    "APP_COLOR=blue",        # ← Your custom variable
    "PATH=/usr/local/bin:...",  # ← Docker defaults
    "PYTHON_VERSION=3.9.5",    # ← From base image
    "HOME=/root"
  ]
}

Docker automatically adds some defaults (like PATH, HOME) based on the base image. Your custom variable (APP_COLOR) appears right alongside them.

Tip: Pipe to grep to quickly find your variable: docker inspect container_name | grep APP_COLOR

Key Takeaways

Environment variables let you configure apps without changing code

Read them in Python with os.environ.get('KEY')

Set them in Docker with docker run -e KEY=val ...

Inspect with docker inspect under Config → Env
