What am I containerizing?

Anything. A Docker image packages your application + everything it needs to run — code, runtime, libraries, environment variables, config files.

Web Apps

Flask, Express, Django, Rails

Databases

MySQL, Postgres, MongoDB, Redis

Scripts & CLIs

Python scripts, cron jobs, utilities

Example: A Python Flask web app that serves a simple API. The image contains Python, Flask, your source code, and starts the Flask dev server when the container runs.

How to create my own image?

You write a Dockerfile — a simple text file that is a recipe for building your image. It tells Docker what base OS to start from, what software to install, what files to copy, and what command to run.

Example Dockerfile

# Dockerfile — Python Flask App
FROM Ubuntu                    # 1. Start with base OS
RUN apt-get update             # 2. Update apt repos
RUN apt-get install python     # 3. Install Python
RUN pip install flask          # 4. Install Flask
RUN pip install flask-mysql    # 5. Install DB driver
COPY . /opt/source-code        # 6. Copy source code
ENTRYPOINT FLASK_APP=app.py flask run  # 7. Run the app

Build & push commands

# Build the image (tag it with a name)
$ docker build Dockerfile -t mmumshad/my-custom-app

# Push to Docker Hub (or any registry)
$ docker push mmumshad/my-custom-app

That's it — your app is now a portable Docker image!

Dockerfile Format

Every line in a Dockerfile follows the same pattern: INSTRUCTION argument. The instruction is always UPPERCASE, followed by its arguments.

Instruction What it does Example
FROM Base image to start from FROM ubuntu:22.04
RUN Execute a command during build RUN apt-get install -y python3
COPY Copy files from host into image COPY . /app
ADD Like COPY but supports URLs & tar ADD https://example.com/file.tar.gz /
WORKDIR Set working directory WORKDIR /app
ENV Set environment variable ENV FLASK_APP=app.py
EXPOSE Document which port the app uses EXPOSE 5000
CMD Default command (can override) CMD ["python", "app.py"]
ENTRYPOINT Fixed command (hard to override) ENTRYPOINT ["python"]

Layered Architecture

Every instruction in a Dockerfile creates a new layer. Docker caches each layer, so if you rebuild you only rebuild the layers that changed. This makes builds fast and efficient.

Analogy: Like a layer cake — each instruction adds one layer. If you need a second cake with the same bottom layers, you reuse them!

Building our example image — layer by layer

Layer 1: Base Ubuntu 120 MB
Layer 2: apt packages (apt-get install python) 306 MB
Layer 3: pip packages (flask, flask-mysql) 6.3 MB
Layer 4: Source code (COPY .) 229 B
Layer 5: Entrypoint (ENTRYPOINT) 0 B

Reuse bonus: If you build a second similar app, layers 1–3 (Ubuntu + apt + pip) are already cached. Docker reuses them — only layers 4–5 are new!

Docker Build Output

When you run docker build, you see each layer being built step-by-step. If a layer fails, fix the issue and rebuild — Docker skips cached layers and restarts from the failed step.

Successful build

$ docker build -t my-app .
[+] Building 12.4s (8/8) FINISHED
 => [1/5] FROM ubuntu:22.04                         2.1s
 => [2/5] RUN apt-get update                        3.8s
 => [3/5] RUN apt-get install -y python3            4.2s
 => [4/5] RUN pip install flask flask-mysql         1.9s
 => [5/5] COPY . /opt/source-code                   0.1s

Failed build & rebuild

$ docker build -t my-app .
 => [1/5] FROM ubuntu:22.04                         2.1s  CACHED
 => [2/5] RUN apt-get update                        3.8s  CACHED
 => [3/5] RUN apt-get install -y python3            4.2s  CACHED
 => [4/5] RUN pip install flask flask-mysql         1.9s  CACHED
 => ERROR [5/5] COPY . /opt/source-code

 --- fix the error ---

$ docker build -t my-app .
 => [1/5] FROM ubuntu:22.04                         2.1s  CACHED
 => [2/5] RUN apt-get update                        3.8s  CACHED
 => [3/5] RUN apt-get install -y python3            4.2s  CACHED
 => [4/5] RUN pip install flask flask-mysql         1.9s  CACHED
 => [5/5] COPY . /opt/source-code                   0.1s  (fixed!)

Layers 1–4 were cached from the first attempt. Only layer 5 (the one that failed) needed to be rebuilt. This is the superpower of Docker's layered architecture!

What can you containerize?

Everything. Any application, any language, any stack. If it runs on Linux (or Windows), it can run in a container.

Node.js App

FROM node:18 + COPY . + npm start

Python Script

FROM python:3.11 + pip install + python app.py

Java Service

FROM eclipse-temurin:17 + COPY .jar + java -jar app.jar

Go Binary

FROM golang:1.21 + go build + ./app

CMD vs ENTRYPOINT

Two instructions that look similar but behave differently. Think of them this way:

CMD = Default setting

Provides a default command that can be overridden when the container runs.

ENTRYPOINT = Fixed mode

Sets a fixed command that cannot be easily overridden — arguments get appended instead.

CMD only — overridable

# Dockerfile
FROM ubuntu
CMD ["sleep", "5"]
# Runs "sleep 5" (uses CMD)
$ docker run ubuntu-sleeper

# Overrides CMD — runs "sleep 10" instead
$ docker run ubuntu-sleeper sleep 10

ENTRYPOINT only — appends arguments

# Dockerfile
FROM ubuntu
ENTRYPOINT ["sleep"]
# Appends "10" as argument to "sleep"
$ docker run ubuntu-sleeper 10

# This runs: sleep 10

ENTRYPOINT + CMD — best of both

# Dockerfile
FROM ubuntu
ENTRYPOINT ["sleep"]   # fixed command
CMD ["5"]              # default argument
# Uses default CMD: sleep 5
$ docker run ubuntu-sleeper

# Overrides CMD: sleep 10
$ docker run ubuntu-sleeper 10

# To override entrypoint itself:
$ docker run --entrypoint sleep2.0 ubuntu-sleeper 10

Analogy: CMD is like the default preset on a microwave (you can change it). ENTRYPOINT is like the microwave mode button — you can set a time (CMD), but the mode stays fixed.

CMD vs ENTRYPOINT — Quick Reference

CMD ENTRYPOINT
Purpose Provide defaults Set the main command
Override Easy — just pass args Hard — needs --entrypoint
Arguments pass Replaces entire CMD Appended to entrypoint
Combine with Works as default args for ENTRYPOINT Can take default args from CMD
Shell form CMD command arg ENTRYPOINT command arg
Exec form CMD ["cmd","arg"] ENTRYPOINT ["cmd","arg"]
