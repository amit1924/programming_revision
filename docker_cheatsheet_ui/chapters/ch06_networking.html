Networking

How containers talk to each other and the outside world — bridges, DNS, and network topologies.

Default Networks

Docker automatically creates three built-in networks when the daemon starts. Every container you run connects to one of them — bridge is the default.

Simple Analogy

  • Bridge = Gated community — each house has its own address, shares the gate (docker0) to reach the outside.
  • Host = Living in the main house — you use the same front door as everyone else, no privacy.
  • None = Isolated cabin in the woods — you have no road, no mail, no connection to anything.

bridge (default)

All containers get a private IP in the 172.17.0.0/16 range and communicate through the virtual docker0 switch.

$ docker run nginx # uses bridge by default

host

Container shares the host's network stack. No isolation, same IP and ports as the host. No port mapping needed.

$ docker run --network=host nginx

none

Completely isolated — no network interfaces except lo (loopback). Perfect for offline/security-sensitive workloads.

$ docker run --network=none alpine sleep 3600

Default Network Topology

┌─────────────────────────────────────────────────────┐ │ Host Machine │ │ ┌───────────────────────────────────────────────┐ │ │ │ docker0 bridge (172.17.0.1) │ │ │ │ ┌──────────┐ ┌──────────┐ │ │ │ │ │ Container │ │ Container │ │ │ │ │ │ web │ │ db │ │ │ │ │ │ 172.17.0.2 │ │ 172.17.0.3 │ │ │ │ │ └────┬─────┘ └────┬─────┘ │ │ │ │ └──────┬──────┘ │ │ │ │ docker0 │ │ │ └──────────────┼────────────────────────────────┘ │ │ │ eth0 (192.168.1.10) │ │ ┌─────┴──────┐ │ │ │ Internet │ │ │ └────────────┘ │ └─────────────────────────────────────────────────────┘

Containers on the default bridge can reach each other by IP but not by name. External traffic requires -p port mapping.

Bridge Network Details

Every container on the default bridge network gets a private IP assigned from the 172.17.0.0/16 subnet. The host itself acts as gateway at 172.17.0.1.

# Run two containers and check their IPs $ docker run -d --name c1 nginx $ docker run -d --name c2 nginx # Inspect container IP $ docker inspect c1 --format {{.NetworkSettings.IPAddress}} 172.17.0.2 $ docker inspect c2 --format {{.NetworkSettings.IPAddress}} 172.17.0.3 # Ping from one container to another (by IP) $ docker exec c1 ping -c 2 172.17.0.3 PING 172.17.0.3 (172.17.0.3) 56(84) bytes of data. 64 bytes from 172.17.0.3: icmp_seq=1 ttl=64 time=0.123 ms

Communication

  • ✓ Containers talk to each other via IP
  • ✓ Traffic goes through docker0 bridge
  • ✓ Outbound internet works (NAT via iptables)
  • ✗ No DNS by name (on default bridge)

External Access

  • Use -p hostPort:containerPort to expose
  • Example: -p 8080:80 maps host 8080 → container 80
  • Docker adds iptables DNAT rules automatically
  • Without -p, no external access

Port Mapping Example

# Host port 8080 → container port 80 $ docker run -d -p 8080:80 --name web nginx # Now visit http://localhost:8080 $ curl -sI http://localhost:8080 | head -1 HTTP/1.1 200 OK

User-Defined Networks

User-defined networks give you better isolation and — most importantly — DNS resolution by container name. You create them with docker network create.

# Create a custom bridge network with a specific subnet $ docker network create --driver bridge --subnet 182.18.0.0/16 custom-isolated-network # List all networks $ docker network ls NETWORK ID NAME DRIVER SCOPE a2b3c4d5e6f7 bridge bridge local 9f8e7d6c5b4a host host local 1a2b3c4d5e6f none null local e7f8a9b0c1d2 custom-isolated-network bridge local # Run containers attached to the custom network $ docker run -d --network custom-isolated-network --name web nginx $ docker run -d --network custom-isolated-network --name db mysql # Verify IP assignment on our custom subnet $ docker inspect web --format {{.NetworkSettings.Networks.custom-isolated-network.IPAddress}} 182.18.0.2 $ docker inspect db --format {{.NetworkSettings.Networks.custom-isolated-network.IPAddress}} 182.18.0.3

Key Benefits Over Default Bridge

  • ✓ DNS resolution by container name (huge!)
  • ✓ Better isolation — containers not on the network cannot reach each other
  • ✓ Can connect/disconnect containers on the fly
  • ✓ Custom subnets, gateways, and IP ranges

Example: Frontend & Backend Networks

┌──────────────────────────────────────────────────────────┐ │ Host │ │ │ │ frontend-net (182.18.0.0/16) backend-net (182.19.0.0/16) │ │ ┌──────────────────────┐ ┌──────────────────────┐ │ │ │ ┌────────────────┐ │ │ ┌────────────────┐ │ │ │ │ │ web │ │ │ │ api │ │ │ │ │ │ 182.18.0.2 │ │ │ │ 182.19.0.2 │ │ │ │ │ └────────────────┘ │ │ └────────────────┘ │ │ │ └──────────────────────┘ └──────────────────────┘ │ │ │ │ db (attached to both networks) │ │ ┌────────────────────────────┐ │ │ │ frontend-net: 182.18.0.3 │ │ │ │ backend-net: 182.19.0.3 │ │ │ └────────────────────────────┘ │ └──────────────────────────────────────────────────────────┘
# Create two networks $ docker network create frontend-net --subnet 182.18.0.0/16 $ docker network create backend-net --subnet 182.19.0.0/16 # web is only on frontend-net $ docker run -d --network frontend-net --name web nginx # api is only on backend-net $ docker run -d --network backend-net --name api nginx # db connects to BOTH (acts as bridge) $ docker run -d --name db mysql $ docker network connect frontend-net db $ docker network connect backend-net db

Inspect Network

Use docker inspect to view all network configuration details for a container. The NetworkSettings section shows IP, gateway, MAC, and per-network info.

# Full inspect output (abbreviated) $ docker inspect web { "NetworkSettings": { "Bridge": "docker0", "Gateway": "172.17.0.1", "IPAddress": "172.17.0.2", "IPPrefixLen": 16, "MacAddress": "02:42:ac:11:00:02", "Networks": { "bridge": { "Gateway": "172.17.0.1", "IPAddress": "172.17.0.2", "MacAddress": "02:42:ac:11:00:02" } } } }
# Quick IP lookup $ docker inspect web --format '{{ .NetworkSettings.IPAddress }}' 172.17.0.2
# Per-network IP $ docker inspect web --format '{{ .NetworkSettings.Networks .custom-net.IPAddress }}' 182.18.0.2

Useful Inspect Fields

Field Path Value Description
.NetworkSettings.IPAddress 172.17.0.2 Primary IP on the default bridge
.NetworkSettings.Gateway 172.17.0.1 Default gateway (the host)
.NetworkSettings.MacAddress 02:42:ac:11:00:02 MAC address of the container's veth
.NetworkSettings.Networks {...} Map of all networks the container is on

Embedded DNS

Docker runs a built-in DNS server at 127.0.0.11 inside every container. It resolves container names to IPs automatically — but only on user-defined networks.

Think of it like phone contacts: On the default bridge you must dial IPs (phone numbers). On a user-defined network, Docker's DNS acts like your contact list — call mysql instead of remembering 172.17.0.3.

# Create a user-defined network $ docker network create app-net # Run a database container $ docker run -d --network app-net --name mysql -e MYSQL_ROOT_PASSWORD=secret mysql:8 # Run a web container — it can reach "mysql" by name! $ docker run -it --network app-net --name web nginx # From inside the web container: $ docker exec web ping mysql -c 2 PING mysql (182.18.0.2) 56(84) bytes of data. 64 bytes from mysql.app-net (182.18.0.2): icmp_seq=1 ttl=64 time=0.089 ms 64 bytes from mysql.app-net (182.18.0.2): icmp_seq=2 ttl=64 time=0.102 ms # Verify DNS server inside container $ docker exec web cat /etc/resolv.conf nameserver 127.0.0.11 options ndots:0

Works On

  • ✓ User-defined bridge networks
  • ✓ User-defined overlay networks (Swarm)
  • ✓ docker-compose networks

Does NOT Work On

  • ✗ Default bridge network
  • ✗ host network mode
  • ✗ none network mode

Full Example: Web + MySQL by Name

# 1. Create a custom network $ docker network create app-net # 2. Start MySQL (no port needed — internal only) $ docker run -d --network app-net --name mysql \ -e MYSQL_ROOT_PASSWORD=secret mysql:8 # 3. Start web app that connects via DNS name "mysql" $ docker run -d --network app-net --name web \ -p 8080:80 my-web-app # 4. The web app can now connect to the database using # the hostname "mysql" — Docker DNS resolves it. # No hardcoded IPs needed! # Verify resolution from within web container: $ docker exec web getent hosts mysql 182.18.0.2 mysql

Quick Reference

Command Description Example
docker network ls List all networks docker network ls

docker network rm Remove a network docker network rm my-net
docker network connect Attach container to network docker network connect my-net my-container
docker network disconnect Detach container from network docker network disconnect my-net my-container
docker network inspect Show network details docker network inspect my-net
