COUNT vs COUNTA — Numbers vs Anything

COUNT counts numbers only (blanks and text ignored). COUNTA ("count all") counts every non-empty cell.

A — job_title_shortM — salary_year_avg
2Data Analyst100000
3Data Scientist150000
4Data Analyst(blank)
5Data Engineer130000
=COUNT(M2:M5)  →  3   ·   =COUNTA(A2:A5)  →  4
FunctionCountsIgnoresCourse result
COUNTnumeric cellsblanks + text~22,000 have salary
COUNTAevery non-empty cellblanks only~32,000 total jobs

Off-by-one: =COUNT(M:M) also counts the column header. For exact numbers subtract 1 — or start the range at row 2.

COUNTIF — One Condition

Count cells that match a single condition. Criteria cell gets locked with F4.

=COUNTIF(K2:K32000, $L$1)  →  25,000  jobs from the United States
=COUNTIF(A2:A32000, $L$2)  →  9,600  jobs titled Data Analyst
A — job_title_shortK — job_countryL — criteria
1job_title_shortjob_countryUnited States
2Data AnalystUnited States✓ counted
3Data ScientistUnited States✓ counted
4Data AnalystIndia✗ skipped
5Data AnalystUnited Kingdom✗ skipped

Structure: range first, then criteria. Lock the criteria cell (F4) so filling the formula down keeps testing the SAME condition.

4

COUNTIFS — Many Conditions, AND logic

Count rows where ALL conditions are true. Never add two COUNTIFs together.

=COUNTIFS(A2:A32000, $L$1, K2:K32000, $L$2)  →  8,000 Data Analyst AND United States
32,000all jobs (COUNTA)
25,000United States (COUNTIF)
9,600Data Analyst (COUNTIF)
8,000Data Analyst + United States (COUNTIFS)

The trap: don't do =COUNTIF(…US) + COUNTIF(…Analyst). That counts ~34,600 — more than all jobs! The same row must pass BOTH conditions, which is exactly what the S in IFS means.

SUM & SUMIF

Add up all values — or only the ones matching a condition.

A — job_title_shortK — job_countryM — salary_year_avg
2Data AnalystUnited States100000
3Data ScientistUnited States150000
4Data AnalystIndia45000
5Data EngineerUnited States130000
=SUM(M2:M5)  →  425,000
=SUMIF(K2:K5, $L$1, M2:M5)  →  380,000 = 100k+150k+130k (US only)
→

SUMIF order

criteria range (what we test: K) → criteria ($L$1) → sum range (M). The sum range comes LAST.

6

SUMIFS — the Sum Range Comes FIRST

The number-one confusion. SUMIFS is backwards from SUMIF on purpose.

=SUMIFS(M2:M5, A2:A5, $L$1, K2:K5, $L$2)  →  100,000 Analyst + US
SUMIFSUMIFS
1st argumentcriteria rangeSUM RANGE
2nd argumentcriteriacriteria range 1
Then…sum range (last)criteria 1, range 2, criteria 2…

The result of the course example is lower than the plain Analyst sum — because only rows that are BOTH Analyst AND US are included. Read the formula left to right: SUM range first, then pairs of range+criteria.

7

AVERAGE, MIN, MAX

The range, spread and extremes of the whole salary column.

=AVERAGE(M2:M32000)  →  ≈ 123,000
=MIN(M2:M32000)  →  ≈ 15,000   ·   =MAX(M2:M32000)  →  ≈ 960,000
FunctionOn salary col MTells you
AVERAGE123,000the mean (pulled up by high earners)
MIN15,000the lowest salary in the data
MAX960,000the highest — a big outlier

Blanks are fine: unlike COUNT, SUM / AVERAGE / MIN / MAX simply skip empty cells — the "find blanks" logic of COUNTA is not relevant here.

AVERAGEIF — Average per Job Title

Criteria range, criteria, average range — then RANK the results.

=AVERAGEIF(A2:A32000, $W$2, M2:M32000) → average salary for the title in W2
Job title (W)Average salaryRank
Data Analyst93,0003
Senior Data Scientist155,0001
Business Analyst90,0004
Data Scientist123,0002
=RANK.EQ(X2, $X$2:$X$11) → rank of a salary against all titles (ref array MUST be F4-locked)

Lesson learned in the course: forgetting the F4 on the rank reference array gives repeated/wrong ranks. Lock the reference, leave the value free.

Why Average ≠ Median

One crazy salary drags the average up. The median stays in the middle.

M — salary_year_avg
180,000
295,000
3115,000 ← MEDIAN (middle)
4130,000
5960,000 ← outlier
=AVERAGE(M1:M5)  →  276,000   ·   =MEDIAN(M1:M5)  →  115,000

Course verdict: the $960k outlier drags the average way up, so Luke prefers the median for salary analysis — "use the median when you can".

Common Errors

The #VALUE! that trips everyone up.

ErrorWhy it happensFix
#VALUE!criteria range spans multiple columnsone column per range
#VALUE!criteria range & sum range not alignedsame size, same rows
Wrong countCOUNTIF added to COUNTIF instead of IFSuse COUNTIFS
Repeated ranksref array not F4-lockedlock $X$2:$X$11
Off-by-onewhole column includes the headersubtract 1 / start at row 2

Most common: selecting two columns as one criteria range. Excel can't test a multi-column range against a single criteria → #VALUE! Always check that every range is a single column.
