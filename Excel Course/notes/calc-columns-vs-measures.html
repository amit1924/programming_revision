Calculated Columns vs Measures

Both are DAX formulas in your data model, but they answer different questions. A calculated column adds a value to every row and stores it. A measure computes an aggregate on the fly and respects your pivot filters.

normal column (green) calculated column (black) measure (fx)
1

The Big Difference

One is stored per row, the other is calculated every time it's asked.

THE CONCEPT
Calculated ColumnMeasure
Stored?YES — one value per row, saved in the tableNO — computed only when the pivot asks
Written with= (Excel-style, no colon):= (DAX colon-equals)
Computed whentable is loaded / refreshedevery time filters change
Knows filters?No (works row by row)Yes (respects filter context)
CostUses memory + file sizeNearly free
Great forper-row values (€ conversion, buckets)aggregates (median, ratio, total)

One-line summary: a column says "what is this row's value?" — a measure says "what is the TOTAL for what I've filtered?"

Spot a calculated column

In the Data View, normal columns are green, calculated columns are black. Measures show an fx icon.

2

Where to write each

Columns: click Add Column in the grid (Design tab → Columns → Add). Measures: click an empty box in the Calculation Area below the table.

3

Calculated Columns — Per Row, Stored

A formula that runs for EVERY row and keeps the result. Written like an Excel formula.

=[salary_year_avg] * 0.9   → € conversion, one value per row
1

Add Column

Design tab → Columns → Add, or just click into the empty column at the end of the grid.

2

Type the formula — NO colon-equals

Write =[salary_year_avg]*0.9. Notice: I didn't use the colon equal sign — because it's not a measure, it's a calculated column.

3

Rename & format

Rename to salary_year_EUR. Excel knows it's still a currency — just set it to € with 0 decimals.

The price: the result is saved for every row of the table. On a big dataset that's real memory and a bigger workbook. Use columns sparingly.

Same number, row context: each row multiplies ITS OWN salary. That's row-by-row logic — you cannot get a "total € across all rows" from this column without aggregating it.

5

Measures — Aggregate, On Demand

Written with := in the Calculation Area. Computed against whatever the pivot has filtered.

Median Salary := MEDIAN([salary_year_avg])
Median Salary EUR := MEDIAN([salary_year_EUR]) → €103,000
1

Click the Calculation Area box

Type a name, then := (the DAX colon-equals tells Power Pivot this is a measure).

2

Aggregate with DAX

MEDIAN has no option in pivot value settings — DAX adds it. Reference a column with brackets: [salary_year_avg].

3

Drag it into a pivot

The measure respects slicers, filters and rows — change the job title and it recomputes. Nothing is stored.

Power: you can build a measure on top of a calculated column — MEDIAN of the € column works even though € was created as a column.

6

Implicit vs Explicit Measures

You've used measures without knowing it — dragging a field into Values is one.

ImplicitExplicit
How it's madedrag a field into Valuesyou write DAX with :=
Iconplain fieldfx (formula icon)
Reusable?No — throwawayYes — use it in other measures
Good forquick sums & countsmedian, ratios, complex KPIs

Why care? Explicit measures get reused — e.g. your Job Count measure used inside other calculations. Implicit ones disappear when you remove the field.

7

When to Use Which

The decision in 4 questions.

QuestionAnswerBuild
Need a value on EVERY row?e.g. € per salary row, a bucket, a flagCalculated Column
Need a TOTAL that changes with filters?median, sum, ratio in a pivotMeasure
Small table, easy per-row math?conversions, derived labelsColumn (cheap here)
Big table, aggregate only?don't bloat the modelMeasure

Course note: for the final project Luke creates no calculated columns — everything is explicit measures. Columns are the occasional tool, measures are the default.

8

The Chain: Column → Measure → Pivot

Columns feed measures, measures feed pivots. Plus a FORMAT column for dates.

salary_year_EUR Median Salary EUR := MEDIAN(…) Pivot Table Values → €103,000
=FORMAT([job_posted_date_time], "yyyy-mm-dd") → a clean date column (calculated column) for joining to the Calendar table
1

Column first

The € column exists per row — but it can't tell you the overall median.

2

Measure wraps it

Median Salary EUR := MEDIAN([salary_year_EUR]) aggregates that column.

3

Pivot consumes it

Drop the measure into Values — it filters, groups and recomputes with every slicer change.

FORMAT columns are legit: creating a "yyyy-mm-dd" date column via a calculated column is how the course builds a clean date key for the relationship to the Calendar table.
