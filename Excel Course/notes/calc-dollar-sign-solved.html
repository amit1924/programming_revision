First, the 3 Rewrite Rules

When you drag a formula, Excel rewrites each reference using these rules.

RuleDrag DOWNDrag RIGHT
1. No $ (A1)row number +1 → A2column letter +1 → B1
2. $A$1 (absolute)never movesnever moves
3. Mixed ($A1 / A$1)only the free part movesonly the free part moves

The whole topic in one sentence: dragging rewrites the parts WITHOUT a $; parts WITH a $ never change. Everything below is just this rule, applied again and again.

SOLVED — Relative: =B2*2 dragged DOWN

Type in C2, drag the fill handle to C4. Watch B2 become B3, B4.

C2: =B2 * 2  →  drag down to C4
B — SalaryC — Formula storedArithmeticResult
295,000=B2*295,000 × 2190,000
3120,000=B3*2120,000 × 2240,000

B2 → B3 → B4 (row moved because no $)  ·  results: 190,000 / 240,000 / 210,000

That's exactly what we want here: each row doubles ITS OWN salary. The reference follows the row on purpose.

SOLVED — Absolute: =B2*$C$1 dragged DOWN

B2 moves, but $C$1 refuses to move. Every row reads the SAME tax cell.

Try WITHOUT $ → broken numbers: C2 would read C1 (0.10) ✓, but C3 would read C2 (blank) → 0, and C4 → C3 (blank) → 0. One correct row, two zeros. That's the silent bug.

The column letter is frozen, the row is free. Drag down → row moves.

SOLVED — Mixed A$1: row locked

The row number is frozen, the column is free. Drag right → column moves.

Start: A$1  →  drag RIGHT
CellExcel storesColumn?Row 1?
startA$1Alocked
+1 colB$1B (col moved)locked

→

And dragging DOWN?

Row is locked, so nothing changes: A$1 stays A$1. Useful when every copied row must keep reading row 1 (headers).

A$1 → B$1 → C$1 (row frozen)

Paired memory hook: $A1 = "stay in column A". A$1 = "stay on row 1". The $ acts like glue on whichever side it touches.

8

SOLVED — Running Total: =SUM($B$2:B2)

The START is locked, the END drifts. The range grows as you fill down.

C2: =SUM($B$2:B2)  →  drag down to C4
B — SalesC — Formula storedSums rangeArithmeticResult
21,000=SUM($B$2:B2)B2:B21,0001,000
31,500=SUM($B$2:B3)B2:B31,000+1,5002,500
42,000=SUM($B$2:B4)B2:B41,000+1,500+2,0004,500
1,000 = 1,000  ·  1,000+1,500 = 2,500  ·  1,000+1,500+2,000 = 4,500

If you locked the END too (=SUM($B$2:$B$2)) every row would show just 1,000 — no growth. The END must stay relative so the range stretches.

The $ is what makes the dashboard interactive: without it, every copied formula drifts to an empty cell and the KPI silently becomes 0. With it, all rows answer to the one dropdown.

10

SOLVED — F4, Key by Key

Type =B2, then press F4 again and again — here's the full loop.

Press #Result in formulaType
0 (typed)=B2relative
1st F4=$B$2absolute (both locked)
2nd F4=B$2mixed — row locked
3rd F4=$B2mixed — column locked
4th F4=B2back to relative
B2 → $B$2 → B$2 → $B2 → B2 (cycle repeats)

Practical use: type the plain reference, F4 once for a fully locked cell, twice for a row-locked header ref, three times for a column-locked one. No typing $ by hand.
