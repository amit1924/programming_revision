Connecting Two Tables

Real data lives in separate tables. To combine them you give them a shared key column, then either merge them (Power Query joins) or relate them (Power Pivot data model). This is how you analyze across tables without VLOOKUPing everything.

The shared key: job_id appears in BOTH tables. Table A has it once per job (unique); Table B has it many times (one row per skill). That key is the bridge.

Primary Key vs Foreign Key

Two roles for the same shared column.

Primary KeyForeign Key
WhereTable A (jobs)Table B (skills)
ValuesUNIQUE — each id appears onceREPEATED — the same id appears many times
JobIdentifies each rowPoints back to Table A's row
Example1000210002 → two skill rows

Memory: the primary key is the "home address" (unique), the foreign key is a "friend's pointer" to that address (repeats).

3

Way 1 — Lookup Formulas (XLOOKUP)

The manual bridge: fetch a value from another table, row by row.

ONE SHEET
1

Add a column to the skills table

For each skill row, look up its job's title in Table A.

job_idjob_skilljob_title_short (added)
10001SQLData Analyst
10001PythonData Analyst
10003SQLData Scientist
10005Power BI#N/A
2

The formula in the new column

Search job_id in Table A, return job_title_short. Missing ids give #N/A → wrap in IFERROR.

=IFERROR(XLOOKUP(A2, jobs[job_id], jobs[job_title_short]), "No job")
3

The catch

One formula per row. Great for a small table; painful for 170,000 rows.

When lookups are right: adding ONE column from a reference table. When they're wrong: building a whole combined dataset — that's Power Query's job.

4

Way 2 — Power Query Merge (Joins)

Merge two queries on job_id and CHOOSE what to keep. Power Query combines the tables into one.

POWER QUERY
1

Merge Queries as New

Power Query Editor → Home → Merge Queries → as New. Pick the two queries and the matching column (job_id).

2

4

Choosing the join

In the course's dataset: a left outer join gave 170,000 rows; an inner join gave 167,000 (dropping the 3,000 jobs that had no skills). Both were valid — it depends on whether you want to keep the empty jobs.

Rule of thumb: keep everything from the "main" table → Left Outer. Only complete matches → Inner.

5

Way 3 — Data Model Relationship (Power Pivot)

Don't merge — just DRAW A LINE between the tables. They stay separate; Excel knows they're connected.

POWER PIVOT
1

Add both tables to the Data Model

Power Pivot tab → Add to Data Model (or tick it when importing). Both tables now live in the model.

2

Open Diagram View and drag the key

Power Pivot → Manage → Diagram View. Drag job_id from one table onto job_id in the other. A line appears.

data_jobs_salary↔data_jobs_skills
job_id (1)⟷ linked ⟷job_id (many)
job_title_shortjob_skill
salary_year_avg

The line shows a 1 on one side and a ★ (many) on the other → a one-to-many relationship.

3

Use it in a Pivot Table

Insert Pivot Table → Use this workbook's Data Model. Now drag job_title_short from one table into Rows, and job_skill from the OTHER table into Values — they count together automatically.

job_title_shortCount of job_skill

Counts skills per job across two separate tables — no VLOOKUP, no merge, just the relationship.

4

Filtering flows ONE way — the arrow

The arrow on the line shows which table can filter the other. Filtering flows from the "1" side to the "many" side.

Gotcha: if you drag job_id from the SKILLS table into a measure, the arrow may not flow that way — you'll count 32,672 (all jobs) instead of per-skill counts. In Excel you can't flip the direction (Power BI can).

6

Relationship Types — 1:1, 1:many, many:many

The "1" and "★" on the diagram tell you which type you have.

TypeMeansExampleOK?
One to OneEach key appears once in BOTH tablesjobs ↔ job_details✅ Fine
One to ManyKey once in A, many times in Bjobs ↔ skills (one job, many skills)✅ Most common
Many to ManyKey repeats in BOTH tablesskills ↔ companies⚠️ Avoid — slow, messy

Expect to see: mostly one-to-many. Many-to-many slows the model down and causes double-counting — restructure instead.

7

Which Way When?

Three tools, three different goals.

GoalUseTables stay separate?
Add ONE column from another tableXLOOKUPYes (in-place)
Build ONE combined table for analysisPower Query MergeNo — merged into one
Query across tables in Pivot Tables, no mergeData Model RelationshipYes — just linked

Short version: formulas = small reference lookups · merge = make one big table · relationship = keep tables and draw a line.

Common Pitfalls

What goes wrong when you connect tables.

DANGER ZONE
SymptomCauseFix
Duplicated values in the pivotRelationship missing / wrong keyRecreate the link on the right key
Same number in every rowFilter direction: measure on the wrong tableUse a DAX measure / correct direction
Rows missing after mergeWrong join kind (e.g. Inner dropped empty jobs)Switch to Left Outer to keep them
Double countingMany-to-many relationshipRestructure with a bridge table
Keys that look the same but don't matchOne is text "10001", other is number 10001Fix the data types

Test: if Excel pops up "relationships between tables may be needed", let it autodetect — but always double-check the arrow direction and the key in Diagram View.
