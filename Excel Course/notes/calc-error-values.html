All Excel Error Values

An error value is Excel's way of saying "I can't produce an answer". They always start with a #. Learn to read each one like a message — the error itself tells you what to check.

error value fixed result working value lookup / reference
1

What Is an Error Value?

Not a crash — a message. Excel is telling you exactly what went wrong.

BIG PICTURE
ErrorWhat Excel is really sayingERROR.TYPE code
#DIV/0!I divided by zero (or an empty cell)2
#N/AI looked, and it's not there7
#VALUE!I got text where I expected a number3
#REF!The cells I pointed at were deleted4
#NAME?I don't recognise that name or function5
#NUM!That number is impossible6
#NULL!You used a space instead of a comma1

Two things to know up front: (1) an error in one cell poisons every formula that points at it — fix the source, not the symptoms. (2) #### is NOT an error value — that's just a column too narrow to show the number.

Read it as a hint: each error has a personality. #DIV/0! is about division, #N/A about lookups, #REF! about deleted cells. Match the error → the problem area → the fix.

#DIV/0! — The Divide-by-Zero Error

The most common error in real sheets. Dividing by a blank counts as dividing by zero.

1

Price per unit — row 3 has no quantity

C÷B. An empty B3 is treated as 0, and ÷0 breaks.

ABCD
1ItemQtyTotalPrice/Unit
2Pen1050050
3Notebook300#DIV/0!
4Eraser525050
=C3/B3 → #DIV/0!
2

Fix it — wrap in IFERROR or guard the divisor

Show a clean 0, or blank, or a message — never the red error.

=IFERROR(C3/B3, 0) → 0
=IF(B3=0, "Missing qty", C3/B3) → "Missing qty"

Also causes #DIV/0!: a formula that returns 0 in the denominator, or a divisor cell that looks empty but contains 0, or another formula error flowing into the divisor.

4

#N/A — The "Not Found" Error

The friendliest error: it means a lookup couldn't find the value. Usually expected, not a bug.

1

A VLOOKUP for an employee that doesn't exist

999 is not in the table → the lookup honestly reports "not found".

ABFG
1IDNameLookupResult
2101Amit999#N/A
3102Rahul101Amit
4103Priya
=VLOOKUP(F2, A2:B4, 2, FALSE) → #N/A
2

Fix it — IFNA (only hides the "not found")

Use IFNA for lookups, not IFERROR: real mistakes stay visible.

=IFNA(VLOOKUP(F2, A2:B4, 2, FALSE), "Not Found") → "Not Found"

#N/A is the expected error for lookups — it's how XLOOKUP/VLOOKUP say "nothing matched". That's exactly why IFNA exists. You can also force it deliberately with =NA(), e.g. to stop a chart plotting missing data.

5

#VALUE! — The Wrong-Data-Type Error

A formula got text where it expected a number (or a number where it expected text).

Broken formulaWhyResult
="abc" + 5Can't add text and a number#VALUE!
=A2*2 where A2 = "10 "Number hidden as text / with a space#VALUE!
=SUM(A1:B2 C3)Bad range syntax#VALUE!

Fix: convert text-numbers with =VALUE(A2), =A2*1, or Text to Columns. Check for invisible spaces with =TRIM(A2). If a whole SUM gives #VALUE!, one bad cell hides in the range — use =IFERROR(A2, 0) while you hunt it, then fix the cell.

=A2*1 converts "95000" (text) → 95000 (number)
6

#REF! — The Broken-Reference Error

The cells or sheet your formula pointed at no longer exist.

1

Delete a column the formula depends on

D3 = A3+C3. Delete column B → the formula has nowhere to point → #REF!.

ABCD
2100200300#REF!
=A2+B2+C2 → after B deleted → =A2+#REF!+C2

Fix: Undo (Ctrl+Z) immediately, or edit the formula back to a valid reference. A #REF! inside a formula also appears if you copy-paste a formula over its own source cells.

7

#NAME? — The "I Don't Know That Name" Error

Excel sees text it can't recognise — usually a typo, a missing quote, or a forgotten range name.

Broken formulaReal problemFix
=VLOKUP(A2,…)Misspelled function=VLOOKUP(A2,…)
=IF(A2>5, Yes, No)Text not in quotes=IF(A2>5,"Yes","No")
=SUM(A1 A5)Missing colon in a range=SUM(A1:A5)
=Totals*2Range name "Totals" doesn't existName it, or reference the cells

The classic trap: after you delete a defined range name that formulas still use, everything referencing it flips to #NAME?. Recreate the name or update the formulas.

=IF(B2>=85000, "Goal met", "Not met") ← quotes around every text output
8

#NUM! — The Impossible-Number Error

A calculation produced a number Excel can't handle, or a function argument is invalid.

Broken formulaWhyResult
=SQRT(-1)Square root of a negative number#NUM!
=DATE(2024,13,1)Month 13 is invalid#NUM!
=A1^100000Result too large for Excel#NUM!
=RATE(…,0,…)Iteration can't converge#NUM!

Fix: make the inputs valid. For negative-square-root cases, guard with =IF(A2<0, 0, SQRT(A2)). For financial functions that won't converge, check your guess and the sign of your cash flows.

9

#NULL! — The Space-Operator Error

A space between ranges means "intersection" — and most of the time the ranges don't overlap.

=SUM(A1:A5 B2:B6) ← space asks for the overlap of two ranges that never meet → #NULL!
BrokenFixed
=SUM(A1:A5 B2:B6)=SUM(A1:A5, B2:B6) (comma = union)
=SUM(A1 A5)=SUM(A1:A5) (colon = range)

Rule: : makes a range, , combines ranges, space asks for the intersection. 99% of the time you mean colon or comma, not space.

Modern 365 Errors — #SPILL! · #CALC! · #BLOCKED! · #FIELD! · #CONNECT! · #BUSY!

Dynamic arrays and cloud data types brought a whole new set of messages.

1

#SPILL! — your array's answers are being blocked

=A2:A4*2 wants to fill 3 cells, but something already lives there.

AB
1SalaryDoubled
2100#SPILL!
3200Blocked ↓
4300occupied
=A2:A4*2 → clear the blocking cell, or force single value with @A2:A4
ErrorTriggerFix
#SPILL!Array result blocked by dataClear the blocker or use @
#CALC!=FILTER(A:A, B:B="x") with zero matchesWrap: =IFERROR(FILTER(…),"None")
#BLOCKED!Data type / import blockedCheck permissions, refresh source
#FIELD!Field missing from a data typeRe-insert the field or refresh
#CONNECT!Connection can't be madeFix data source, refresh
#BUSY!Server still computingWait a moment and refresh

#GETTING_DATA sits in this group too — it means Excel is still fetching (usually Power Query). It's temporary: it clears itself when the refresh finishes.

The fastest mapping from message to action.

Golden rule: an error is information, not noise. Read the message, fix the cause, and only then — if the case is genuinely expected — wrap it in a safety net so it reads cleanly.
