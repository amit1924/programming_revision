Excel — Star Schema & Snowflake Schema
Step by step
Two classic ways to organize fact + dimension tables in a data model

Star Schema · Snowflake Schema

Once you have a fact table and several dimension tables, you arrange them in a pattern. The star keeps everything flat and simple; the snowflake normalizes dimensions into more detail. Both live in your data model (Power Pivot) and feed pivot tables.

Why it's called a star

Draw it: fact in the center, lines out to every dimension. It looks like a star.

Fast: every query is one hop away. This is the classic data-warehouse design and what Excel/Power Pivot models are built like.

3

The Snowflake Schema

Dimensions are split into smaller, normalized tables — the star's points grow "branches".

NORMALIZED
1

The layout — dimensions chain out

dim_location no longer stores country directly. It now links to a separate dim_country table.

FACT
fact_jobs
job_id · location_id · salary
⟷
DIM_LOCATION
location_id · city · country_id
⟷
DIM_COUNTRY
country_id · country · region

The location dimension has been split: location table + a separate country table.

2

Normalized — no repeated values

"United States" appears ONCE in dim_country, not hundreds of times in every location row.

country_idcountryregion
1United StatesNorth America
2IndiaAsia

Trade-off: saving space, but a query now needs 2–3 hops to reach the answer. Slower joins, more complex model.

3

Why it's called a snowflake

The branches make the star look like a snowflake crystal.

4

Star vs Snowflake — Side by Side

Same business question, two different models.

FeatureStar SchemaSnowflake Schema
DimensionsDenormalized (all in one)Normalized (split up)
Hops from fact1 (fast)2+ (slower)
StorageMore (repeats values)Less (no repetition)
Query speedFastSlower joins
ComplexitySimple, easy to readMore tables, more complex
Best forExcel, Power Pivot, BI reportsBig data warehouses, ETL

Excel verdict: Excel's data model is built for STAR schemas. Keep dimensions denormalized for speed and simplicity — snowflakes rarely pay off inside Power Pivot.

Building It in Power Pivot (Diagram View)

Load the tables, add them to the data model, drag the keys to draw the star.

1

Add fact + dimensions to the Data Model

Power Pivot tab → Add to Data Model for each table.

2

Draw relationships in Diagram View

Power Pivot → Manage → Diagram View. Drag each dimension's key onto the fact table's foreign key.

dim_product
product_id (1)
dim_store
store_id (1)
dim_date
date_id (1)
⟷ 1 : many ⟷
fact_sales
product_id · store_id · date_id (★)
all dimensions point IN

Every dimension is the "1", the fact is the "many".

Arrows all point toward the fact table.

This IS the star schema, ready for pivot tables.

If you see many-to-many lines (both sides ★), that's a snowflake/messy link — Excel will struggle. Restructure to 1:many so each dimension points at the fact.

7

Which One Should You Use?

A quick decision guide.

SituationChooseWhy
Building reports in Excel / Power BIStarFast, simple, made for pivot tables
Small-medium data in Power PivotStarNo storage benefit from snowflake at this size
Massive warehouse, storage is a concernSnowflakeNormalization removes repeated values
Heavily nested detail dataSnowflakeGranular split dimensions make sense

Default answer: STAR. Start there, and only go snowflake when storage genuinely matters.
