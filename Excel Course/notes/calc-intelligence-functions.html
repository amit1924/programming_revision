Intelligence Functions

Excel's Logical and Information functions let your formulas make decisions (IF, AND, OR, IFS) and interrogate the data itself (ISBLANK, ISNUMBER, ISERROR…). Together they turn a dumb calculator into a spreadsheet that thinks.

What Are the Intelligence Functions?

Two families, one goal — make Excel make decisions and understand its own data.

BIG PICTURE

The idea (from Excel Formulas & Functions): these functions "add to your worksheet models the two cornerstones of good business analysis — intelligence and knowledge." Logical functions add the thinking, information functions add the knowing.

LogicalMakes decisions based on conditionsIF · IFS · AND · OR · NOT · IFERROR · IFNATRUE / FALSE or your chosen value
InformationAsks "what kind of value is in this cell?"ISBLANK · ISNUMBER · ISTEXT · ISERROR · CELL · ERROR.TYPE · TYPETRUE / FALSE or a code / answer

Mental model: Information functions are the detective (what is this value?), logical functions are the judge (what do we do about it?). They are usually used together: =IF(ISNUMBER(A2), A2*2, "Check data").

Real use — "role desired" = Data Analyst or Business Analyst

Same question the course uses: put AND / OR / NOT inside an IF's logical test.

AB=AND(A2="Data Analyst",B2>=85000)=OR(A2="Data Analyst",A2="Business Analyst")=NOT(B2>=85000)

Nested IFs vs AND/OR: a nested IF (=IF(a,1,IF(b,2,3))) does the same job but is hard to read. AND / OR make the intent obvious.

IFS — Many Buckets, First Match Wins

More than two outcomes? Pair each test with its answer. Excel 2016+.

=IFS(test1, value1, test2, value2, …)
1

Bucket salaries — but one row has no data at all

The course's exact problem: a plain IF would call an empty cell "Below 85k". Test for the blank FIRST.

The IFS formula

Tests run top-to-bottom; the FIRST TRUE one wins. The final TRUE test is the catch-all "else".

=IFS(B2="", "No data", B2>=85000, "Above 85k", TRUE, "Below 85k")
OrderTestIf TRUE
1B2="""No data"
2B2>=85000"Above 85k"
3TRUE"Below 85k" (everything else)

Order matters. IFS stops at the first TRUE test. Always test the special cases (blanks, errors) before the normal ranges.

The IS Family — Yes/No Questions About Any Value

Every IS function takes one value and answers TRUE or FALSE.

Why use them? Check a value before calculating on it — so a blank cell or an error never silently poisons your totals.

The IS Traps — Gotchas That Bite

Four little surprises that make IS functions return the "wrong" answer.

FormulaResultWhy?
=ISNUMBER("19")FALSEText in quotes is NOT converted — "19" is text, not a number
=ISBLANK("")FALSEAn empty text string "" is not a blank cell
=ISNONTEXT(A3)TRUEA blank cell counts as "not text" — so ISNONTEXT(blank) is TRUE
=ISTEXT(95000)FALSEA number typed as a number is not text, even if it looks like one

The classic trap: data imported from CSV often arrives as text numbers ("19", "95000"). ISNUMBER returns FALSE and your checks fail until you convert the column. Check with =ISNUMBER(B2) — if FALSE, convert with =B2*1 or Text-to-Columns.

Spill note (Microsoft 365): point an IS function at a whole range like =ISNUMBER(B2:B9) and it spills one TRUE/FALSE per cell automatically. Older Excel needs it dragged down.

1

The lookup pattern

ISNA sees the "not found" #N/A and swaps in a message — while real formula errors still show up for you to fix.

=IF(ISNA(XLOOKUP(E2, A2:A9, B2:B9)), "Not in catalog", XLOOKUP(E2, A2:A9, B2:B9))

Rule of thumb: lookups → ISNA (or IFNA). Anything else → ISERROR. Almost never need ISERR.

Remember: Information functions detect (ISBLANK, ISNUMBER, ISERROR…), logical functions decide (IF, IFS, AND, OR, NOT). Chain them — the detective feeds the judge.
