Working Locally

Init, add, commit, staging area, diff, reset, and more

1. Creating a New Repository

Use git init to create a brand new Git repository in a subdirectory. Git creates the directory for you along with a hidden .git/ subfolder containing all version control metadata.

$ git init myrepository
Initialized empty Git repository in /home/user/myrepository/.git/
$ ls -la myrepository/
total 12
drwxr-xr-x 3 user user 4096 Jan 15 10:00 .
drwxr-xr-x 4 user user 4096 Jan 15 10:00 ..
drwxr-xr-x 7 user user 4096 Jan 15 10:00 .git

The .git/ directory contents:

$ ls -la myrepository/.git/
total 40
drwxr-xr-x 7 user user 4096 Jan 15 10:00 .
drwxr-xr-x 3 user user 4096 Jan 15 10:00 ..
-rw-r--r-- 1 user user 23 Jan 15 10:00 HEAD
drwxr-xr-x 2 user user 4096 Jan 15 10:00 branches
-rw-r--r-- 1 user user 235 Jan 15 10:00 config
-rw-r--r-- 1 user user 73 Jan 15 10:00 description
drwxr-xr-x 2 user user 4096 Jan 15 10:00 hooks
drwxr-xr-x 2 user user 4096 Jan 15 10:00 info
drwxr-xr-x 4 user user 4096 Jan 15 10:00 objects
drwxr-xr-x 4 user user 4096 Jan 15 10:00 refs
Warning: The .git/ directory holds your entire repository history. Deleting it destroys all version control data!

2. Committing Your First Files

Two-step process: stage with git add, then commit with git commit.

$ cd helloworld
$ echo 'Hello World!' > hello
$ git add hello
$ git commit -m "added file 'hello'"
[master (root-commit) f7c3d8a] added file 'hello'
1 file changed, 1 insertion(+)
create mode 100644 hello

master is the default branch name. The commit hash f7c3d8a uniquely identifies this snapshot.

3. The Staging Area (Index)

Traditional VCS has two areas: the repository (committed history) and the working tree (your files). Git adds an intermediate layer: the staging area (also called the index).

Working Tree
Your files on disk
git add →
Index / Staging
Prepared snapshot
git commit →
Repository (HEAD)
Committed history
git add copies files into the index git commit commits the content of the index

4. Updating a File

Editing a file without re-staging it means Git sees the changes but won't include them in the next commit.

$ echo 'Goodbye World!' > hello
$ git commit -m "updated hello"
On branch master
Changes not staged for commit:
(use "git add <file>..." to update what will be committed)
(use "git restore <file>..." to discard changes in working directory)
modified: hello
no changes added to commit (use "git add" and/or "git commit -a")

You must git add again before committing:

$ git add hello && git commit -m "updated hello"
[master 2b4f1e3] updated hello
1 file changed, 1 insertion(+), 1 deletion(-)

5. Bypassing the Index

You can commit files directly from the working tree without explicitly using git add. However, this only works for already tracked (modified) files — new files are ignored.

$ git commit hello -m "direct commit of hello"
[master a1b2c3d] direct commit of hello
1 file changed, 1 insertion(+), 1 deletion(-)

To include all changes (including new files), use git add . first:

$ git add . && git commit -m "commit everything"
[master d4e5f6g] commit everything
3 files changed, 12 insertions(+)
create mode 100644 newfile.txt
create mode 100644 another.txt

6. Deleting Files

git rm removes a file from both the index and the working copy. Then commit the removal.

$ git rm hello
rm 'hello'
$ git status
On branch master
Changes to be committed:
(use "git restore --staged <file>..." to unstage)
deleted: hello
$ git commit -m "removed hello"
[master 9a8b7c6] removed hello
1 file changed, 0 insertions(+), 1 deletion(-)
delete mode 100644 hello

If you delete a file manually (rm file), Git shows it as "deleted" in git status, and you can stage the removal with git rm file or git add file.

7. Showing Differences

git diff compares different states of your repository. By default it shows differences between the index and the working copy.

git diff
working copy vs index
git diff --staged
index vs HEAD
git diff HEAD
working copy vs HEAD

Scenario: start with a clean repo containing hello, then edit it and stage a modified version:

$ echo 'Line 2' >> hello
$ git add hello
$ echo 'Line 3' >> hello

git diff — shows unstaged changes (working copy vs index):

$ git diff
diff --git a/hello b/hello
index 3b18e51..c3f8a2d 100644
--- a/hello
+++ b/hello
@@ -1 +1,2 @@
Hello World!
+Line 3

git diff --staged — shows staged changes (index vs HEAD):

$ git diff --staged
diff --git a/hello b/hello
index f7c3d8a..3b18e51 100644
--- a/hello
+++ b/hello
@@ -1 +1,2 @@
Hello World!
+Line 2

git diff HEAD — shows all uncommitted changes (working copy vs HEAD):

$ git diff HEAD
diff --git a/hello b/hello
index f7c3d8a..c3f8a2d 100644
--- a/hello
+++ b/hello
@@ -1 +1,3 @@
Hello World!
+Line 2
+Line 3

8. Resetting Changes

git reset lets you undo staged changes. Use it carefully — --hard is destructive!

git reset
Unstages changes — working copy is untouched
git reset --hard
⚠ Drops ALL changes in index AND working copy

Reset the index (unstages everything):

$ git add hello
$ git status
Changes to be committed:
modified: hello
$ git reset
Unstaged changes after reset:
M hello
$ git status
Changes not staged for commit:
modified: hello

Reset with --hard — all changes are lost:

$ git reset --hard
HEAD is now at f7c3d8a added file 'hello'
$ git status
On branch master
nothing to commit, working tree clean

9. Resetting Changes in Working Copy

To discard unstaged changes in a specific file, restore it from the index. This reverts the working copy to the last staged version.

$ echo 'Bad edit' >> hello
$ git checkout -- hello
$ cat hello
Hello World!

Since Git v2.23 (2019), you can also use the experimental git restore command:

$ git restore hello
# same effect as 'git checkout -- hello'

10. Other Local Commands

git status

Shows the current state of the index and working copy — which files are staged, modified, or untracked.

$ git status
On branch master
Changes to be committed:
(use "git restore --staged <file>..." to unstage)
new file: index.html
Changes not staged for commit:
modified: style.css
Untracked files:
script.js

git show

Shows the full details of a commit — metadata and the diff.

$ git show f7c3d8a
commit f7c3d8a4e1c5a2b3f4d5e6f7a8b9c0d1e2f3a4b5
Author: User <user@example.com>
Date: Mon Jan 15 10:05:00 2026 +0100
added file 'hello'
diff --git a/hello b/hello
new file mode 100644
index 0000000..3b18e51
--- /dev/null
+++ b/hello
@@ -0,0 +1 @@
+Hello World!

git log

Shows the commit history in reverse chronological order.

$ git log
commit 2b4f1e3a9b8c7d6e5f4a3b2c1d0e9f8a7b6c5d4e
Author: User <user@example.com>
Date: Mon Jan 15 10:10:00 2026 +0100
updated hello
commit f7c3d8a4e1c5a2b3f4d5e6f7a8b9c0d1e2f3a4b5
Author: User <user@example.com>
Date: Mon Jan 15 10:05:00 2026 +0100
added file 'hello'

git mv

Move or rename a file in one step. Equivalent to cp + git rm + git add.

$ git mv hello greetings.txt
$ git status
On branch master
Changes to be committed:
renamed: hello -> greetings.txt
$ git commit -m "renamed hello to greetings.txt"
[master e5f6a7b] renamed hello to greetings.txt
1 file changed, 0 insertions(+), 0 deletions(-)
rename hello => greetings.txt (100%)

git tag

Create lightweight or annotated tags to mark specific commits (e.g., releases).

$ git tag v1.0.0
# create a lightweight tag at HEAD
$ git tag -a v1.0.1 -m "release v1.0.1"
# create an annotated tag with a message
$ git tag
v1.0.0
v1.0.1
$ git tag -d v1.0.0
Deleted tag 'v1.0.0'

11. Exercises

Complete these exercises to practice working locally with Git.

1

Create a new repository

Create a new directory and initialize a Git repository in it.

2

Create, add, and commit

Create a file in the repository, stage it, and commit it.

3

Launch gitk

Launch gitk (or git log --graph --oneline if gitk is unavailable) to view the commit history. Keep it open.

4

Modify and commit again

Modify the file, stage the changes, and create a new commit.

5

Rename a file with git mv

Use git mv to rename a file, then commit the rename.

6

Delete a file and commit

Use git rm to delete a file, then commit the removal.

7

Create files, commit, modify, and diff

Create two files, commit them, then modify one. Use git diff to show the changes.

8

Stage a file and compare states

Stage one file. Use git diff and git diff --staged to show differences between the index, working copy, and HEAD.

9

Reset the index

Run git reset to unstage all changes. Verify with git status.

10

Run git reset --hard

Run git reset --hard to discard all staged and unstaged changes. Warning: this is destructive — any uncommitted changes will be lost!
