How Git Handles History (DAG)

Git models history as a Directed Acyclic Graph (DAG). Each commit stores references to its parent commit(s):

  • 0 0 parents — initial commit (root of the graph)
  • 1 1 parent — ordinary commit (linear history)
  • 2+ 2+ parents — merge commit (joins histories)

Each commit + its parent chain forms the DAG — there is never a cycle, hence "acyclic".

Visual DAG
A
B
C
main
D
E
feature
F
merge commit
Commit F has two parents (C and E).
The DAG guarantees that from any commit you can trace back to the root.

Branch = Pointer

Git has no formal "branch history". A branch is simply a movable pointer to a commit.

  • Internally, branches and tags are handled identically — both are refs to commits.
  • Every commit is identified by its SHA-1 hash (160 bits, displayed as 40 hex chars).
  • The hash is computed from: committed files + metadata (author, date, message) + parent hashes.
  • A commit hash securely identifies both content AND full history — tamper-proof.
Branch pointer moving forward
a1
a2
a3
main
main points to commit a3. If you create a new commit, the pointer moves to that new commit.

Creating a New Branch

Syntax:

Terminal
git checkout -b <new_branch> [<starting_point>]

Starting point can be: a commit id, a tag, another branch, or omitted (defaults to current HEAD).

Example
$ git status
# On branch master
$ git checkout -b develop
Switched to a new branch 'develop'

$ git branch
* develop
master
The new branch starts at the same commit you are currently on. Both branches then diverge as you make commits.

Switching Between Branches

Syntax:

Terminal
git checkout [-m] <branch_name>
  • Fails when the working copy is not clean (uncommitted changes would be lost).
  • The -m flag merges local changes into the destination branch.
  • Since v2.23: git switch is available as an experimental alternative.
Error & Recovery
$ git checkout develop
error: Your local changes to the following files would be overwritten by checkout:
index.html
Please commit your changes or stash them before you switch branches.
$ git stash
Saved working directory and index state WIP on main: a3c2f1d ...
$ git checkout develop
Switched to branch 'develop'
$ git stash pop # restore changes later
Use git stash to temporarily save uncommitted work, then pop it after switching.

Merging a Branch

Syntax:

Terminal
git merge <other_branch>
  • Merges changes from other_branch into the current branch.
  • The result is immediately committed (unless there is a conflict).
  • The new commit has two parents — merge history is recorded in the DAG.
  • Only applies changes since the last common ancestor (merge base).
Example
$ git branch
develop
* master
$ git merge develop
Merge made by the 'recursive' strategy.
$ git log --oneline -3
f7d3e2a (HEAD -> master) Merge branch 'develop'
b8a2c1d Update footer in develop
a3c2f1d Initial commit
Before merge: master and develop have diverged from a common ancestor.
After merge: a new merge commit connects both branch histories.

How Git Merges Files

  • Text files: merged per-line.
  • Lines changed in only one branch → auto-merged.
  • Lines changed in both branches → conflict reported.
  • Conflict markers inserted: <<<<<<<, =======, >>>>>>>
  • Binary files: always conflict (no line-based merge possible).
Conflict Block Example
<<<<<<< HEAD (current change)
console.log("Hello from main");
=======
console.log("Hello from develop");
>>>>>>> develop
// Lines above === are your current branch's version.
// Lines below === and above >>>>> are the incoming branch's version.

Merge Conflicts

When a merge results in conflicts:

  • Unmerged files are left in the working tree, marked as "unmerged".
  • Conflict-free files and metadata are automatically added to the index (staged).
  • Git refuses to commit until all conflicts are resolved.
Conflict Scenario Walkthrough
$ git merge feature
Auto-merging index.html
CONFLICT (content): Merge conflict in index.html
Automatic merge failed; fix conflicts and then commit the result.

$ git status
On branch master
You have unmerged paths.
(fix conflicts and run "git commit")
Unmerged paths:
both modified: index.html

$ git diff --name-only --diff-filter=U
index.html

Resolving Conflicts

Two approaches:

Manual
  1. Edit file to resolve conflict
  2. git add <file>
  3. Or git rm <file> to delete
Tool
  1. git mergetool [file]
  2. Supported: xxdiff, kdiff3, emerge, vimdiff, etc.
  3. Once done: git commit
Resolution Process
# 1. Edit index.html to remove conflict markers and keep desired code
$ nano index.html

# 2. Mark as resolved
$ git add index.html

# 3. Verify status
$ git status
On branch master
All conflicts fixed but you are still merging.
(use "git commit" to conclude merge)

# 4. Commit the merge
$ git commit
[master f7d3e2a] Merge branch 'develop'

Deleting Branches

Syntax:

Terminal
git branch -d <branch_name> # safe delete
git branch -D <branch_name> # force delete
  • -d (safe) refuses if the branch is not fully merged or is currently checked out.
  • -D (force) deletes unconditionally — use with care.
Example & Error
$ git branch -d old-feature
error: The branch 'old-feature' is not fully merged.
If you are sure you want to delete it, run 'git branch -D old-feature'.

$ git branch -D old-feature
Deleted branch old-feature (was a3c2f1d).

$ git branch
* master
develop
You cannot delete the branch you are currently on (HEAD). Switch to another branch first.

Exercises

Practice these exercises to master branching and merging:

  1. Visualize the DAG: Run gitk --all or git log --graph --oneline --all to display all branches and their commit graph.
  2. Create & diverge: Create a "develop" branch, switch to it, and make 2–3 commits. Then switch back to master and make 1–2 different commits.
  3. Fast-forward merge: Switch to master and merge develop before making any commits on master. Observe the fast-forward output.
  4. Recursive merge: Make commits on both branches (so they diverge), then merge develop into master. Observe the "recursive" strategy message.
  5. Create & resolve a conflict: Edit the same line of the same file on both branches. Merge → observe conflict markers. Fix manually, git add, git commit.
  6. Merge master into develop: After resolving, switch to develop and merge master into it to keep both branches in sync.
Quick visual log command
$ git log --graph --oneline --all --decorate
* f7d3e2a (HEAD -> master) Merge branch 'develop'
|\
| * b8a2c1d (develop) Update footer
* | c9b4a3e Fix header styling
|/
* a3c2f1d Initial commit
