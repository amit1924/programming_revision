Some Advice (Part 1)

Commit Often

Keep independent changes in separate commits. Commit as frequently as makes sense — small, logical commits are easier to review and revert.

Run git diff Before Commit

Always review staged changes with git diff --cached before committing. Catch mistakes before they become history.

Describe the Rationale

The "why" matters more than the "what". Explain why a change was made — the diff already shows what changed.

Don't Forget git push

Commits are local until pushed. Make sure to git push regularly so your work is backed up and visible to collaborators.

Use .gitignore

Ignore generated files (*.o, *.a, *.class, node_modules/, .env). Keeps your repo clean and prevents accidental commits of binaries.

Meaningful Commit Messages

Separate subject from body with a blank line. Keep the subject under 50 chars, wrap body at 72 chars.

Good vs Bad Commit Message

BAD
$ git commit -m "fixed stuff"
GOOD
$ git commit -m "Fix null pointer in user login

The session object was not being checked for null
before accessing the user_id field, causing a crash
when an unauthenticated request hit the dashboard."

Some Advice (Part 2)

Pull Often

Don't stay desynchronized from the remote. Run git pull frequently to avoid accumulating merge conflicts.

Merge Mainstream Often

Feature branches should regularly merge from main (or master) to stay up-to-date and reduce conflict complexity.

One Branch per Patch

When handling external contributions, create one branch per complex patch. This keeps reviews isolated and history clean.

Keep gitk Open

When doing complex operations (rebasing, cherry-picking), keep a gitk --all or git log --graph window open for visual feedback.

Regular Pull Schedule

# First thing in the morning
$ git checkout main
$ git pull origin main
$ git checkout feature/my-feature
$ git merge main
Already up to date.

# Before pushing any commit
$ git pull --rebase origin main
Successfully rebased and updated refs/heads/feature/my-feature.

Common Traps (Part 1)

git diff vs INDEX

git diff with no arguments shows differences between the working copy and the INDEX (staging area), not the last commit!

Use git diff HEAD to compare working copy with the last commit.

git reset & Working Copy

git reset reverts the index but leaves the working copy unchanged. Your files still have the modified content.

Use git reset --hard to also revert the working copy (warning: discards changes!).

Common Trap: git diff Behavior

TRAP
$ echo "hello" > file.txt
$ git add file.txt
$ echo "hello world" > file.txt
$ git diff
diff --git a/file.txt b/file.txt
--- a/file.txt
+++ b/file.txt
+hello world
-hello
# Shows diff vs INDEX (staged version), not HEAD!
CORRECT
$ git diff HEAD
diff --git a/file.txt b/file.txt
--- a/file.txt
+++ b/file.txt
+hello world
-
# Shows diff vs HEAD (last commit)
# Notice: the first version "hello" is gone
# because it wasn't in HEAD yet.

Common Trap: git reset Behavior

$ echo "urgent fix" > main.py
$ git add main.py
$ git reset
Unstaged changes after reset:
M main.py
# Index reverted, but main.py still has "urgent fix" in working copy
$ cat main.py
urgent fix

# To fully undo both index and working copy:
$ git reset --hard HEAD
HEAD is now at a1b2c3d Previous commit message
# DANGER: all uncommitted changes in working copy are lost!

Common Traps (Part 2)

Git is Not Forgiving

Don't ignore warnings. Never use --force unless you fully understand the consequences. Git will let you shoot yourself in the foot.

History is Not Immutable

Rebasing, amending, and force-pushing can rewrite history. Once pushed and shared, rewriting history causes pain for collaborators.

Detached HEAD State

git checkout on an arbitrary commit or tag (not a branch) puts you in "detached HEAD" state. You can commit, but those commits will be lost without a branch or tag reference.

Detached HEAD Scenario

$ git log --oneline
a1b2c3d (HEAD -> main) Implement dashboard
e5f6g7h Add user authentication
i9j0k1l Initial commit

$ git checkout e5f6g7h
Note: switching to 'e5f6g7h'.
You are in 'detached HEAD' state...
HEAD is now at e5f6g7h Add user authentication

$ git log --oneline
e5f6g7h (HEAD) Add user authentication
i9j0k1l Initial commit
# Note: "main" branch & "Implement dashboard" are no longer reachable from HEAD!

Detached HEAD State

What It Looks Like

Git prints a warning message when entering detached HEAD. The prompt may show (HEAD detached at a1b2c3d).

How to Get Into It

Run git checkout <commit-hash> or git checkout <tag> instead of a branch name.

How to Get Out

Create a branch from the current position: git checkout -b <branch-name> or switch back: git checkout main.

The Risk

You can commit in detached HEAD state, but those commits become unreachable (and may be garbage collected) if no branch/tag points to them.

Visual: Detached HEAD

# Normal state: HEAD points to a branch
HEAD → main → a1b2c3d → e5f6g7h → i9j0k1l

# Detached HEAD: HEAD points directly to a commit
$ git checkout e5f6g7h
HEAD → e5f6g7h
↓
i9j0k1l
↓
...
(main branch still points to a1b2c3d)

# To save work done in detached HEAD:
$ git checkout -b save-my-work
HEAD → save-my-work → e5f6g7h (now safe!)

Other Useful Utility Commands

git gc

Garbage collector. Cleans up unreachable objects and compresses the .git/ directory. Run when .git/ takes too much space.

$ git gc
Counting objects: 152, done.
Delta compression using up to 8 threads.
Removing duplicate objects: 100%...

git stash

Temporarily save the working copy and index. Perfect for urgent fix scenarios: stash, switch branches, fix, switch back, pop stash.

$ git stash
Saved working directory and index state "WIP on feature..."
$ git stash pop
Dropped refs/stash@{0}
# Use git stash list to see all stashes

git clean

Remove untracked files from the working tree. Ensure all valuable code is committed first!

$ git clean -n
Would remove build/output.o
$ git clean -f
Removing build/output.o
# -n = dry run; -f = force; -fd = include dirs

git bisect

Binary search to find the exact commit that introduced a bug. Mark commits as "good" or "bad" and git narrows it down.

$ git bisect start
$ git bisect bad
$ git bisect good v1.0
Bisecting: 8 revisions left to test...
$ git bisect good
Bisecting: 4 revisions left to test...
$ git bisect bad
a1b2c3d is the first bad commit
$ git bisect reset

git cherry-pick

Apply a specific commit from another branch onto the current branch. Useful for porting a single fix without merging the whole branch.

$ git cherry-pick a1b2c3d
[main a1b2c3d] Fix login bug
Date: Mon May 18 14:30:00 2026
1 file changed, 2 insertions(+), 1 deletion(-)

git revert

Create a new commit that undoes a previous commit. Safer than git reset because it doesn't rewrite history.

$ git log --oneline
a1b2c3d (HEAD) BROKEN: added debug prints
e5f6g7h Working version
$ git revert a1b2c3d
[main f8a9b0c] Revert "BROKEN: added debug prints"
1 file changed, 3 deletions(-)
# Creates a NEW commit that inverses a1b2c3d
