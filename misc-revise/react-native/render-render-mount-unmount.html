What's happening?

Mount: React creates the component, runs it, renders JSX to the screen. useEffect([]) fires.

Re-render: State changes → React re-runs the component, compares new vs old JSX, updates only what changed (diffing).

Unmount: Component is removed from the tree. Cleanup functions fire.

The Diagram

1. App() ← mount
├─ Header ← mount
├─ Counter ← mount
│ └─ count=0 ← render
│ └─ count=1 ← re-render
├─ {child}? ← mount / unmount
└─ Footer ← mount
💡 Key insight: A re-render of the parent does NOT remount the child. Only adding/removing the child from JSX causes mount/unmount.

The Code

App.tsx 
function App() {
  const [count, setCount] = useState(0);
  const [show, setShow] = useState(false);

  // 🔵 Runs on mount + every re-render
  console.log('App rendered');

  // 🟢 Runs once on mount
  useEffect(() => {
    console.log('Mounted');
  }, []);

  return (
    <View>
      <Text>{count}</Text>
      <Button title="+" onPress={() => setCount(c => c + 1)} />

      // 🔴 Toggle = mount/unmount
      {show && <Child />}
      <Button title="toggle" onPress={() => setShow(s => !s)} />
    </View>
  );
}

// Each time Child is conditionally rendered:
//   show=true  → Child mounts  (useEffect runs)
//   show=false → Child unmounts (cleanup runs)
function Child() {
  useEffect(() => {
    console.log('Child mounted');
    return () => console.log('Child unmounted');
  }, []);
  return <Text>I'm a child</Text>;
}

The Golden Rule

  • setState → re-render that component (and children)
  • Conditional rendering {flag && } → mount when true, unmount when false
  • Re-render parent ≠ re-mount child. Child's useEffect([]) does NOT re-run on parent re-render.
  • Unmount always fires cleanup from useEffect return.
