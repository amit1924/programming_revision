How it works

Change happens — state updates in React

New VDOM tree — React creates a new virtual tree in memory

Diffing — React compares old vs new tree (not the real DOM)

Minimal update — Only the changed nodes touch the real DOM

What is VDOM?

// Real DOM — slow to touch document.getElementById('root').innerHTML = ...; // Virtual DOM — plain JS object (fast) const vdom = { type: 'View', props: { style: {} }, children: [ { type: 'Text', props: {}, children: 'Hello' } ] }; // React creates VDOM → diffs it → patches real DOM // Only the minimum necessary DOM operations
💡 Why VDOM? Touching the real DOM is slow (reflow, repaint). VDOM lets React batch changes and update the DOM in the most efficient way.

The 3-Step Process

1 Render

React calls your component function. It returns a Virtual DOM tree (JS object). No real DOM touched yet.

function App() {
  return <View>...</View>;
}
// VDOM: { type: 'View', props: {}, children: [...] }
2 Diff / Reconciliation

React compares the new VDOM tree with the previous one. It walks both trees and finds differences (additions, removals, changes).

// Old: <Text>Bob</Text>
// New: <Text>Bob (away)</Text>
// Diff: textContent changed!
3 Commit / Patch

React updates the real DOM — but only the nodes that changed. The rest stays untouched. This is called batching.

// React does this efficiently:
node.textContent = 'Bob (away)';
// Only 1 DOM operation instead of rebuilding everything

Minimal Example

App.tsx 
function App() {
  const [name, setName] = useState('Alice');

  // 1. You call setName('Bob')
  // 2. React creates a new VDOM tree in memory:
  //    { type: 'Text', props: {}, children: 'Bob' }
  // 3. React diffs old VDOM vs new VDOM
  //    Old: 'Alice'  →  New: 'Bob'  →  change detected
  // 4. React patches the real DOM (only this text node)

  return <Text>Hello {name}</Text>;
}
