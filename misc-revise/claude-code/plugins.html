01

What are Plugins?

A plugin is a directory with a plugin.json manifest that packages all Claude Code extensions into a single, shareable unit. Instead of scattering config across .claude/ dotfiles, you get one folder you can version, publish, and share.

Standalone (.claude/)
  • Skills in .claude/skills/
  • Hooks scattered across project root
  • MCP config in .claude/mcp.json
  • No versioning or packaging
  • Manual setup per project
vs
Plugin Distribution
  • Everything in my-plugin/ folder
  • Single plugin.json manifest
  • Install with claude plugin add
  • Semantic versioning support
  • Portable across projects

03

What Plugins Can Include

Six component types a plugin can bundle. Each becomes available to Claude Code on plugin load.

⚙

Skills

Markdown instructions that teach Claude Code new abilities, patterns, and workflows.

🤖

Agents

Specialized autonomous agents with their own instructions and tool access scopes.

🔗

Hooks

Shell scripts that run before/after commands — for linting, formatting, and validation.

🌐

MCP

Model Context Protocol servers exposing external data sources, APIs, and databases.

⌨

LSP

Language Server Protocol integrations for real-time code intelligence in any language.

📈

Monitors

File watchers that trigger actions on file changes — rebuild, restart, notify.

04

Creating a Plugin

Two approaches: use the scaffold command for a quick start, or create everything manually.

⚡ claude plugin init

Run the interactive scaffold — it asks for plugin name, description, and which components to include.

# Create a new plugin interactively claude plugin init my-plugin
# Move into your new plugin cd my-plugin
# Install it locally claude plugin add .

✎ Manual Creation

Create the directory structure and plugin.json yourself.

# Create directories mkdir -p my-plugin/{skills,agents,hooks,lsp,monitors}
# Create plugin.json cat > my-plugin/plugin.json <<EOF { "name": "my-plugin", "version": "1.0.0", "skills": ["skills/*.md"] } EOF
# Add a skill touch my-plugin/skills/my-skill.md
05

Migrating Standalone → Plugin

Moving from .claude/ dotfiles to a plugin is straightforward. Here's the mapping:

Standalone PathPlugin Path
.claude/skills/*.md→my-plugin/skills/*.md
.claude/agents/*.md→my-plugin/agents/*.md
.claude/hooks/pre-command→my-plugin/hooks/pre-command.sh
.claude/mcp.json→my-plugin/mcp.json
.claude/commands/*→my-plugin/hooks/commands/*
.claude/lsp/*→my-plugin/lsp/*
💡 Migration Tips

Copy existing .md files verbatim — skills/agents need no changes. The plugin.json manifest is the only new file. Run claude plugin add ./my-plugin to test, then remove the old .claude/ entries once verified.
