Skills Basics

Everything you need to know about SKILL.md — how skills work, where they live, and how to build your own.

01

What is a Skill?

A skill is a reusable instruction file (SKILL.md) that teaches Claude how to handle a specific task. Skills live in your project, your home directory, or in plugins.

02

SKILL.md Anatomy

A SKILL.md file has two parts: frontmatter (YAML metadata) and body (markdown instructions).

File Tree
📁my-project/
📁.claude/
📄SKILL.md ● active
📁src/
📄 index.js
SKILL.md 
---
name: my-skill
mode: auto
description: Does a thing
---

## Instructions

When asked to do the thing, follow these steps:
1. Step one here
2. Step two here

Frontmatter Reference

core modestringauto | manual | bothboth

info modelstringModel name (e.g. claude-sonnet-4-20250514)—
info modelDescriptionstringShown to model for routing—
behavior systemPromptstringPrepended to system prompt—

behavior afterCommandsstringRun after registered commands—
ux autocompletestringAutocomplete hint for manual invocations—

04

Where Skills Live

Skills can live in three locations, checked in order of priority:

👤

User-Level

~/.claude/skills/SKILL.md

Lowest priority. Global skills available everywhere.

📚

Project-Level

.claude/skills/SKILL.md

Medium priority. Scoped to current project.

📦

Plugin-Level

<plugin>/skills/SKILL.md

Highest priority. Bundled with plugins.

Priority Hierarchy
#1 Plugin-Level <plugin>/skills/SKILL.md
▼
#2 Project-Level .claude/skills/SKILL.md
▼
#3 User-Level ~/.claude/skills/SKILL.md

07

Real Example: /commit

Let's build the commit skill step by step.

1Define frontmatter
Name, mode, and description tell Claude Code when this skill applies.
2Add system prompt override
systemPrompt sets custom instructions for this skill.
3Write markdown instructions
The body tells Claude exactly what to do — conventions, format, etc.
4Place in project
Save as .claude/skills/SKILL.md to activate.
.claude/skills/SKILL.md 
---
name: commit
mode: auto
description: Generate commit messages from staged changes
systemPrompt:
  You are an expert at writing conventional commits
  following the Conventional Commits specification.
---

## Instructions

When the user asks to commit or when changes are staged:
1. Run `git diff --cached`
2. Analyze the diff for:
   - Scope (component, module)
   - Change type (feat, fix, refactor, etc.)
   - Breaking changes (`!` after type)
3. Generate commit messages in format:
   `type(scope): description`
4. Offer 3-5 options to the user
5. Commit with their choice
