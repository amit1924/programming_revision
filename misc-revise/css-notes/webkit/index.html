WebKit CSS — Visualized

-webkit- vendor-prefixed CSS properties — what they do, when to use them, and when they're the only way to get the result you want.

0. What is WebKit? — The browser engine behind Safari

WebKit is the browser rendering engine used by Safari (macOS, iOS, iPadOS) and all iOS browsers (Chrome, Firefox, Edge on iOS are all WebKit underneath). CSS properties prefixed with -webkit- are WebKit-specific extensions — some are now standard, some are still unique to Safari.

Critical: iOS only allows WebKit engines. Chrome/Firefox on iOS are safari under the hood. If you want a feature to work on iPhone, it must work in WebKit. -webkit- prefixed properties are often the only way to style certain things on iOS.

1. -webkit-line-clamp — Multi-line text truncation

The only cross-browser way to truncate text at N lines with an ellipsis. Still requires the -webkit- prefix in all browsers.

This is a long card description that demonstrates the line-clamp property. It shows how text can be truncated at any number of lines with an ellipsis automatically added by the browser at the end of the last visible line. 
.card-text {
  display: -webkit-box;           /* required — creates a flex-like box */
  -webkit-line-clamp: 3;          /* number of lines to show */
  -webkit-box-orient: vertical;   /* required — sets box axis */
  overflow: hidden;               /* required — clips the rest */
}
/* ⚠️ Still requires -webkit- prefix in ALL browsers (2024+) */
This is the most-used -webkit- property. Every card grid, every preview, every feed uses it. The -webkit- prefix is required even in Chrome/Firefox — the unprefixed version doesn't exist. See typography notes for details.

3. -webkit-text-stroke & -webkit-text-fill-color — Outlined text

Creates outlined/stroked text. Also supported in Firefox (unprefixed) but originally a WebKit invention.

Text stroke demo — adjust stroke width
2px
Stroked Text 
.text {
  -webkit-text-stroke: 2px #89b4fa;       /* stroke width + color */
  -webkit-text-fill-color: transparent;  /* makes text fill transparent */
  /* also works unprefixed in Firefox */
  text-stroke: 2px #89b4fa;
  text-fill-color: transparent;
}

4. -webkit-appearance / appearance — Reset native UI styles

Removes native OS styling from form elements (buttons, inputs, selects, checkboxes). Required for custom-styled form controls.

Native appearance

OS-dependent look — varies by browser/platform

appearance: none + custom
select { -webkit-appearance: none;
         appearance: none; } /* full reset */
Always use both -webkit-appearance: none and appearance: none (unprefixed). Safari still requires the -webkit- prefix. This is the most reliable cross-browser way to reset form controls.

Controls the gray highlight that appears when tapping links/buttons on iOS Safari. Only works in WebKit.

/* Makes text thinner/lighter — common in dark themes */
body {
  -webkit-font-smoothing: antialiased;    /* macOS Safari/Chrome */
  -moz-osx-font-smoothing: grayscale;     /* macOS Firefox */

7. -webkit-mask — Image/gradient masking

Masks an element using another image or gradient. Transparent parts of the mask hide the element. Originally WebKit, now standard with prefix fallback needed for Safari < 15.

Mask demo — gradient fades the edges
.element {
  background: linear-gradient(135deg, #89b4fa, #cba6f7);
  -webkit-mask: linear-gradient(           /* Safari fallback */
    to right, transparent, black 30%, black 70%, transparent
  );
  mask: linear-gradient(
    to right, transparent, black 30%, black 70%, transparent
  );
}

The bar above fades in from left, is fully visible in the middle, and fades out to the right. This is achieved with a mask gradient, not opacity.

Always use both -webkit-mask and mask. Safari < 15 only supports the prefixed version. The standard mask property works in Chrome/Firefox/Safari 15+.

8. -webkit-overflow-scrolling Deprecated — iOS momentum scrolling

Used to enable smooth momentum scrolling on iOS. Now the default behavior — this property is no longer needed on iOS 13+.

❌ Old code (iOS 5–12)
.scroll {
  overflow: auto;
  -webkit-overflow-scrolling: touch;
  /* iOS momentum scroll */
}
✅ Modern (iOS 13+)
.scroll {
  overflow: auto;
  /* momentum is default now */
}

You can safely remove -webkit-overflow-scrolling from your code. It's been the default since iOS 13 (2019).

9. -webkit-touch-callout — iOS callout menu

Disables the context menu (copy/paste/share) that appears on long-press in iOS Safari. Only works in WebKit.

Default: long-press shows "Copy/Share" popup
Long-press this link on iPhone (try it) 
/* Disable the iOS callout menu on long-press */
.no-callout {
  -webkit-touch-callout: none;
}
/* Useful for web apps that have custom copy behavior */

10. -webkit-box Deprecated — The original flexbox (2009)

The original WebKit flexbox model from 2009. Now replaced by the standard flexbox but still needed for -webkit-line-clamp to work.

❌ Old -webkit-box (2009)
.container {
  display: -webkit-box;
  -webkit-box-orient: horizontal;
  -webkit-box-pack: center;
  -webkit-box-align: center;
}
/* DO NOT use — only kept for line-clamp */
✅ Modern flexbox
.container {
  display: flex;
  justify-content: center;
  align-items: center;
}
/* Use this instead */
The only reason -webkit-box still exists in CSS: -webkit-line-clamp requires display: -webkit-box and -webkit-box-orient: vertical. This is the only valid use case for the old box model in 2024. Everything else should use modern flexbox.

11. WebKit-Only Media Queries & Selectors — Targeting Safari specifically

Safari-only CSS — hacks to target WebKit
Target Safari only
/* Safari 7.1+ */
_::-webkit-full-page-media,
_:future, .selector {
  /* Safari-only styles */
}

/* Safari 10.1+ */
@media not all and
  (min-resolution:.001dpcm) {
  .safari-only { }
}
Target iOS Safari only
/* iOS Safari 10+ */
@supports (-webkit-touch-callout: none) {
  .ios-only { }
}

/* iOS Safari notch area */
@viewport {
  viewport-fit: cover;
}
.under-notch {
  padding-top: env(safe-area-inset-top);
}
Use @supports for feature detection, not UA sniffing. Instead of targeting Safari, test for the specific WebKit property you need: @supports (-webkit-tap-highlight-color: transparent) { /* WebKit-only */ }

12. env(safe-area-inset-*) — Notch & home indicator (iOS)

WebKit-specific CSS environment variables that report the screen's unsafe areas (notch, rounded corners, home indicator). Critical for iOS web apps.

Safe area variables — values auto-set by iOS Safari
env(safe-area-inset-top)
Notch height (iPhone: ~44px)
env(safe-area-inset-bottom)
Home indicator (iPhone: ~34px)
env(safe-area-inset-left)
Rounded corners left
env(safe-area-inset-right)
Rounded corners right
/* Full-screen web app on iPhone */
body {
  padding-top: env(safe-area-inset-top);
  padding-bottom: env(safe-area-inset-bottom);
  padding-left: env(safe-area-inset-left);
  padding-right: env(safe-area-inset-right);
}

/* Or use with viewport-fit for full-bleed */
/* <meta name="viewport" content="viewport-fit=cover"> */
.fixed-footer {
  padding-bottom: max(12px, env(safe-area-inset-bottom));
}

Test on real iOS devices — the browser inspector can't simulate everything. The 3 you'll actually use daily: -webkit-line-clamp, -webkit-appearance (with standard), and -webkit-tap-highlight-color.
