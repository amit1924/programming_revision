1 What Is CSS Positioning?

The position property controls how an element is placed in the document flow. It has 5 values: static, relative, absolute, fixed, and sticky. The top, right, bottom, left offset properties work differently depending on the position value.

Static
Default — normal flow
Relative
Offset from its normal position
Absolute
Positioned relative to nearest positioned ancestor
Fixed
Positioned relative to the viewport
Sticky
Toggles between relative and fixed based on scroll
Z-index
Stacking order on the z-axis
2 Static · The Default
/* Default — no position needed */ .element { position: static; /* top/right/bottom/left have NO effect */ /* z-index has NO effect */ }

Static is the default. Elements flow in normal document order — block elements stack vertically, inline elements flow horizontally. top, left, z-index are ignored.

ⓘ You rarely write position: static. It's the default. But it's useful to reset a positioned element back to normal flow.

3 Relative · Offset From Self
/* Offset from where it WOULD have been */ .element { position: relative; top: 20px; /* pushed DOWN 20px */ left: 30px; /* pushed RIGHT 30px */ /* Original space is PRESERVED — no reflow */ }

Relative offsets the element from its normal position. The element's original space is preserved — other elements don't reflow to fill the gap. Relative also establishes a positioning context for absolutely-positioned children.

4 Absolute · Relative to Ancestor
/* Removed from flow, positioned relative to nearest positioned ancestor */ .parent { position: relative; /* becomes the reference */ } .child { position: absolute; top: 10px; right: 10px; /* Removed from normal flow — no space preserved */ }

Absolute removes the element from normal flow (no space preserved). It positions relative to the nearest positioned ancestor (any ancestor with position: relative/absolute/fixed/sticky). If none exists, it uses the initial containing block (usually the viewport).

⚠ THE #1 GOTCHA: Absolute elements look for the NEAREST positioned ancestor. Forgetting to set position: relative on the parent causes the absolute child to fly to the top of the page!

5 Fixed · Relative to Viewport
/* Stays in place regardless of scroll */ .navbar { position: fixed; top: 0; left: 0; right: 0; height: 60px; /* Removed from flow, relative to viewport */ /* Scrollbars don't push it */ }

Fixed positions the element relative to the viewport. It's removed from normal flow and ignores scrolling. Commonly used for navbars, modals, and back-to-top buttons.

⚠ On mobile, fixed behaves differently. iOS Safari has issues with fixed elements during keyboard open / elastic scrolling. Test thoroughly.

6 Sticky · Relative + Fixed Hybrid
/* Becomes fixed when it reaches top: 0 */ .section-header { position: sticky; top: 0; /* Behaves as relative until it hits top: 0, then "sticks" (behaves as fixed) */ /* Stays in its container — doesn't escape parent */ }

Sticky is a hybrid: it's relative until the scroll reaches its threshold, then it "sticks" (becomes fixed-like). But unlike fixed, it's bounded by its parent container — when the container scrolls past, the sticky element goes with it.

ⓘ Sticky requires a threshold: top, bottom, left, or right must be set. Without it, sticky behaves like relative.

7 Z-Index & Stacking Context

z-index controls stacking within the same stacking context. A stacking context is created by positioned elements, opacity < 1, transform, filter, etc.

/* Stacking context is created by: */ .element { position: relative; /* + z-index !== auto */ opacity: 0.9; /* also creates context */ transform: scale(1);/* also creates context */ filter: blur(1px); // also creates context }
