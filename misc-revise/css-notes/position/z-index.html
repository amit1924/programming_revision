1 What Is Z-Index?

z-index controls the stacking order of positioned elements along the z-axis (the axis coming toward you). Higher values appear closer to the user (on top).

1
2
3
z-index: 3 is on top
/* Higher value = closer to user (on top) */ .box1 { position: relative; z-index: 1; } .box2 { position: relative; z-index: 2; /* on top of box1 */ } .box3 { position: relative; z-index: 3; /* on top of both */ }

z-index only works on positioned elements (relative, absolute, fixed, sticky). It is ignored on static elements.

2 What Happens Without Z-Index?

Even without any z-index, elements stack in a natural order. When elements overlap, the browser decides who's on top based on these rules:

Natural stacking order (bottom to top):
1 (bottom) Background + border of root element
2 Block-level elements in normal flow (in DOM order)
3 Floated elements
4 Inline elements (text, spans)
5 (top) Positioned elements (in DOM order)
Block in normal flow (at bottom of stack)
Float
Inline
Positioned element (always on top of non-positioned)
ⓘ Without z-index, DOM order wins. The last positioned element in the HTML appears on top. This is the default stacking order.

4 The Stacking Context · The Real Key

A stacking context is an isolated group where z-index values are relative to each other within that group. Elements in one stacking context cannot interleave with elements in another.

/* THESE CREATE A NEW STACKING CONTEXT: */ // 1. Positioned + z-index (NOT auto) el { position: relative; z-index: 1; } // 2. Opacity less than 1 el { opacity: 0.9; } // 3. Transform el { transform: scale(1); } // 4. Filter el { filter: blur(1px); } // 5. will-change el { will-change: transform; } // 6. isolation: isolate el { isolation: isolate; }

5 The Trap: Why Z-Index "Doesn't Work"

This is the #1 reason developers say "z-index isn't working." The element has a high z-index but is trapped inside a parent's stacking context.

😈 The Bug

// Parent creates a stacking context .parent { position: relative; z-index: 1; // ⚠ Creates a stacking context! background: rgba(0,0,0,.5); } .child { position: absolute; z-index: 9999; // Intended to be on top // ⚠ But trapped inside parent's context! // Parent's z-index is 1, sibling has 2 // Child's 9999 is ONLY relative within parent }

▶ See it in action

Sibling A (z-index: 1)
Child of A · z-index: 9999
Still BEHIND Sibling B!
Sibling B (z-index: 2)
I'm on top because my parent (Sibling B) has higher z-index than Sibling A
⚠ z-index: 9999 doesn't help if the parent is trapped in a lower stacking context. The child's z-index is relative to the parent's context, not the root.

7 When Z-Index "Doesn't Work"

Here are the 4 most common reasons z-index seems broken — with live demos.

⚠ 1. Element is not positioned

z-index is ignored on position: static. The element must be relative, absolute, fixed, or sticky.

// WON'T WORK: div { position: static; z-index: 999; } // WILL WORK: div { position: relative; z-index: 999; }

⚠ 2. Trapped in a parent's stacking context

Parent has opacity < 1, transform, or position + z-index — child can't escape.

// Parent creates context: .parent { position: relative; z-index: 1; } .child { z-index: 9999; // Still inside parent! }

⚠ 3. Sibling with higher z-index

Another element at the same stacking context level has a higher z-index and overlaps.

.box1 { position: relative; z-index: 2; } .box2 { position: relative; z-index: 3; } // box2 is on top of box1

⚠ 4. Overflow: hidden clipping

A parent with overflow: hidden clips positioned children even if they have higher z-index.

.parent { overflow: hidden; position: relative; } .child { position: absolute; z-index: 999; } // Child is CLIPPED by parent's overflow!
8 Debugging Checklist

When z-index "doesn't work", check these in order:

☐ 1 Is the element positioned? (position: relative/absolute/fixed/sticky) Static ignores z-index
☐ 2 Are there parent stacking contexts trapping the element? Check opacity, transform, filter
☐ 3 Is a sibling at the same level with a higher z-index? Check siblings, not cousins
☐ 4 Is overflow: hidden on a parent clipping the element? Overflow clips positioned children
☐ 5 Is there a transform or will-change on an ancestor? Both create stacking contexts
☐ 6 Use DevTools — check the "layers" tab or inspect computed z-index Visual debugging
9 When to Apply Z-Index

✓ Good uses

  • Modals / Overlays — highest z-index
  • Tooltips & popovers — above UI elements
  • Dropdown menus — above content below
  • Fixed headers — above page content
  • Toast notifications — above everything
  • Drag & drop — active item on top

✗ Overused / wrong

  • Fighting layout bugs — z-index hides layout issues
  • Using 99999 — creates maintenance nightmares
  • Every element positioned — unnecessary stacking contexts
  • Without understanding stacking context — won't work anyway
✓ Best practice: Use small z-index values (1–10) and organize them. Reserve z-index: 1000+ for modals and toasts. Use isolation: isolate to create clean stacking context boundaries.
