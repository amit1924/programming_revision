CSS Units — Deep Visual Guide

px, em, rem, %, vw, vh, vmin, vmax, ch, ex — see them side by side, understand when to use each.

1. Absolute vs Relative The Core Divide

Every CSS unit is either absolute (fixed, predictable) or relative (scales based on context). The choice determines how your layout responds to different screens, font sizes, and user preferences.

📏
px
Absolute
Fixed size. Ignores all context. 1px = 1/96th of an inch.
📐
em
Relative to parent
Scales with parent's font-size. Compounds when nested.
🌳
rem
Relative to root
Scales with <html> font-size. Consistent everywhere.
👁️
vw / vh
Relative to viewport
Scales with window size. Great for full-screen layouts.
🔤
ch / ex
Relative to character
ch = width of "0". ex = height of "x". For text measurements.
📦
%
Relative to parent
Percent of parent's size. Tricky: width vs height behave differently.

3. px — The Absolute Unit Fixed · Predictable

1px = 1/96th of an inch on screens. Pixels are the anchor unit — all other units ultimately compute to px.

px stays the same regardless of anything. Resize the window — it doesn't move.
80px
120px
200px
Use px for
Borders, box-shadows, outline-width, fine decorative details, min/max constraints where you need precision.
Don't use px for
Font sizes, layout widths, padding, margin — if you want the UI to scale with user preferences or screen size.
Rule of thumb: If it should not scale (border width, shadow blur), use px. If it should scale (text, spacing, layout), use a relative unit.

4. % — Relative to Parent Trickiest Unit

A percentage is always relative to something on the parent — but which property of the parent varies by context.

% behaves differently for width vs height vs padding vs margin
Parent (width: 100%)
25%
50%
75%
width: 50%
50% of parent's width. Most intuitive % use.
height: 50%
50% of parent's height. Only works if parent has an explicit height.
padding: 10%
Always relative to parent's WIDTH — even for padding-top/bottom!
margin: 10%
Always relative to parent's WIDTH — even for margin-top/bottom!
Biggest gotcha: padding-top: 50% is 50% of parent's width, not height. This is famously used for aspect-ratio boxes: padding-top: 56.25% = 16:9, padding-top: 100% = 1:1 square.

5. em — Relative to Parent Font Compounds!

1em = current element's font-size. If not set on the element, it inherits from the parent. If the parent uses em too, it compounds.

Each nested level multiplies the em — the "compounding effect"
16px
Level 0: 1em = 16px
Level 1: 1.5em = 24px
Level 2: 1.5em of 1.5em = 36px
Level 3: 1.5em of 2.25em = 54px 
/* em compounds — watch out! */
html  { font-size: 16px; }
div   { font-size: 1.5em; }  /* 16 * 1.5 = 24px */
  div { font-size: 1.5em; }  /* 24 * 1.5 = 36px */
    div { font-size: 1.5em; }/* 36 * 1.5 = 54px */
Use em for
Padding/margin that should scale with the element's font-size. Components that need to scale proportionally when their font changes.
Don't use em for
Font sizes across a large app — the compounding effect makes it unpredictable. Prefer rem for global typography.

6. rem — Relative to Root Consistent · Accessible

1rem = root element's font-size (the <html> element, usually 16px). Unlike em, rem never compounds — it's always relative to the same base.

rem is the SAME everywhere — no compounding
16px
1rem = 16px
1.5rem = 24px
1.5rem (same!) = 24px
1.5rem (same!) = 24px
rem does NOT compound — all nested levels are 24px
Use rem for
Global font sizes, spacing (padding, margin), max-width containers. The standard for accessible, scalable typography.
Best practice
Set html { font-size: 100% } (respects user's browser font-size setting). Use rem everywhere for text and spacing.
Accessibility win: Users who set their browser default to 20px get 1rem = 20px. If you used px for font sizes, their preference is ignored. With rem, your entire UI scales up proportionally.

7. vw & vh — Viewport-Relative Screen Size

1vw = 1% of viewport width. 1vh = 1% of viewport height. Perfect for full-screen sections and responsive typography.

Use vw/vh for
Full-screen hero sections (height: 100vh), responsive font sizes with clamp(), overlays that cover the viewport.
Watch out for
100vh on mobile includes the address bar. Use 100dvh (dynamic viewport height) for modern browsers. And 100vw includes the scrollbar width.
Fluid typography trick: font-size: clamp(1rem, 2.5vw, 3rem); — text scales with viewport but stays between min and max. No media queries needed for responsive text.

8. vmin & vmax Edge Cases

vmin = the smaller of vw and vh. vmax = the larger of vw and vh. Useful for maintaining proportions on differently-oriented screens.

9. ch & ex — Character-Relative Typography

1ch = width of the "0" character in the current font. 1ex = height of the "x" character (the x-height). Great for text measurement.

ch is useful for setting readable line widths
With max-width: 65ch (ideal reading width):
This paragraph is constrained to 65ch — the optimal line length for readability. Studies show that 45-75 characters per line is ideal for comfortable reading. Any wider and the eye struggles to track to the next line; any narrower and the text feels choppy. 
/* Perfect reading width */
.article {
  max-width: 65ch;  /* ≈ 65 characters wide */
}
Use ch for
Container widths for readable text (max-width: 65ch), monospace layouts, input field widths.
Use ex for
Vertical measurements relative to lowercase letters (rarely used). ex can help with inline elements.

10. Fluid Typography with clamp() The Best of Both

clamp(min, preferred, max) combines relative and absolute constraints — the holy grail of responsive typography.

12. Unit Decision Tree Cheat Sheet

  ┌─ What am I sizing?
  │
  ├─ Font size?
  │   ├─ Use rem for most text (respects user preferences)
  │   ├─ Use em for component-relative text (buttons, badges)
  │   └─ Use clamp(…, vw, …) for fluid headlines
  │
  ├─ Layout width?
  │   ├─ Use % for fluid containers
  │   ├─ Use rem for fixed-width components (sidebars, cards)
  │   └─ Use vw for full-viewport sections
  │
  ├─ Spacing (padding, margin)?
  │   ├─ Use rem for global spacing (consistent everywhere)
  │   ├─ Use em for spacing that should scale with the element's font
  │   └─ Use px for tiny adjustments (1px, 2px)
  │
  ├─ Border / Shadow?
  │   └─ Use px — these should never scale
  │
  ├─ Text container width?
  │   └─ Use ch — max-width: 65ch for readable articles
  │
  └─ Full-screen section?
      └─ Use vh / vw — min-height: 100vh or 100dvh
