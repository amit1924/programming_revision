width: auto, 100%, 100vw, min-width, max-width, margin: auto — when each applies, how they behave, and whether width is inherited.

1. The Default: width: auto — Not the same for block vs inline

width: auto is the default for every element, but it behaves differently for block vs inline elements:

block width: auto
parent
Fills parent width (100% of available) 
div { } /* width: auto → fills parent */
inline width: auto
This is a sentence with inline span that shrink-wraps its content 
span { } /* width: auto → shrink-wraps */
Block auto = fill parent, Inline auto = shrink-wrap
block — fills available
block auto → 100%
inline — shrink-wraps

Critical: A block element with width: auto fills its parent's content area. This is NOT the same as width: 100% — auto accounts for margins/padding/borders without overflowing.

3. Width is NOT Inherited — auto != inherited

A child does not get its parent's explicit width. It defaults to width: auto, which fills the parent — but that's auto behavior, not inheritance.

What inheritance is NOT
parent: width: 300px
Child — no width set
This is NOT 300px 
/* Width is NEVER inherited */
.parent { width: 300px; }
.child { } /* width: auto (NOT 300px!) */
What actually happens
parent: width: 300px
Child — auto fills parent
auto → fills parent's width
Child — explicit width: 60%
60% of parent
.parent { width: 300px; }
.child1 { }           /* auto: fills parent */
.child2 { width: 60%; } /* 180px */
Why this matters: width: auto on a block child looks like inheritance because it fills the parent. But it's not — it's the default block behavior. The child always starts from auto, not from the parent's value. Use width: inherit if you truly need inheritance (rare).

4. min-width — "Never Narrower Than This"

Sets a minimum width. The element can grow wider but never shrink below this value. Essential for responsive layouts.

Without min-width
Text can get squished to one letter per line 
.box { width: 100%; }
/* on narrow parent → text crushed */
With min-width
Text stops shrinking at 200px, then scrolls 
.box { min-width: 200px; }
/* never narrower than 200px */

5. max-width — "Never Wider Than This"

Sets a maximum width. The element can shrink but never grow beyond this. Essential for readable layouts on large screens.

Without max-width
Full width on giant screen
This text stretches across the entire screen — very hard to read! 
.text { width: 100%; }
/* on 2560px monitor → 2560px wide text */
With max-width
Capped at 600px + centered
This text is capped at 600px — readable! 
.text { max-width: 600px;
        margin: 0 auto; }
/* comfortable reading width */

.container {

This is THE responsive pattern: width: 100%; max-width: 1200px; margin: 0 auto; — fills the screen on mobile, caps at 1200px on desktop, always centered. The entire web uses this.

6. margin: auto — "Center Me"

margin: auto tells the browser to automatically calculate the margin, pushing the element to the center. Only works on the horizontal axis by default.

7. box-sizing — Affects How Width Is Calculated

box-sizing changes whether width includes padding and border or not. This is critical when using percentage widths.

content-box (default)
parent
width: 100% → overflows! actual width: 100% + 12px*2 + 4px*2 
/* box-sizing: content-box (default) */
.child { width: 100%; padding: 12px;
         border: 4px solid; }
/* OVERFLOWS parent! */
border-box (fixed)
parent
width: 100% → fits perfectly! padding & border included in width 
/* box-sizing: border-box */
.child { width: 100%; padding: 12px;
         border: 4px solid; }
/* FITS inside parent! */
Always use border-box: The universal reset * { box-sizing: border-box; } prevents the most common width bug on the web. Percentage widths with padding no longer overflow.
