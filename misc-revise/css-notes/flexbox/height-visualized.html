When height is automatic, when it's inherited, how block vs inline differ, and when to use min-height / max-height.

1. The Default: height: auto — Content Determines Height

Every HTML element starts with height: auto. The element's height is determined by its content — nothing else.

auto — no fixed height
This box has height: auto Second line — height grows to fit Third line — still fitting 
.element { height: auto; } /* default */
Same content, fixed height
This box has height: 44px Second line is clipped! This cannot be seen
content overflow
.element { height: 44px; overflow: hidden; }
Rule: With height: auto, the element expands to contain its content. With a fixed height, content can overflow (or you need overflow to handle it). Auto is usually what you want.

3. Height is NOT Inherited — This confuses everyone

Unlike font-size or color, height is not inherited. A child doesn't automatically get its parent's height.

Common Mistake: expecting inheritance
Parent: height: 80px
Child — NOT 80px 
.parent { height: 80px; }
.child { } /* height is auto (content), NOT 80px */

Despite what many expect, the child doesn't stretch to fill parent height by default.

The fix: height: 100%
Parent: height: 80px
Child: height: 100% → 80px 
.parent { height: 80px; }
.child { height: 100%; } /* now matches parent */

✅ height: 100% = same as parent's explicit height.

The 100% trap — parent needs an explicit height
✕ height: 100% fails here
Parent: auto (no height set)
Child: height: 100%
↳ falls back to auto (content height)
✓ height: 100% works here
Parent: height: 200px
Child: height: 100%
↳ matches parent's 200px
/* For height: 100% to work, the parent chain must have an explicit height */
html { height: 100%; }
body { min-height: 100%; }
.parent { height: 100%; }
.child { height: 100%; } /* now works */

5. min-height — "Never Smaller Than This" — The safety net

Sets a minimum height. The element can grow taller but never shorter. This is the most useful height property for responsive design.

Without min-height
Empty container collapses to 0 
.box { } /* height: auto → 0 when empty */
With min-height
Empty container stays at 60px 
.box { min-height: 60px; } /* never collapses */

When to use min-height

✅ DO use min-height
  • Full-page layouts: min-height: 100vh
  • Empty states / placeholders
  • Cards with variable content
  • Sidebars (ensure minimum visible area)
  • Panels that load content dynamically
✕ Don't overuse
  • When content is predictable (use auto)
  • On inline elements (ignored anyway)
  • As a replacement for fixed height
  • When you need precise control (use height)

Best practice: Use min-height: 100vh on your page wrapper and min-height on components that load async content. It's the safest height property — it guarantees a minimum without breaking content flow.

When to use max-height

✅ DO use max-height
  • Expandable panels / accordions
  • Chat message areas (scrollable)
  • Dropdown menus with scroll
  • Modal bodies (prevent overflow)
  • Code blocks / preformatted text
✕ Don't use alone
  • Always pair with overflow (auto/scroll)
  • Don't clip important content without warning
  • Not for page-level layout (use min-height)
  • Avoid on elements with dynamic unknown content

Golden rule: Prefer height: auto (the default) whenever possible. Use min-height for safety nets. Use height: 100vh for full-screen sections. Use max-height + overflow for scrollable containers. Never set fixed heights on content that can grow unpredictably.
