Py __name__ == "__main__"
Python › __name__ idiom
Core Pattern
1 What Is __name__?

__name__ is a special built-in variable that Python sets automatically in every file. Its value depends on how the file is being used.

▶ Run Directly

"__main__"
$ python calculator.py
Python sets __name__ → "__main__"

📦 Imported

"calculator"
>>> import calculator
Python sets __name__ → module name
Key insight: __name__ is not something you define — Python sets it automatically. Your code just checks it with if __name__ == "__main__": to decide what to do based on how the file is being used.
2 The Two Scenarios

Scenario 1: Run Directly

When you run a file with python file.py, Python executes it from top to bottom. It sets __name__ to "__main__" before executing.

📄 calc.py
1 def add(a, b):
2     return a + b
3
4 # Python sets this before running:
5 print("__name__ ==", __name__)
6 # Output: __name__ == __main__
$ python calc.py # Python executes the file... __name__ == "__main__" # ↓ So this condition is True if __name__ == "__main__": # This block RUNS

Scenario 2: Imported

When another file imports this one, Python sets __name__ to the module's name (the filename without .py).

📄 main.py
1 # main.py imports calc
2 import calc
3
4 result = calc.add(3, 5)
5 print(result)
$ python main.py # Python executes calc.py FIRST (due to import) __name__ == "calc" # ← NOT __main__! # ↓ So this condition is False if __name__ == "__main__": # This block does NOT run
3 The Guard Pattern

The guard is the if __name__ == "__main__": block. It creates a fence — code inside runs only when the file is executed directly, not when imported.

📄 utils.py
⬇
▶ python utils.py
→
✅ Guard runs
vs
📦 import utils
→
⛔ Guard skipped
# === With Guard (Correct) === def greet(name): return f"Hello, {name}!" if __name__ == "__main__": # ← The Guard # Only runs when "python file.py" print(greet("Alice"))
Put the guard at the bottom of your file — after all function and class definitions. This ensures everything is defined before the guard runs.
4 What Happens Without the Guard?

❌ Without Guard

# calculator.py — NO guard def add(a, b): return a + b print("Result:", add(5, 3)) # ⚠ Prints when imported too!
Problem: import calculator prints "Result: 8" — unexpected side effect! The import runs all top-level code.

✅ With Guard

# calculator.py — WITH guard def add(a, b): return a + b if __name__ == "__main__": print("Result:", add(5, 3)) # ✅ Only prints when run directly
Safe: import calculator silently defines add — no output. The print only runs when python calculator.py is executed.

7 Real Example: CLI Tool

A typical Python CLI tool uses the guard to separate library code from CLI code.

📄 math_tools.py
1 import sys
2
3 # Library code — reusable
4 def add(a, b):
5     return a + b
6
7 def multiply(a, b):
8     return a * b
9
10 # Guard — CLI entry point
11 if __name__ == "__main__":
12     a = int(sys.argv[1])
13     b = int(sys.argv[2])
14     print(add(a, b))
# Run as CLI — guard activates $ python math_tools.py 10 5 15 # Import as module — guard skips $ python >>> import math_tools >>> math_tools.add(3, 4) 7 # No CLI output — clean import!
8 Common Mistakes
MistakeWhy It's WrongFix
if __name__ == "__main__" at the top of file Functions used inside aren't defined yet Move the guard to the bottom
Forgetting the double underscores __name__ is __name__ not _name_ or __main Use exactly __name__ and "__main__"
Putting ALL code inside the guard Functions aren't accessible when imported Define functions outside, call inside
