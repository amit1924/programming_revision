1 What Is the MCP Inspector?

MCP Inspector is a web-based UI for testing and debugging MCP servers. It connects to your server and lets you explore tools, resources, and prompts — all without writing any code.

🌐 Browser
You open the UI
←→
🔍 Inspector
localhost:5173
←→
⚡ MCP Server
Your server process
# Start the inspector (from mcp folder): $ npx @modelcontextprotocol/inspector node my-server.js # → Opens http://localhost:5173 in your browser
Think of it as Postman for MCP. Just like Postman lets you test REST APIs without writing code, the Inspector lets you test MCP servers — list tools, call them, read resources — all from a visual interface.

3 What You Can Do in the Inspector

Click List Tools to see all tools your server exposes. Click a tool to call it with custom arguments.

🔧 Tool: get_weather
▸ Enter a city and click "Call Tool"

Click List Resources to browse data the server provides. Each resource has a URI and MIME type.

weather://Mumbai → application/json
weather://London → application/json
weather://Tokyo → application/json

Click Get Prompts to see pre-built prompt templates. Select one and fill in arguments.

summarize_weather "Summarize weather for {city}"
compare_cities "Compare weather between {city1} and {city2}"
travel_advice "Travel advice based on weather in {city}"

View server metadata — protocol version, capabilities, server info.

Protocol Version: 2025-03-26
Capabilities: tools, resources, prompts, logging
Server Name: weather-server
Transport: stdio / streamable-http
4 Request Log — See Every Message

The Inspector logs every JSON-RPC message exchanged — both outgoing requests and incoming responses.

📋 Request Log
4 outgoing 4 incoming
→ initialize protocolVersion: "2025-03-26"
← result capabilities: {tools, resources}
→ tools/list
← result tools: [get_weather, get_forecast]
→ tools/call name: "get_weather", city: "Mumbai"
← result "27°C, Sunny in Mumbai"
→ resources/list
← result resources: [weather://Mumbai, ...]
Why this matters: The request log is the most powerful debugging feature. You can see exactly what your client sends and what the server responds — no guesswork. Spot malformed JSON-RPC, wrong parameters, or error codes instantly.

7 Why Use the Inspector?

❌ Without Inspector

  • ✗ Write test scripts to call each tool
  • ✗ Manually print and inspect JSON-RPC messages
  • ✗ Guess what tools the server exposes
  • ✗ Hard to spot malformed schemas
  • ✗ No visual feedback for debugging

✅ With Inspector

  • ✓ Click to list tools instantly
  • ✓ See every JSON-RPC in real-time log
  • ✓ Visual tool registry at a glance
  • ✓ Spot schema errors immediately
  • ✓ Test arguments before coding
The Inspector is your MCP debugging Swiss Army knife. Before writing any client code, use the Inspector to verify your server works correctly — tool discovery, parameter schemas, response formats, error handling.
8 How to Start the Inspector

You can start the Inspector from your terminal — it works with any MCP server command.

# Basic usage — pass your server command as argument $ npx @modelcontextprotocol/inspector node my-server.js # With Python server $ npx @modelcontextprotocol/inspector python weather-server.py # With arguments for the server $ npx @modelcontextprotocol/inspector node server.js --port 3000 # Opens browser at http://localhost:5173
Pro tip: The Inspector wraps your server command — it launches the server as a subprocess (stdio transport) and connects to it. All traffic between the Inspector UI and your server shows up in the request log.
