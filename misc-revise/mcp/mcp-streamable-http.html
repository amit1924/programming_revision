1 What Is Streamable HTTP?

Streamable HTTP is a new MCP transport that uses standard HTTP POST requests + chunked transfer encoding for streaming responses — no persistent connection needed.

Remote Persistent

Streamable HTTP

HTTP POST for both directions. Chunked encoding for streaming. No persistent connection.

Remote Stateless Streaming
Think of it as: Regular HTTP requests that can stream their response back using chunked transfer encoding. No WebSocket, no SSE — just plain HTTP POST with a streaming twist.
2 How Streamable HTTP Works

The Core Idea

Instead of keeping a persistent connection open (like SSE), Streamable HTTP uses standard HTTP POST for each request. The server sends back the response using chunked transfer encoding, which allows streaming data without knowing the full size upfront.

🔌 Client
── POST /mcp ──▶
🌐 HTTP
── POST /mcp ──▶
⚡ Server
🔌 Client
◀── Chunked stream ──
🌐 HTTP
◀── Chunked stream ──
⚡ Server
Key difference from SSE: With SSE, the client keeps a persistent TCP connection open to receive events. With Streamable HTTP, each request is a separate HTTP POST, and the response is streamed back chunk-by-chunk. No persistent connection to maintain.
3 Request & Response Format

🔵 Client → Server (POST)

Client sends a JSON-RPC message as the HTTP request body.

HTTP Request
POST /mcp HTTP/1.1
Host: api.example.com
Content-Type: application/json
Accept: application/json, text/event-stream
JSON-RPC Body
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "get_weather",
    "arguments": { "city": "Mumbai" }
  }
}

🟠 Server → Client (Chunked Response)

Server responds with chunked transfer encoding. Each chunk can be a partial result.

HTTP Response
200 OK
Content-Type: application/json
Transfer-Encoding: chunked
Chunked Body (streamed)
chunk 1 {
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [{
      "type": "text",
      "text": "27°C, Sunny"
    }]
  }
}
Chunked encoding No persistent TCP
4 SSE vs Streamable HTTP
FeatureSSE TransportStreamable HTTP
Connection Persistent TCP (kept open) Short-lived HTTP request/response
Streaming SSE events over open connection Chunked transfer encoding
Infrastructure Needs special config for load balancers (timeouts, sticky sessions) Works with standard HTTP load balancers
Connection Count 1 TCP per session (held open) 1 TCP per request (released after response)
Server Push ✅ Yes (events sent anytime) ❌ No (response to a request only)
Complexity Medium (SSE protocol) Low (plain HTTP)
Best For Long-running connections, real-time updates Request-response, serverless, HTTP-only infra
Streamable HTTP is simpler. No persistent connections means it works everywhere standard HTTP works — serverless functions, container orchestration, standard load balancers. SSE requires infrastructure that supports long-lived connections.

6 Code: Streamable HTTP Server

Here's a minimal Streamable HTTP MCP server using Python's FastAPI or any HTTP framework.

# streamable_http_server.py from fastapi import FastAPI, Request from fastapi.responses import StreamingResponse from mcp.server import Server import json app = FastAPI() mcp = Server("weather-server") @mcp.tool() async def get_weather(city: str) -> str: return f"27°C, Sunny in {city}" @app.post("/mcp") async def handle_mcp(request: Request): body = await request.json() # Process through MCP server result = await mcp.process_request(body) # Stream response back return StreamingResponse( iter([json.dumps(result)]), media_type="application/json", headers={"Transfer-Encoding": "chunked"} )
# Client connecting to Streamable HTTP import httpx async def call_mcp(method, params): async with httpx.AsyncClient() as client: response = await client.post( "http://localhost:8000/mcp", json={ "jsonrpc": "2.0", "id": 1, "method": method, "params": params } ) return response.json() # Usage — just like REST API! result = await call_mcp( "tools/call", {"name": "get_weather", "arguments": {"city": "Mumbai"}} ) print(result) # → 27°C, Sunny in Mumbai
Notice: The client just does a normal HTTP POST. No special SSE parsing, no persistent stream handling. The server uses Transfer-Encoding: chunked to stream the response back if needed.
7 When to Use Streamable HTTP

✅ Good For

  • ✓ Serverless deployments (AWS Lambda, Cloudflare Workers)
  • ✓ HTTP-only infrastructure
  • ✓ Standard load balancers (no sticky sessions needed)
  • ✓ Simple request-response patterns
  • ✓ Microservices architecture

❌ Not Ideal For

  • ✗ Real-time server push (notifications)
  • ✗ Long-lived bidirectional streaming
  • ✗ Scenarios needing persistent connection state
  • ✗ SSE-based event streaming
8 Transport Evolution

MCP transports have evolved to meet different deployment needs:

v1
stdio Local subprocess → stdin/stdout. For local development and local-only tools.
v2
HTTP + SSE Remote access via HTTP POST + SSE stream. Persistent TCP connection.
v3
Streamable HTTP Simple HTTP POST with chunked response. No persistent connection. Works everywhere HTTP works.
Bottom line: Streamable HTTP is the simplest remote transport. If your infrastructure supports standard HTTP (and whose doesn't?), this is the easiest MCP transport to deploy. No persistent connections, no special proxies, no sticky sessions.
