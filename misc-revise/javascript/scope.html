1 What Is Scope?

Scope defines where a variable is accessible in your code. It's the region of the program where a variable can be referenced. JavaScript has three types of scope: global, function, and block.

GLOBAL
const user = "Alice"
FUNCTION
let age = 30
BLOCK
const msg = "Hello"
Inner scopes can access outer variables — outer cannot access inner
// GLOBAL scope — accessible everywhere const globalVar = 'I am global'; function myFunction() { // FUNCTION scope — only inside this function let funcVar = 'I am local'; if (true) { // BLOCK scope — only inside this { } const blockVar = 'I am block-scoped'; console.log(globalVar); // ✓ accessible console.log(funcVar); // ✓ accessible } console.log(blockVar); // ✗ ReferenceError! }
2 Global Scope

Variables declared outside any function or block are in the global scope. They are accessible from everywhere — every function, every block, every module.

// In the browser, global = window // In Node.js, global = global var x = 10; // becomes window.x in browser let y = 20; // NOT attached to window const z = 30; // NOT attached to window console.log(window.x); // 10 (var leaks!) console.log(window.y); // undefined (let is safe) console.log(window.z); // undefined (const is safe)
⚠ var leaks to window. let and const do NOT create properties on the global object. This is one reason let/const are preferred.

3 Function Scope

Function scope means every variable declared with var, let, or const inside a function is only accessible within that function. Parameters are also function-scoped.

function greet(name) { // name is function-scoped (parameter) var greeting = 'Hello'; let time = 'morning'; const emoji = '👋'; // ALL of these are accessible here console.log(name, greeting, time, emoji); } greet('Alice'); // Outside: name, greeting, time, emoji // are all UNDEFINED / ReferenceError

var greeting = "Hello"

const emoji = "👋"
All variables live INSIDE the function — invisible from outside
4 Block Scope · let & const vs var

Block scope (ES6+) means variables declared with let and const are confined to the { } block they're in. var ignores block boundaries.

if (true) { var a = 1; // LEAKS outside the block! let b = 2; // Stays inside { } const c = 3; // Stays inside { } } console.log(a); // 1 (— var escaped!) console.log(b); // ReferenceError console.log(c); // ReferenceError

5 The Scope Chain · Variable Lookup

When JavaScript encounters a variable, it walks up the scope chain — starting from the innermost scope outward — until it finds the variable. If it reaches global scope and still doesn't find it, you get a ReferenceError.

const global = 'GLOBAL'; function outer() { const a = 'OUTER'; function inner() { const b = 'INNER'; console.log(b); // Finds in INNER scope console.log(a); // Finds in OUTER scope console.log(global);// Finds in GLOBAL scope } inner(); } outer();

6 Lexical Scoping · Where You Write It Matters

JavaScript uses lexical scoping (also called static scoping). This means scope is determined by where the code is written, not where it's called. A function's scope is defined by its physical position in the source code.

const x = 'GLOBAL'; function outer() { const x = 'OUTER'; function inner() { // Lexical scope: inner is INSIDE outer // So it sees outer's 'x' console.log(x); // "OUTER" } inner(); } outer(); console.log(x); // "GLOBAL"
GLOBAL
const x = "GLOBAL"
outer()
const x = "OUTER" ← inner sees THIS x
inner()
console.log(x) → "OUTER"
ⓘ Lexical vs Dynamic: If JS were dynamically scoped, inner() would use the x from wherever it was called, not where it was written. JS is lexically scoped — always check where the function is defined, not where it runs.
7 The Temporal Dead Zone (TDZ)

let and const are hoisted but not initialized. The period between entering the scope and reaching the declaration is the Temporal Dead Zone — accessing the variable throws ReferenceError.

// TDZ starts at the beginning of the scope // and ends at the declaration { // ↑ SCOPE ENTERS HERE — TDZ BEGINS console.log(x); // ReferenceError! // x is in TDZ — can't access yet let x = 5; // ↑ TDZ ENDS HERE console.log(x); // 5 (works fine) } // var doesn't have TDZ: { console.log(y); // undefined (not error!) var y = 5; }
⚠ TDZ
let x = 5 is hoisted but uninitialized
✓ After declaration
x = 5 — accessible and initialized
8 Scope Pitfalls

⚠ Accidental global (no declaration)

function oops() { leak = 'global!'; // No let/var/const! // JavaScript creates a GLOBAL variable! } oops(); console.log(leak); // "global!"

⚠ Loop scope with var

for (var i = 0; i < 3; i++) { setTimeout(() => console.log(i)); // Prints 3, 3, 3 } // Fix: use let (block-scoped)

⚠ Hoisting confusion

console.log(a); // undefined (not error) var a = 5; // var is hoisted
// but not initialized

⚠ Block scope in switch/case

switch(x) { case 1: let y = 5; // Error: can't redeclare break; case 2: let y = 10; // Same block! break; } // Fix: wrap each case in { }
