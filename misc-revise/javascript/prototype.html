What is a Prototype?

A prototype is just an object that another object inherits from. When you access a property on an object, JavaScript first checks the object itself, then walks up the prototype chain until it finds it or hits null.

myObj { name: "Alice", age: 25 }
── [[Prototype]] ──▶
myObj's Prototype { greet: ƒ, toString: ƒ }
── [[Prototype]] ──▶
Object.prototype { hasOwnProperty: ƒ, toString: ƒ, ... }
── [[Prototype]] ──▶
null — end of chain —

__proto__ vs prototype

These are the most confused two properties in JavaScript. They are not the same thing.

__proto__

The actual prototype link of an instance. Points to the object it inherits from.

const arr = []
arr.__proto__ // → Array.prototype
✅ Exists on instances
✅ The actual prototype link
✅ Also accessible via Object.getPrototypeOf(obj)

prototype

A property on constructor functions/classes. Sets the __proto__ of created instances.

class Foo {}
Foo.prototype // → { constructor: ƒ Foo }
// Now:
new Foo().__proto__ // → Foo.prototype ✅
✅ Exists on constructors only
✅ Used to set __proto__ of new instances
❌ NOT the actual prototype of the constructor itself
⚠️
Function.__proto__ points to Function.prototype (the function's own prototype). But Function.prototype is what new Function() instances get. They point in opposite directions.
function Animal(name) {
  this.name = name;
}
Animal.prototype.speak = function() {
  console.log(`${this.name} speaks`);
};

const dog = new Animal('Rex');

// dog.__proto__ → Animal.prototype ✅
// Animal.prototype → { speak: ƒ, constructor: ƒ }
// Animal.__proto__ → Function.prototype (not Animal.prototype!)
class Cat {
  constructor(name) { this.name = name; }
  meow() { console.log('meow'); }
}

const cat = new Cat('Whiskers');

// cat.__proto__ → Cat.prototype ✅
// Cat.prototype → { meow: ƒ, constructor: ƒ }
// Cat.__proto__ → Function.prototype (classes are functions)

The new Operator — 4 Steps

When you call a function with new, JavaScript does exactly 4 things behind the scenes. Click "Step Through" to see each one.

1 Create a brand new empty object {}
// const obj = {}; (empty)
2 Link the new object's __proto__ to the constructor's .prototype
obj.__proto__ = Constructor.prototype;
3 Bind this to the new object and run the constructor
// Constructor.call(obj, args)
4 Return the new object obj (unless constructor returns an object)
return obj;

// What new actually does:
function _new(Constructor, ...args) {
  // 1. Create empty object
  const obj = {};

  // 2. Link prototype
  Object.setPrototypeOf(obj, Constructor.prototype);

  // 3. Bind this + run constructor
  const result = Constructor.call(obj, ...args);

  // 4. Return object
  return result instanceof Object ? result : obj;
}
// Visual demo:
function Animal(name) {
  this.name = name;
}

const rex = new Animal('Rex');

// Step 1: {} created
// Step 2: rex.__proto__ = Animal.prototype
// Step 3: this.name = 'Rex' runs
// Step 4: rex is returned
console.log(rex.name); // 'Rex'
console.log(rex.__proto__ === Animal.prototype); // true

// 1. Prototypal inheritance with Object.create
const animal = {
  speak() { console.log(`${this.name} speaks`); }
};

const dog = Object.create(animal);
dog.name = 'Rex';
dog.speak(); // 'Rex speaks' — from prototype

// 2. Constructor function inheritance
function Dog(name) { this.name = name; }
Dog.prototype = Object.create(animal);
Dog.prototype.bark = function() {
  console.log('Woof!');
};
// 3. ES6 class inheritance (same under the hood)
class Animal {
  constructor(name) { this.name = name; }
  speak() { console.log(`${this.name} speaks`); }
}

class Dog extends Animal {
  constructor(name) { super(name); }
  bark() { console.log('Woof!'); }
}

// Dog.prototype.__proto__ → Animal.prototype
// Animal.prototype.__proto__ → Object.prototype

const rex = new Dog('Rex');
console.log(rex instanceof Dog);    // true
console.log(rex instanceof Animal);  // true
console.log(rex instanceof Object);  // true

instanceof — How It Works

instanceof walks the prototype chain of the left operand and checks if Right.prototype appears anywhere. It's essentially: left.__proto__ === right.prototype or left.__proto__.__proto__ === right.prototype ... and so on.

Check below
arr instanceof Array → true ✅
arr instanceof Object → true ✅
arr instanceof Function → false ❌
fn instanceof Function → true ✅
date instanceof Date → true ✅
date instanceof Object → true ✅
/./ instanceof RegExp → true ✅
/./ instanceof Object → true ✅
// How instanceof works under the hood:
function myInstanceof(left, right) {
  let proto = Object.getPrototypeOf(left);
  while (proto !== null) {
    if (proto === right.prototype) return true;
    proto = Object.getPrototypeOf(proto);
  }
  return false;
}

console.log(myInstanceof([], Array));   // true
console.log(myInstanceof([], Object));  // true
console.log(myInstanceof([], Function)); // false
⚠️
instanceof checks the prototype chain. If you change Constructor.prototype after creating an instance, instanceof stops working correctly for that instance.

Own Properties vs Inherited

hasOwnProperty checks if a property exists directly on the object (not on the prototype chain). Inherited properties are "shadowed" when you assign them directly.

hasOwnProperty Demo

function Animal(name) {
  this.name = name; // own
}
Animal.prototype.speak = function() {}; // inherited

const a = new Animal('Rex');

a.hasOwnProperty('name');  // true ✅  (own)
a.hasOwnProperty('speak'); // false ❌ (inherited)
'speak' in a;              // true ✅  (in chain)

Shadowing

const parent = { x: 10 };
const child = Object.create(parent);

console.log(child.x); // 10 (from parent)

child.x = 20; // shadows parent.x
console.log(child.x);           // 20 (own)
console.log(parent.x);          // 10 (unchanged)
console.log(child.__proto__.x); // 10 (still accessible)

// To access the proto's property after shadowing:
delete child.x; // removes shadow
console.log(child.x); // 10 (from parent again)
💡
Use Object.hasOwn(obj, prop) (ES2022+) instead of obj.hasOwnProperty(prop) — safer because it doesn't break if the object overrides hasOwnProperty.

Object.create()

Object.create(proto) creates a new object with its [[Prototype]] set to proto directly — no constructor, no new. It's the purest form of prototypal inheritance.

const animal = {
  speak() {
    console.log(`${this.name} speaks`);
  }
};

// Create an object that inherits from animal
const dog = Object.create(animal);
dog.name = 'Rex';

dog.speak(); // ✅ inherited from animal

// Check the chain:
console.log(dog.__proto__ === animal);
// true ✅

console.log(animal.isPrototypeOf(dog));
// true ✅ (ES5+ method)
// Polyfill: what Object.create does
function objectCreate(proto) {
  function F() {}
  F.prototype = proto;
  return new F();
}

// Object.create(null) → no prototype!
const dict = Object.create(null);
dict.x = 1;
console.log(dict.toString);
// undefined ❌ (no Object.prototype)

// Safe for key-value maps
// (no inherited keys to worry about)

ES6 Classes — Sugar Over Prototypes

ES6 class syntax is syntactic sugar over JavaScript's existing prototype system. The prototype chain looks identical whether you use class or a constructor function.

class Syntax

class Animal {
  constructor(name) {
    this.name = name;
  }
  speak() {
    console.log(`${this.name} speaks`);
  }
}

class Dog extends Animal {
  bark() { console.log('Woof'); }
}

Same Thing with Prototypes

function Animal(name) {
  this.name = name;
}
Animal.prototype.speak = function() {
  console.log(`${this.name} speaks`);
};

function Dog(name) {
  Animal.call(this, name);
}
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;
Dog.prototype.bark = function() {
  console.log('Woof');
};

Both produce the same chain:

rex
⬇ proto
Dog.prototypebark, constructor
⬇ proto
Animal.prototypespeak, constructor
⬇ proto
Object.prototypetoString, hasOwnProp
⬇ proto
null
⚠️
Key difference: class methods are non-enumerable. Constructor function methods assigned to .prototype are enumerable by default. Also, class cannot be called without new (throws TypeError).
