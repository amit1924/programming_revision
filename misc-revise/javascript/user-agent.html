1 What Is the User-Agent?

The User-Agent is an HTTP header that tells the server what browser, operating system, and device is making the request. It's sent with every HTTP request from a browser.

💻 Your Browser
→
User-Agent: Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 ...
→
🏦 Server

What the server sees:

GET /page HTTP/1.1 Host: example.com User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/125.0.0.0 Safari/537.36 Accept: text/html

What it's used for:

  • Serving different content to mobile vs desktop
  • Browser-specific CSS/JS workarounds
  • Analytics (browser/OS market share)
  • Bot detection & content negotiation
  • Download links (correct binary for your OS)

3 The History · Why UAs Are a Mess

The User-Agent string is notoriously convoluted because of a decades-long arms race between browsers pretending to be each other.

1993🌐Mosaic — the first graphical browser. UA: NCSA Mosaic/1.0
1994🤖Netscape — UA: Mozilla/1.0 (X11; ...) — "Mozilla" = "Mosaic killer"
1995💻IE enters. To get frames, IE pretends to be Netscape: Mozilla/1.0 (compatible; MSIE 2.0; ...)
2003🐱Safari — built on KHTML, pretends to be Mozilla: Mozilla/5.0 (Macintosh; ...) AppleWebKit/... (KHTML, like Gecko) Safari/...
2008⚡Chrome — built on WebKit (forked from Safari), pretends to be Safari, which pretends to be Mozilla: Mozilla/5.0 ... AppleWebKit/... (KHTML, like Gecko) Chrome/... Safari/...
2013🦄Edge — originally EdgeHTML, then 2018 rebuild on Chromium. Now pretends to be Chrome, which pretends to be Safari, which pretends to be Mozilla.
⚠ Every modern browser says "Mozilla/5.0" at the start. None of them are actually Mozilla. It's pure historical baggage. The UA string is a lie we all inherited.

6 UA Spoofing & Why It Matters

😈 How UA spoofing works

The User-Agent header is client-controlled. Anyone can change it. Browsers let you override it in DevTools, extensions exist to change it, and curl can set any UA.

// curl pretending to be Chrome: curl -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/125.0.0.0 Safari/537.36" https://example.com // Server thinks it's Chrome on Windows // Node.js fetch with fake UA: fetch(url, { headers: { 'User-Agent': 'Mozilla/5.0 ...' } });

✓ Good uses of spoofing

  • Testing mobile layouts on desktop
  • Accessibility tools behaving as different devices
  • Web scraping with appropriate UA
  • Debugging server-side logic

✗ Bad uses

  • Bypassing browser-specific blocks
  • Faking analytics data
  • Pretending to be a search bot to access restricted content
7 Browser Detection vs Feature Detection

Never rely on User-Agent for critical decisions. Feature detection is the standard approach.

⚠
Bad: UA sniffing
// Fragile — breaks when UA changes const ua = navigator.userAgent; if (ua.includes('Chrome')) { // Assume modern features exist // What about Edge? Opera? Brave? }
✓
Good: Feature detection
// Check the feature directly if ('geolocation' in navigator) { // Feature exists — use it navigator.geolocation.getCurrentPosition(...); } else { // Graceful fallback showManualLocationPicker(); }
✓ The golden rule: Check for the feature, not the browser name. UA sniffing is fragile and breaks when new browsers appear or existing ones update their UA strings.

9 Privacy & Fingerprinting

👀 How UAs contribute to fingerprinting

The UA string is one of many signals used to uniquely identify your browser. Combined with other headers, it can be surprisingly specific.

// Signals used for fingerprinting: - User-Agent (browser + version + OS) - Accept-Language (locale) - Accept-Encoding - Timezone (via JS) - Screen resolution - Installed fonts - Canvas fingerprint - WebGL renderer - Touch/Mouse support

🔒 How to reduce fingerprinting

  • Firefox — has "resist fingerprinting" mode
  • Brave — spoofs UA to generic Chrome version
  • Tor Browser — all users have identical UA
  • UA-CH — Client Hints reduce UA entropy
  • Extensions — User-Agent switchers
ⓘ The combination of User-Agent + Accept-Language + screen resolution alone can uniquely identify ~1 in 10,000 browsers.
10 The Future · User-Agent Client Hints

User-Agent Client Hints (UA-CH) is the modern replacement. Instead of sending one big string, the server requests specific pieces of info it needs.

Old way (User-Agent header)

// Bloated, spoofable, one-size-fits-all: User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 ...
Sent with EVERY request. Can't opt out.

New way (Client Hints)

// Server asks for specific hints: Accept-CH: Sec-CH-UA, Sec-CH-UA-Platform // Browser responds with ONLY what's asked: Sec-CH-UA: "Google Chrome";v="125" Sec-CH-UA-Platform: "Windows"
Opt-in. Granular. Less entropy for fingerprinting.
