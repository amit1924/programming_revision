0. What Is an Object? Key-Value Pairs

An object is a collection of key-value pairs. Keys are strings (or Symbols), values can be any type — including other objects and functions (methods). Objects are reference types: variables hold a reference, not the value itself.

A simple object visualized — each row is a key → value pair
name:"Alice"
age:30
isAdmin:true
greet:ƒ ()
Keys
Always strings (or Symbols). Even with quotes omitted, they become strings. obj[1] → key is "1".
Values
Any type: primitive, object, array, function, Date, etc.
Reference type
const a = {x:1}; const b = a; b.x = 2; // a.x is now 2 — they point to the same object.
Mutable by default
You can always add, update, or delete properties unless frozen/sealed.

2. Accessing Properties dot · bracket · optional chaining

Dot notation — static key
user.name
✔ Clean, readable
✔ user.name
✘ Can't use dynamic keys
✘ Can't use keys with hyphens/spaces
Bracket notation — dynamic key
user["name"]
✔ Dynamic keys: user[key]
✔ Keys with spaces: user["my key"]
✔ Computed: user["age" + 1]
✘ Slightly more verbose
Interactive — click to access different properties
Access: 
// Optional chaining — safe access through null/undefined
user?.address?.city          // → undefined if address is null/undefined (no error!)
user?.address?.city ?? "N/A" // → "N/A" with nullish coalescing

// Nullish coalescing — only for null/undefined (not for 0, "", false)
const x = value ?? "default";  // → "default" only if value is null/undefined
⚠ vs ||: || treats 0, "", false as falsy. ?? only treats null/undefined as nullish. Prefer ?? for defaults.

3. Modifying Properties Add · Update · Delete

Click buttons to modify the object — see it change live
// Mutation operations
obj.key = value;                // → add or update
obj["key"] = value;            // → same via bracket
delete obj.key;                 // → removes property entirely
"key" in obj;                  // → true/false (checks own + inherited)
obj.hasOwnProperty("key");   // → true only if own property
Object.hasOwn(obj, "key");   // → ES2022, recommended
delete removes the key entirely — not just sets it to undefined. After delete obj.x, "x" in obj is false. Setting obj.x = undefined keeps the key with value undefined.

4. Static Methods keys · values · entries · assign · freeze · seal

// Static methods — called on Object itself
Object.keys(obj)      // → ["name", "age"]  (own enumerable keys)
Object.values(obj)    // → ["Alice", 30]    (own enumerable values)
Object.entries(obj)   // → [["name","Alice"], ["age",30]]
Object.assign(target, src) // → merges src into target, mutates target
Object.freeze(obj)    // → makes object immutable (shallow)
Object.seal(obj)      // → prevents add/delete, but allows value changes
Object.hasOwn(obj, key) // → ES2022, checks own property
Object.freeze()
Cannot add, delete, or change values. Shallow — nested objects are still mutable.
Object.seal()
Cannot add or delete properties, but can change existing values.
Object.assign()
Copies own enumerable properties. Shallow. Mutates the target. Object.assign({}, src) = shallow clone.
Spread clone: {...src}
Same as Object.assign({}, src). More concise. Also shallow.

6. Prototypes & Inheritance The Prototype Chain

Every object has an internal [[Prototype]] link to another object (or null). When you access a property, JS walks the chain until it finds it or reaches null.

The prototype chain — click to see property lookup in action:
Access: 
// Prototype chain walk:
obj.name          // → 1. Check obj own props → found! stop.
obj.greet()       // → 1. obj own? No. 2. obj.__proto__? Yes → found!
obj.toString      // → 1-2-3... walks up to Object.prototype → found!
obj.nonexistent   // → walks entire chain → null → returns undefined

// Setting up inheritance
childObj = Object.create(parentObj);  // child's prototype = parent
class Child extends Parent { }        // class inheritance
⚠ hasOwnProperty is critical: for (let key in obj) iterates own + inherited properties. Always use hasOwnProperty or Object.hasOwn() to filter.

7. The this Keyword Depends on Call Context

Method call: obj.fn()
this = the object before the dot (obj). Most intuitive.
Regular fn: fn()
this = global (window) or undefined in strict mode.
Arrow fn: () => {}
this = lexical (inherits from surrounding scope). Can't be rebound.
Event listener
this = the element that received the event.
const obj = {
  name: "Alice",
  greet() { return this.name; },
  greetArrow: () => this.name,  // → undefined (lexical this = global)
};
obj.greet();       // → "Alice"  (this = obj)
const fn = obj.greet;
fn();              // → undefined  (this = global, no .name)
The "this" rule of thumb: Look at the call site — how is the function called? obj.fn() → this = obj. fn() → this = global/undefined. Arrow functions don't care — they use the surrounding this.

8. Getters & Setters Computed Properties

Getters compute a value. Setters run logic on assignment.
const user = {
  firstName: "Alice",
  lastName: "Smith",
  get fullName() { return this.firstName + " " + this.lastName; },
  set fullName(val) { [this.firstName, this.lastName] = val.split(" "); }
};
user.fullName;       // → "Alice Smith"  (getter, no () needed)
user.fullName = "Bob Jones";  // → setter runs, updates both fields
