1. ReferenceError The "Not Found" Error

JavaScript throws a ReferenceError when you try to access a variable that doesn't exist in any scope. This is different from undefined — the variable was never declared at all.

Click each to see the difference
> let x = 42; x
⇐ 42
ReferenceError
Variable was never declared in any accessible scope. The JS engine cannot find it. Code execution stops here unless caught.
undefined
Variable was declared but has no value assigned. JS engine knows it exists, but the value is empty. Code continues running.
TDZ (Temporal Dead Zone)
Accessing let or const before declaration throws ReferenceError too. The variable exists in scope but isn't initialized yet.
⚠ Common cause: Typos. userName vs username. event.target vs event.target. Always check spelling first when you see ReferenceError.

2. undefined Default Empty

undefined is the default value JavaScript assigns when nothing else is set. It's a primitive type with a single value: undefined.

Where undefined appears automatically:
> let a;
⇐ undefined (declared, no assignment)
> function f() {}
⇐ undefined (no return statement)
> const obj = {}; obj.x
⇐ undefined (property doesn't exist)
Declared, no value
let x; → x is undefined. The variable slot exists but is empty.
Missing property
obj.nonExistent → undefined. Not an error — JS just returns undefined.
No return
function f() {} → returns undefined. Every function returns something.
Missing args
f(a) called as f() → a is undefined inside.
void operator
void 0 → undefined. Safe way to get undefined.
Never assign undefined manually. If you need to mark something as "empty", use null. Treat undefined as JS's own "not set" signal, not yours.

3. null Intentional Absence

null is a primitive value representing the intentional absence of any object value. You assign it deliberately.

The crucial difference:
undefined — "JavaScript hasn't set anything here"
null — "I explicitly set this to nothing"
> let user = null;
⇐ null (developer says: no user)
> typeof null
⇐ "object" // historic JS bug, kept forever
> Object.getPrototypeOf(null)
⇐ TypeError: Cannot read properties of null
Use null when
You want to reset a value. Clear a reference. Represent "no data" intentionally (e.g., no user selected, no result yet).
typeof null
Returns "object" — a bug since JS's birth (1995). Can't be fixed without breaking the web. Always use strict equality to check for null.

Critical rule: undefined == null is true. But undefined === null is false. They are different types ("undefined" vs "object"). Always use === when checking for null or undefined.

5. == vs === The Core of Equality

=== (Strict): No type conversion. If types differ → false. == (Loose): Converts types first, then compares.

== Loose Equality
1️⃣ Are types the same? → compare directly
2️⃣ Different types? → coerce one or both
3️⃣ Compare the coerced values
"5" == 5 → coerces string to number → true
0 == false → coerces boolean to number → true
=== Strict Equality
1️⃣ Are types the same?
→ No: return false immediately
→ Yes: compare values
"5" === 5 → types differ → false
0 === false → types differ → false

⚠ The golden rule: Always use === except in these specific cases where == is intentional: checking null == null (catches both null and undefined), or comparing against null/undefined in a single check.

8. Best Practices Decision Tree

✅ Always use ===
Default to strict equality. No surprises. No coercion. Your code is explicit about what it compares.
✅ Use == only for null check
if (x == null) catches both null and undefined. Equivalent to x === null || x === undefined.
✅ Use Object.is for edge cases
Object.is(NaN, NaN) → true (unlike ===). Object.is(-0, +0) → false.
❌ Never rely on coercion
Code like if (x == 1) is fine (same type). But if (x == "1") is ambiguous — be explicit.
// Good — explicit, no surprises
if (x === null)  { /* only null */ }
if (x == null)   { /* null OR undefined — intentional */ }
if (x === undefined) { /* only undefined */ }
if (typeof x === 'undefined') { /* safe even if x is not declared */ }

// Bad — relies on coercion, hard to read
if (!x)  { /* true for 0, "", false, null, undefined, NaN */ }
if (x == 'false') { // ??? */ }
