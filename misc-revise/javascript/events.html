1 What Are Events?

The DOM is event-driven. Events are signals fired when something happens — a click, a keystroke, a form submit, a page load. JavaScript listens for these events and responds with handler functions.

🔈
User clicks a button
↓
🛰
Browser fires a click event
↓
💾
Event handler runs
// The event pattern: const btn = document.querySelector('button'); // 1. Something happens (user clicks) // 2. Browser creates Event object // 3. Event propagates through DOM // 4. Registered handlers execute btn.addEventListener('click', (event) => { console.log('Button was clicked!'); // 'event' contains details: // event.target — what was clicked // event.type — "click" // event.clientX/Y — mouse position });

3 Adding Event Listeners

▶ addEventListener()

The modern, preferred way. Attach multiple handlers to the same event, control capturing/bubbling, and remove them cleanly.

// Multiple handlers — all run: btn.addEventListener('click', handler1); btn.addEventListener('click', handler2); // Both fire! Order is preserved. // Capture phase (third param): el.addEventListener('click', handler, true); // Remove specific handler: btn.removeEventListener('click', handler1); // One-time only: btn.addEventListener('click', handler, { once: true });

✗ onclick / HTML Attributes

The old way. Only one handler per event — setting a second one overwrites the first.

// HTML attribute (avoid): <button onclick="doStuff()"> // Property assignment: btn.onclick = function() { ... }; // This OVERWRITES any previous onclick btn.onclick = function() { ... }; // Only the LAST one runs! // Cannot use capture phase // Cannot use { once } option
Use addEventListener() — it's more flexible and doesn't overwrite other handlers.

4 Event Propagation · Capturing vs Bubbling

When you click a nested element, the event doesn't just fire on that one element — it travels through the DOM tree in three phases.

↓
1. Capturing
Event travels DOWN from document to target
●
2. Target
Event reaches the clicked element
↑
3. Bubbling
Event travels UP from target to document

↓ Capture phase (event.capturing = true)

Event listeners registered with { capture: true } (or true as third arg) fire during the capturing phase — before the event reaches the target.

// Fire during CAPTURE (top-down): document.addEventListener('click', handler, true); // or: document.addEventListener('click', handler, { capture: true });

Use case: Global event interceptors, analytics, before child handlers run.

↑ Bubble phase (default)

Most event listeners fire during the bubbling phase (bottom-up). This is the default behavior — no special flag needed.

// Fires during BUBBLE (bottom-up): el.addEventListener('click', handler); // (third param defaults to false)

Use case: Most handlers. Also enables event delegation.

5 Event Methods · Stop & Prevent

❗ stopPropagation()

Stops the event from traveling further — neither up (bubbling) nor down (capturing).

Click me → parent also has a handler
Child with stopPropagation()
// Click the child or the parent

❗ preventDefault()

Prevents the browser's default behavior for that event (e.g., link navigation, form submit, checkbox toggle). The event still propagates normally.

// Link won't navigate: link.addEventListener('click', (e) => { e.preventDefault(); // Now I handle navigation myself }); // Form won't submit: form.addEventListener('submit', (e) => { e.preventDefault(); // Validate first, then fetch() });
🔗 Click me — I won't navigate
// Click the link
Note: preventDefault() does NOT stop propagation. The event still bubbles.
6 Event Delegation

Delegation uses bubbling to handle events for many elements with a single listener on a parent. This works for dynamic elements too (added after page load).

// BAD: 1 listener per item items.forEach(item => { item.addEventListener('click', handler); // Doesn't work for new items! }); // GOOD: 1 listener on parent list.addEventListener('click', (e) => { const item = e.target.closest('.item'); if (!item) return; // Works for ALL items, // even ones added later! handleItem(item.dataset.id); });

7 The Event Object

Every event handler receives an Event object with properties about what happened.

PropertyWhat it reveals
event.typeThe event name ("click", "keydown", etc.)
event.targetThe element that triggered the event (the actual clicked element)
event.currentTargetThe element the listener was attached to (different from target in delegation!)
event.clientX / clientYMouse position relative to viewport (px)
event.keyKey pressed ("Enter", "Escape", "a")
event.ctrlKey / shiftKey / altKeyModifier keys held during event
event.preventDefault()Cancel default behavior
event.stopPropagation()Stop event from traveling further
event.eventPhaseCurrent phase: 1=capture, 2=target, 3=bubble

8 Custom Events

You can create and dispatch your own events — useful for decoupled components, pub/sub patterns, and frameworks.

// 1. Create a custom event const event = new CustomEvent('user-login', { detail: { userId: 42, name: 'Alice' }, bubbles: true, cancelable: true }); // 2. Dispatch it document.dispatchEvent(event); // 3. Listen for it anywhere document.addEventListener('user-login', (e) => { console.log('User logged in:', e.detail.name); // → Alice });

9 Do All Events Bubble?

Most events bubble — but some don't.

BubbleDo NOT bubbleNotes
click, mousedown, mouseup focus, blur Use focusin/focusout instead
keydown, keyup, keypress mouseenter, mouseleave These fire on the element only, not children
submit, change, input load, unload, beforeunload Window-level events
scroll, wheel, resize (in some cases) error (on media elements) Some are non-bubbling for performance
ⓘ Non-bubbling events cannot be used with event delegation. If you need delegation for focus, use focusin (which bubbles).
