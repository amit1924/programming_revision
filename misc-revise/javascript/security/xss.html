1 What is XSS?

Cross-Site Scripting (XSS) is a vulnerability where an attacker injects malicious scripts into a trusted website. The browser thinks the script came from the trusted site — so it executes with full access to cookies, localStorage, and page content.

Attacker
→
Server
→
Victim
Attacker injects → Server stores/serves → Victim's browser executes

What can an attacker do?

  • 🔒 Steal cookies (session hijacking)
  • 📋 Read localStorage (tokens, secrets)
  • 🕵 Keylog keystrokes (password theft)
  • 🔗 CSRF — make requests on your behalf
  • 🗜 Deface the page
  • 🔎 Scan internal networks
2 The Three Types of XSS

Stored XSS Most dangerous

Malicious script is permanently stored on the server (database, comments, profile).

All users

Reflected XSS Phishing

Malicious script is in the URL and reflected back by the server immediately.

Link

DOM

Server returns safe HTML — vulnerable JS does the damage.

6 The Vulnerable Code

Stored XSS Server-side

// VULNERABLE: renders raw input app.post('/comment', (req, res) => { comments.push(req.body.text); // No sanitization! }); app.get('/comments', (req, res) => { res.send(`<div>${comments.join('</div><div>')}</div>`); // Direct injection into HTML! });
Fix: Use textContent or templating engine with auto-escaping.

Reflected XSS Server-side

// VULNERABLE: echoes query param app.get('/search', (req, res) => { const q = req.query.q; res.send(`<h1>Results for: ${q}</h1>`); // q = <script>alert(1)</script> → executes! });
Fix: Encode output with encodeURIComponent or HTML-escape.

DOM-based XSS Client-side

// VULNERABLE: unsafe DOM insertion const name = location.hash.slice(1); document.getElementById('welcome').innerHTML = `Welcome, ${name}!`; // name = <img src=x onerror=alert(1)> // Server never sees this!
Fix: Use textContent instead of innerHTML.
7 Prevention · The Defense Layers

1. Output Encoding

HTML-escape all user input before rendering. Use textContent not innerHTML.

// Safe el.textContent = userInput; // Danger el.innerHTML = userInput;

2. Content Security Policy (CSP)

Tell the browser what scripts are allowed. Blocks inline scripts by default.

Content-Security-Policy: default-src 'self'; script-src 'self';

3. HttpOnly Cookies

Makes cookies inaccessible to JavaScript. Even if XSS succeeds, cookies are safe.

Set-Cookie: session=abc; HttpOnly // document.cookie → "" (empty!)

4. Input Sanitization

Strip or escape dangerous characters server-side. Use a library like DOMPurify.

const clean = DOMPurify.sanitize(input); // Removes <script>, onerror, etc.
