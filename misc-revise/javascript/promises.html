1. Promise Lifecyclestate machine

A Promise is an object representing the eventual completion (or failure) of an async operation. It starts pending, then settles as fulfilled (resolved with a value) or rejected (with an error). Once settled, a promise is immutable — it cannot change state again.

2. Creating Promisesconstructors

new Promise(executor)
Executor receives resolve & reject callbacks. Runs synchronously (the callback runs immediately).
Promise.resolve(val)
Returns a promise already fulfilled with val. Useful for wrapping sync values.
Promise.reject(err)
Returns a promise already rejected with err.
Promise.resolve(thenable)
If given a .then() object, follows its then — "thenable" unwrapping.
// Executor runs synchronously — "start" logs immediately
const p = new Promise((resolve, reject) => {
  console.log("start");  // <-- runs NOW
  setTimeout(() => resolve("done"), 1000);
});
console.log("after");    // runs BEFORE the promise resolves

3. Consuming Promises.then / .catch / .finally

.then(onFulfilled, onRejected)
Returns a new promise. The callback's return becomes the next promise's value.
.catch(onRejected)
Sugar for .then(null, onRejected). Catches rejections from any previous step.
.finally(onFinally)
Runs regardless of outcome. No access to value/error. Passes through the settled value.
⚠️ .then(a, b) vs .then(a).catch(b)
Two-arg .then catches errors only from the original promise. Chained .catch catches from .then(a) too.

4. Chaining & Flatteningpromise chain

Each .then returns a new promise. If the callback returns a plain value, it's wrapped in Promise.resolve. If it returns another promise, the outer promise "follows" it (flattening).

🧩 Promise chain visualizer
Flattening: Returning a promise from .then() doesn't create nesting — the inner promise is "unwrapped" into the outer chain. This is the superpower that makes chaining clean.

5. Error Handlingpropagation

Rejections propagate down the chain like thrown exceptions. A .catch() at the end catches any rejection in the chain. A .catch() can also return a value to recover from an error.

🛡️ Error handling demo — click to see different strategies
Unhandled Rejections: In modern Node/browsers, an unhandled rejection (no .catch() handler) triggers a warning and will crash future Node versions. Always attach a .catch() or use try/catch with await.

6. Static MethodsPromise.all / race / any / allSettled

Promise.all([...])
Resolves when all resolve. Rejects immediately if any rejects. Returns array of values in input order.
Promise.allSettled([...])
Resolves when all settle (resolve or reject). Returns array of {status, value/reason}. Never rejects.
Promise.race([...])
Resolves/rejects with the first settled promise. If the first to settle rejects, race rejects.
Promise.any([...])
Resolves with the first fulfilled. Ignores rejections unless all reject → AggregateError.

7. Async / Awaitsyntactic sugar

async makes a function return a promise. await pauses execution until a promise settles — but only inside an async function (or modules with top-level await).

// Clean sequential async code — no explicit .then chains
async function fetchUser(id) {
  const response = await fetch(`/api/users/${id}`);
  if (!response.ok) throw new Error("Network error");
  const user = await response.json();
  return user;
}
.then() chain
fetch(url)
  .then(r => r.json())
  .then(d => console.log(d))
  .catch(e => console.error(e))
async/await
try {
  const r = await fetch(url);
  const d = await r.json();
  console.log(d);
} catch(e) {
  console.error(e);
}

Error Handling with try/catch

Using try/catch with await is the cleanest way to handle async errors. Without try/catch, an await rejection becomes an unhandled rejection.

async function safeFetch(url) {
  try {
    const res = await fetch(url);
    return await res.json();
  } catch (err) {
    console.error("Fetch failed:", err);
    return { error: true };  // fallback
  }
}
Top-level await: Available in ES modules (<script type="module">). Allows await outside any async function. Modules that depend on it block execution of dependents.

8. Microtasks vs Macrotasksevent loop

Promise .then()/.catch()/.finally() callbacks run as microtasks. setTimeout, setInterval, DOM events run as macrotasks. Microtasks are processed before the next macrotask — the "microtask queue is checked after every macrotask."

⏱️ Event loop queue visualizer
Microtask Queue (Promise .then/.catch/.finally)
Macrotask Queue (setTimeout, setInterval, I/O)
Key insight: Promise.resolve().then(() => console.log("micro")) runs before setTimeout(() => console.log("macro"), 0). Microtasks are processed in FIFO order until the microtask queue is empty, then the next macrotask is picked.

9. Common Patternsrecipes

Sequential vs Parallel

Sequential (slow but ordered)
for (const id of ids) {
  const r = await fetch(id);
  results.push(await r.json());
}
Parallel (fast, unordered)
const results = await Promise.all(
  ids.map(id => fetch(id).then(r => r.json()))
);

Promisify (callback → promise)

function promisify(fn) {
  return (...args) => new Promise((resolve, reject) => {
    fn(...args, (err, result) => {
      if (err) reject(err);
      else resolve(result);
    });
  });
}
const readFileAsync = promisify(require('fs').readFile);

Retry Pattern

async function fetchWithRetry(url, retries = 3) {
  for (let i = 0; i < retries; i++) {
    try {
      return await fetch(url);
    } catch (err) {
      if (i === retries - 1) throw err;
      await new Promise(r => setTimeout(r, 1000 * (i + 1)));
    }
  }
}

Timeout Wrapper

function withTimeout(promise, ms) {
  const timeout = new Promise((_, reject) =>
    setTimeout(() => reject(new Error('Timed out')), ms)
  );
  return Promise.race([promise, timeout]);
}
// Usage: const data = await withTimeout(fetch(url), 5000);
