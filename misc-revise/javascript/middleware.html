What is Middleware?

Middleware is a function that sits between the request and the response. It can modify the request, end the request, or call the next middleware.

Each middleware either calls next() to pass control forward or sends a response with res.send() / res.json() / etc. If neither happens, the request hangs forever.

Without Middleware

Without middleware, every route handler must repeat the same logic — logging, auth checks, body parsing, error handling. This leads to massive code duplication.

❌ Without Middleware

// Every route duplicates logic
app.get('/api/users', (req, res) => {
  if (!req.headers.authorization)
    return res.status(401).end();
  console.log(req.method, req.url);
  let body = '';
  req.on('data', c => body += c);
  req.on('end', () => {
    const data = JSON.parse(body);
    res.json({ users: [] });
  });
});

app.post('/api/users', (req, res) => {
  if (!req.headers.authorization)
    return res.status(401).end();
  console.log(req.method, req.url);
  let body = '';
  req.on('data', c => body += c);
  req.on('end', () => {
    const data = JSON.parse(body);
    res.json({ created: true });
  });
});

✅ With Middleware

// Middleware handles auth once
app.use(authMiddleware); // Checks token
app.use(loggerMiddleware); // Logs request
app.use(express.json()); // Parses body

// Routes are clean
app.get('/api/users', (req, res) => {
  res.json({ users: [] });
});

app.post('/api/users', (req, res) => {
  res.json({ created: true });
});
⚠️
Without middleware, every route is a tangled mess of boilerplate. A single cross-cutting concern (auth, logging, CORS) requires changes in every route handler.

The next() Function

The next() function is the control flow mechanism of Express. It tells Express to move to the next middleware in the chain. Three behaviors:

next()

Passes control to the next matching middleware. The default — normal flow continues.

app.use((req, res, next) => {
  console.log('Logging...');
  next(); // → next middleware runs
});

next('route')

Skips to the next route handler (skips remaining middleware in the current route).

app.get('/user', checkAdmin, handler);
// checkAdmin calls next('route')
// ↳ skips handler, tries next route

next(err)

Passes an error. Jumps directly to error-handling middleware.

app.use((req, res, next) => {
  if (!req.user)
    next(new Error('Unauth'));
  // ↳ skips all normal middleware
  // ↳ goes to error handler
});

Nothing (HANG)

If middleware neither calls next() nor sends a response, the request hangs indefinitely.

app.use((req, res, next) => {
  console.log('Forgot next()');
  // ❌ no next(), no res.send()
  // ↳ request times out (hangs)
});

Types of Middleware

Express has 5 categories of middleware. Click each card to see a code example.

📱

Application-level

Bound to the app instance. Runs on every request matching the path.

app.use('/api', logger)
🗂️

Router-level

Bound to a Router instance. Scoped to a group of routes.

router.use(authMW)
🚨

Error-handling

4 arguments (err, req, res, next). Called when next(err) is invoked.

app.use((err, req, res, next) => {})
⚙️

Built-in

Bundled with Express: express.json(), express.static(), express.urlencoded().

app.use(express.json())
📦

Third-party

npm packages like cors, morgan, helmet, cookie-parser.

app.use(cors())
// Application-level middleware example const express = require('express'); const app = express(); // Runs on every request app.use((req, res, next) => { console.log(`${req.method} ${req.url}`); next(); });

Order Matters

In Express, middleware runs in the order it was registered. Reordering middleware can break your app. Click two items to swap them and see what changes.

Middleware Stack

1Logger← must come first
2Body Parser← must come before routes
3Auth Check← protects routes
4Error Handler← must come LAST

Effect

✅ Correct order. Logger runs first, body is parsed before auth, auth protects routes, error handler catches all.
⚠️
Common order mistakes: Putting the error handler before routes (it will never catch errors). Putting the body parser after a route that needs it. Putting CORS after your routes.

Conditional Middleware

Middleware can be applied conditionally — by path, by HTTP method, by request property, or using a function wrapper.

Path-based

// Only runs on /api/* routes
app.use('/api', authMiddleware);

// Only runs on /public/* routes
app.use('/', express.static('public'));

Function-based

// Conditional wrapper function
const unless = (path, mw) => {
  return (req, res, next) => {
    if (req.path.startsWith(path))
      return next(); // skip middleware
    mw(req, res, next); // run middleware
  };
};
app.use(unless('/public', authMW));

Error Middleware

Error-handling middleware has 4 parameters (err, req, res, next). It only runs when next(err) or a throw is triggered. It must be registered last in the stack.

Common Middleware Patterns

🔐 Authentication

const auth = (req, res, next) => {
  const token = req.headers.authorization;
  if (!token) return res.status(401).json({error:'Unauthorized'});
  try {
    req.user = jwt.verify(token, SECRET);
    next();
  } catch { next(err); }
};

📝 Request Logging

const logger = (req, res, next) => {
  console.log(`${req.method} ${req.url} - ${Date.now()}`);
  const start = Date.now();
  res.on('finish', () => {
    console.log(`${req.method} ${req.url} ${res.statusCode} ${Date.now()-start}ms`);
  });
  next();
};

🚦 Rate Limiting

const rateLimit = {};
const limiter = (req, res, next) => {
  const ip = req.ip;
  rateLimit[ip] = (rateLimit[ip] || 0) + 1;
  if (rateLimit[ip] > 100)
    return res.status(429).json({error:'Too Many Requests'});
  next();
};

🌐 CORS

const cors = (req, res, next) => {
  res.setHeader('Access-Control-Allow-Origin', '*');
  res.setHeader('Access-Control-Allow-Methods', 'GET,POST,PUT,DELETE');
  if (req.method === 'OPTIONS')
    return res.sendStatus(204);
  next();
};
