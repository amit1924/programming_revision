Responsive & Performance

Great animations work on every screen size and run at 60fps. Learn gsap.matchMedia(), responsive values, and optimization techniques.

1 The Problem — Fixed Values Break on Different Screens

A box that animates 300px to the right looks great on desktop. On a 360px-wide phone, it flies off the screen. Fixed px values are the #1 cause of broken mobile animations.

❌ Broken 
gsap.to(".box", {
  x: 300,  // 300px on a 360px phone?
  duration: 1   // Box flies off-screen!
});
✅ Responsive 
// Use a function — value adapts to viewport
gsap.to(".box", {
  x: () => window.innerWidth * 0.5,
  duration: 1
});

// Or use matchMedia for full control:
const mm = gsap.matchMedia();

mm.add("(min-width: 768px)", () => {
  gsap.to(".box", { x: 300 });
});

mm.add("(max-width: 767px)", () => {
  gsap.to(".box", { x: 120 });
});

Rule of thumb: If an animation uses px values that are >10% of the target element's container, make it responsive. Percentage-based values, matchMedia, or viewport-relative calculations.

2 gsap.matchMedia() — Conditional GSAP Code

gsap.matchMedia() lets you write different GSAP code for different screen sizes. It automatically reverts when the media query no longer matches — no manual cleanup needed. 

const mm = gsap.matchMedia();

// Desktop — big animation
mm.add("(min-width: 768px)", () => {
  gsap.to(".box", {
    x: 250,
    rotation: 360,
    scale: 1.5,
    duration: 2
  });
});

// Mobile — smaller animation
mm.add("(max-width: 767px)", () => {
  gsap.to(".box", {
    x: 100,
    rotation: 180,
    duration: 1.5
  });
});

// ✅ Reverts automatically on resize!
// No need to kill tweens manually

3 Responsive Values — Functions & Viewport

GSAP lets you use functions as values — they're evaluated when the animation starts. Combine with window.innerWidth or getBoundingClientRect for adaptive values. 

// Function-based values — evaluated at animation start
gsap.to(".box", {
  x: () => window.innerWidth * 0.3,
  scale: () => {
    if (window.innerWidth < 640) return 0.5;
    return 1.2;
  },
  duration: 1.5
});

// Self-adapting to any viewport!

// Also useful for element-relative values:
gsap.to(".child", {
  x: () => {
    const parent = document.querySelector(".parent");
    return parent.offsetWidth * 0.5;
  }
});

Pro tip: Function values re-run if you restart the animation. For dynamic resizing, use matchMedia instead — it's cleaner for breakpoint-specific code.

4 ScrollTrigger & Resize

ScrollTrigger calculates positions once on init. When the user rotates their phone or resizes the window, those positions become stale. You need to ScrollTrigger.refresh(). 

// Refresh ALL ScrollTriggers on resize
window.addEventListener("resize", () => {
  ScrollTrigger.refresh();
});

// Or debounced for performance:
let resizeTimer;
window.addEventListener("resize", () => {
  clearTimeout(resizeTimer);
  resizeTimer = setTimeout(() => {
    ScrollTrigger.refresh();
  }, 200);
});

// Invalidate + refresh for matchMedia changes
gsap.matchMedia().add("(min-width: 768px)", () => {
  gsap.to(".box", {
    x: 300,
    scrollTrigger: {
      trigger: ".box",
      scrub: true
    }
  });
});

// matchMedia already handles refresh internally!

5 Performance — 60fps Best Practices

GSAP is already highly optimized, but these tips ensure buttery-smooth 60fps even on low-end devices.

✅ Do
  • → Animate only transform & opacity (GPU-accelerated)
  • → Use will-change: transform on animated elements
  • → Kill tweens with .kill() when leaving a page section
  • → Use force3D: true to promote to GPU layer
  • → Debounce resize handlers (200ms throttle)
❌ Avoid
  • → Animating width, height, top, left (triggers layout)
  • → Animating margin, padding, border (triggers layout)
  • → Creating tweens inside scroll or resize events
  • → Leaving unused ScrollTriggers alive (kill when done)
  • → Over-animating on mobile (reduce complexity)
// ✅ OPTIMIZED
gsap.to(".box", {
  x: 200,           // transform → GPU
  scale: 1.5,       // transform → GPU
  rotation: 45,    // transform → GPU
  opacity: 0.5,     // opacity → GPU
  force3D: true,    // promote to GPU layer
  duration: 1
});

// ❌ SLOW (triggers layout reflow)
gsap.to(".box", {
  width: 200,       // layout → CPU
  height: 150,      // layout → CPU
  top: 50,         // layout → CPU
  marginLeft: 20,   // layout → CPU
  duration: 1
});

GPU vs CPU: Browsers can render transform and opacity entirely on the GPU. Everything else (width, height, color, layout) forces a layout recalc on the CPU — that's what causes jank. GSAP automatically uses force3D in most cases.
