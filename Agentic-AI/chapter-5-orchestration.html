Orchestration

How the agent decides what to do, in what order, and how to combine tools to solve a real problem.

What is Orchestration? 🎼

"The logic that coordinates the model, tools, databases, context, planning, and execution."

Like an Orchestra

Without conductor 🎺💥🎻😵
Everyone plays randomly = noise
With conductor 🎼🎻🎺🥁🎹

2

Reflex Agent 🟢

IF condition THEN action. No AI reasoning needed.

if "weather" in msg:
  get_weather()
elif "logout" in msg:
  logout_user()

Why use it?

Don't waste expensive LLM calls deciding if "logout" means logout. 😂

Best for: keyword routing, simple lookups, basic automation.

3

ReAct Agent 🔵

ReAct = Reason + Act

The most fundamental agent loop. Think → Do → See → Think again.

The ReAct Loop

🤔 Reason
🔧 Act
👀 Observe
Reason again...

Example: Should I carry an umbrella?

Step 1 🤔
"I need current weather."
Step 2 🔧
get_weather("Patna")
Step 3 👀
Result: 🌧️ Rain expected
Step 4 🤔
"Rain → recommend umbrella."
"Rain is expected tomorrow, so yes — I'd recommend carrying an umbrella."

Planner-Executor 🟠

Create an explicit plan first, then execute each step.

👤 "Analyze my business"
🧠 Planner
Step 1
Step 2
Step 3
📄 Report

Advantages

✅ Clear decomposition
✅ Easy to debug
✅ Cost efficient

Cost Advantage

🧠 Powerful model → Create plan
⚙️ Smaller models → Execute steps

Reserve big models for planning.

5

Query Decomposition 🟡

Break one big question into smaller sub-questions, answer each, then synthesize.

Big Question
🧠 Decompose
X age?
🔍→85
Y age?
🔍→90
🧠 Compare → Answer

Giant questions are hard for one search. Decompose → Search each → Synthesize.

6

Reflection Agent 🟣

The agent checks its own work. Act → Check → Correct → Continue.

Reflection Loop

🤔 Think
🔧 Act
👀 Observe
🔍 Check my work
Correct
Continue
Wrong
Fix/Replan

Coding Agent Example

🔍 Read code → ✏️ Fix bug → 🧪 Run tests
❌ 3 tests failed → 🤔 "Null handling is wrong"
✏️ Revise → 🧪 Test → ✅ All pass!

⚠️ More reflection = more LLM calls = more cost & latency. Use when mistakes are expensive (finance, medical, critical systems).

7

Deep Research Agent 🔴

Combines Planner + Query Decomposition + ReAct + Reflection for large open-ended investigations.

More intelligence ≠ always better architecture.

Tool Selection 🎯

The agent must select the right tool from many available options.

Standard

LLM sees all tools, picks best one.

Small library (≤10 tools)

Semantic

Embedding search → only send relevant tools to LLM.

Large library (5000+)

Hierarchical

Category → Subcategory → Tool.

Huge / organized library

Tool Descriptions Matter A LOT

❌ Bad:
def process_numbers(x, y):
"""Processes numbers."""

😐 What does "processes" mean?

✅ Good:
def calculate_sum(x, y):
"""Returns sum of two integers.
Example: calculate_sum(5,3)→8"""

Name + Description + Example + Constraints

Selection Strategy Rule

≤10 tools
Standard
500+ tools
Semantic
5000+ organized
Hierarchical

Cheat Sheet 🏆

Orchestration Map

● Reflex — Input → Action
● ReAct — Reason → Act → Observe → Repeat
● Planner-Executor — Plan → Execute steps
● Query Decomposition — Big Q → Small Qs
● Reflection — Act → Check → Correct
● Deep Research — Combines several patterns
● Standard Selection — LLM picks from small list
● Semantic Selection — Embedding search for large list
● Hierarchical Selection — Category → Tool

Use the simplest orchestration pattern that can reliably solve the problem.

You don't need a Deep Research Agent to answer "What is 2 + 2?" 😂

The Most Important Thing

Orchestration ≠ just calling tools.

Orchestration = deciding how to use models, tools, context, memory, and intermediate results to accomplish a task.

Mini Challenge

"Find the bug in my Node.js API, fix it, run the tests, and if tests fail, revise the fix."

🔍 Find bug
✏️ Fix
🧪 Test
🔄 Revise if needed
Answer: ReAct + Reflection — Think → Act → Observe → Check → Revise
