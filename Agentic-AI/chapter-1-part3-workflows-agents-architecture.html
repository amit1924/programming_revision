The Most Important Question

Do I Actually
Need an Agent?

Choosing the simplest architecture that solves the problem — from scripts to workflows to RAG to agents.

Surprisingly, the answer is often NO.

The Core Problem

"In many real-world projects, choosing between a simple script, a deterministic workflow, a traditional chatbot, a retrieval-augmented generation (RAG) system, or a full-blown autonomous agent can be the difference between an elegant solution and an overengineered, hard-to-maintain mess."

The Mistake Beginners Make

Wrong Thinking
"I learned LangGraph, therefore
everything should be an agent."

That's like learning Kubernetes and deploying a calculator on it.

Right Thinking
"What is the simplest architecture
that can reliably solve this problem?"

4 Questions Before Choosing 🎯

1. Variability of Inputs

How predictable are the inputs?

"Add 5 + 10"
Very predictable
"Why are customers complaining?"
Highly unpredictable

2. Reasoning Complexity

Does it need to decide what to do next?

Follow instructions
Deterministic
"What should I do next?"
Dynamic decisions

3. Performance / Compliance

Need millisecond latency, deterministic behavior, or strict auditing?

Millisecond latency Regulatory compliance Auditability

LLM agent may be a bad choice

4. Maintenance Burden

Can your team realistically maintain this?

10-line script
Easy to maintain
LLM + Agent + Memory + Tools + RAG + VectorDB + Orchestrator + Observability + Guardrails
More things that can break

When NOT to Use AI 🚫

"If your inputs are fully predictable and every possible output can be described in advance, ordinary code is often better."

Log Parsing

2026-08-17 10:30:15—Server started
2026-08-17 10:31:22—DB connected
2026-08-17 10:32:04—Request failed
Don't use GPT
pattern = r"(\d{4}-\d{2}-\d{2})..."

Predictable input → predictable output = regex wins.

Embedded / Real-time

Sensor → CPU → Decision
Needs 2ms response
Calling external LLM:
Sensor → Internet → API → Model → Response → Internet → Device
😂

Latency-critical = use local deterministic code.

Regulated Systems

Aircraft safety controller
Medical device
Financial systems
You don't want:
Pilot: "What's happening?"
LLM: "Based on my reasoning, perhaps..."
🤣

Need fully deterministic and auditable logic.

Rule #1

If the problem is predictable + deterministic + performance-critical + highly auditable → Use normal code.

Don't add an LLM just because you can.

Deterministic Workflows 🔀

"Workflows make sense when the logic can be expressed as a finite set of steps or branches."

Invoice Processing Example

📄 Invoice
Identify format
CSV
JSON
PDF
Validate → Process or Flag Error
Valid → Process Invalid → 👤 Human

Workflow

Developer decides the path
A → B → C → D

Includes retries, backoff, branching — all predetermined.

Agent

Agent decides the path
A? B? C? Tool?
Another tool? Replan? Finish?

Dynamic path selection based on context.

Chatbot / RAG 📚

How RAG Works

📚 10,000 Documents
🔢 Embeddings
🗄️ Vector DB
🔍 Similarity Search
📄 Relevant Chunks
🧠 LLM
💬 Answer

RAG: "Here is information"

User: "How do I reset my VPN?"
→ Find documentation
→ Answer user
Done. Information delivered.

Stops short of autonomous, multistep planning.

Agent: "Here's what I think we should do"

User: "My VPN isn't working. Fix it."
→ Check documentation
→ Check user's account
→ Check VPN status
→ Run diagnostics
→ Reset config if needed
→ Test connection
→ If failed → escalate

Takes actions, not just retrieves info.

When Agents Are Appropriate 🤖

Inputs are:

Unstructured Novel Highly Variable

You need:

Dynamic planning Multistep reasoning Continuous feedback

Why You Can't Pre-code Every Scenario

"My laptop battery is swelling and might erupt."
"Why am I being charged for something I never ordered?"
"The delivery guy never came."
"I bought the wrong product and now I'm angry."
You can't realistically write if customer_says_X: do_A for thousands of variations.

Agent: "My battery is swelling"

Understand intent
Identify safety issue
Look up safety policy
Identify order
Determine appropriate response
Escalate to human
Provide safety instructions

The exact path wasn't hard-coded for every possible sentence — that's the value of contextual reasoning.

Supply Chain — Replanning

Situation:
Supplier A → 5-day delay
Inventory → falling
Demand → increasing
Weather → bad
Agent can:
→ Observe current situation
→ Calculate consequences
→ Check alternative suppliers
→ Compare prices
→ Replan shipments
→ Recommend action
Key word: REPLAN — the environment changed, so the system changes its plan.

5 Principles for Building Agentic Systems 🏗️

1

Scalability 📈

10 tickets/min → Works fine
1,000 tickets/min → Crash?
Solution: Distributed agents
Load Balancer
Agent 1 Agent 2 Agent 3

Docker, Kubernetes, queues, distributed systems — your existing knowledge matters here.

2

Modularity 🧩

Bad Architecture
Agent → 5,000 lines of code
├── model logic
├── search logic
├── database
└── everything else

Change one tool? 💥 Rewrite everything.

Good Architecture
🤖 Agent Core
SearchTool EmailTool DBTool

Each has a clear interface. Swap freely.

Why this matters even more with AI:
Today: Model A → Tomorrow: Model B. If tightly coupled = painful switch. With abstraction = flexibility.
Agent → Model Interface → GPT | Claude | Local
3

Continuous Learning 🔄

Problem: Agent keeps making the same mistake
Solution:
Feedback → Store Retrieve in future Prompt/tool changes Fine-tuning

Learning doesn't necessarily mean retraining — it can mean feedback loops, evaluation datasets, and prompt changes.

4

Resilience 🛡️

When API fails:
Bad: 💥 Agent crashes
Resilient approach:
Timeout → Retry
→ Fallback API
→ Tell agent
→ Agent changes strategy
Retries Timeouts Fallbacks Error handling Rate-limit handling Redundancy
5

Future-proofing 🔮

Don't Build This:
App → Vendor-specific API
→ Vendor changes API
→ 💀
Build This:
Agent → Standard Interface
Model A Model B Model C

Use open standards (OpenAPI) and modular designs to reduce vendor lock-in.

11

Organizing Teams Around Agents 👥

Don't Standardize Too Early

Day 1 Standardization
"EVERYONE MUST USE FRAMEWORK X"
→ 6 months later → Outdated → Everyone stuck 🤣
Right Approach
🧪 Experiment → Discover what works → 🏗️ Standardize successful patterns → Scale

One Standard per Large Group

Engineering Common standards
Security Common standards
Finance Common standards
Support Common standards

Consistency per group without forcing the whole company into one stack.

Knowledge Sharing

Flow:
Team A discovers something
→ Document result
→ Shared repository
→ Team B learns
→ Organization improves
Both matter:
Successful experiments
Failed experiments

If Team A finds "this fails badly under long contexts", Team B shouldn't discover the same thing 6 months later.

The Most Important Lesson ⭐

PROBLEM
How predictable is it?
HIGH → 📝 CODE
LOW → Need reasoning?
NO → 🔀 WORKFLOW YES → Need knowledge?
YES → 📚 RAG NO → 🤖 AGENT

If you remember only one sentence:

Use the simplest architecture that can reliably solve your problem.

Fixed transformation → 📝 Code Known steps + branches → 🔀 Workflow Answer questions → 📚 RAG Dynamic reasoning → 🤖 Agent

An agent is not just an LLM. It's a software system that needs scalability, modularity, resilience, evaluation, feedback, and governance.
