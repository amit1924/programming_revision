4

Stateful Tools 💾

Stateless (Safe)

add(5, 10) → 15

Nothing permanent changed.

Stateful (Dangerous) ⚠️

delete_user(123)

Changes the real system permanently.

The Real-World Horror Story

AI agent was supposed to optimize database performance but ended up deleting a large portion of production data.

This is why tool security isn't optional.

5

Never Give Unlimited SQL 🚨

❌ Bad: execute_any_sql()

@tool
def execute_sql(query):
  database.execute(query)

Model could produce: DROP TABLE users; 😱

✅ Good: Narrowly Scoped

get_user_profile() add_customer() get_order() update_address()

Each tool does one controlled thing. ✅

Principle of Least Power

Give the agent ONLY the permissions it actually needs.
✅ Agent needs 2 → Give 2
SELECT orders · SELECT users
❌ Agent needs 2 → Don't give 200
DELETE · DROP · ALTER · CREATE...

AI-Generated Tools 🤖

Normal: Developer builds tool

👨‍💻 → writes tool → 🤖 uses it

AI generates its own tool

👨‍💻 → gives API spec → 🧠 LLM → generates code → 🧪 test → 🔧 ready

Real-time Code Generation & Iteration

Analyze task
Generate code
Execute
Error: Missing param
Modify code
200 OK 🎉

But This Is Dangerous

⚠️ Poor code quality ⚠️ Security vulnerabilities ⚠️ Malicious injection ⚠️ Unauthorized access

Never treat "AI-generated code" as automatically safe. Human review before entering production.

Repeatability Problem

Traditional Software:
Input A → Same function → Output A → Same A → A
AI-Generated:
Input A → LLM → Code A → Later: Code B (!)

LLMs aren't deterministic — testing, debugging, and compliance become harder.

8

Tool Choice Configuration 🎛️

Four Modes

auto
🤖 "I'll decide whether a tool is necessary."

General agent behavior.

required / any
🤖 "You MUST call at least one tool."

When tool output is necessary.

none
🚫 No tools allowed.

Controlled environments / testing.

specific tool 🎯
"You MUST use get_weather()."

Deterministic behavior.

Production Use Case

"What's my account balance?"
Don't let LLM answer from memory. Enforce:
required tool
🔧 get_account_balance() → Real data ✅

Validation, Retry & Fallback 🛡️

Recovery Mechanism

🧠 LLM Response
🧪 Validate
Valid
Execute
Invalid
Retry
Still bad? → 🛟 Fallback

🧪 Validation

Expected: {"user_id": 123}
AI gives: {"username": "Amit"}
→ Reject & retry

Use Pydantic or jsonschema.

🔄 Exponential Backoff

Attempt 1 ❌ → wait
Attempt 2 ❌ → wait longer
Attempt 3 ✅

For transient failures like API timeouts.

🛟 Fallback Options

🔄 Backup API/model
💬 Ask user for help
💾 Use cached data
🛡️ Safe default

When retries exhausted.

The Most Important Lesson

Don't think "Tools make the agent powerful."
Think "Tools give the agent power, so tool design determines how safely that power can be used."

The Safety Pipeline

Narrow tools → Clear schemas → Least privilege → Validation → Logging → Retries → Fallbacks
