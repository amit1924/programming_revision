Chapter 4

Tool Use

Where an LLM goes from "I can tell you how" to "I can actually do something" — the bridge between reasoning and the real world.

LLM provides reasoning; tools give the ability to interact with the real world.

1

The Problem 🤔

A normal LLM:

👤 User → 🧠 LLM → 💬 Text
✅ Can answer
"What is 25 × 40?"
1000
❌ Needs live data
"Apple's stock price?"
No real-time access
❌ Needs action
"Send this email."
No email access

Solution: Introduce tools the LLM can call.

🌐 API 🗄️ Database 💻 Code
2

What Exactly Is a Tool? 🔧

"A tool is a capability or set of actions that an agent can perform to achieve an outcome."

Simplest tool = a Python function

def add(x, y):
return x + y

Normal usage: result = add(5, 3) → 8

With an Agent — The Interesting Part

"What is 5 + 3?"
🧠 LLM decides to use add tool
🔧 add(5, 3)
8
"5 + 3 = 8."

🔥 The model decides to use the function.

3

LLM Doesn't Execute ⚠️

The LLM doesn't directly run your Python function. Your application sits between the model and the actual tool.

🧠 LLM "I want to call add"
Tool call request
Your Python program
add(5, 3) → 8
🧠 LLM receives result

Creating a Tool 🛠️

Without @tool

def add_numbers(x, y):
    return x + y

Just a normal function. LLM can't see it.

With @tool

@tool
def add_numbers(x: int, y: int) -> int:
    """Adds two numbers and returns the sum."""
    return x + y

LLM can now see & select this tool. ✅

Why the Description Matters

Tool name + Description + Input schema
🧠 LLM decides: "Should I use this?"

The docstring isn't just for humans — the model uses it to decide when the tool is appropriate.

6

Naming & Design 🏷️

Bad Names

@tool
def do_something(...): ← 🤷

Model doesn't know what this means.

Good Names

@tool
def calculate_shipping_cost(weight: float) -> float:

Obvious what it does.

Single Responsibility Principle for Tools

❌ One giant tool:
🔧 database_tool
delete · update · insert · search · drop · change

Dangerous & confusing.

✅ Focused tools:
get_customer() update_address() search_orders() cancel_order()

Clear responsibility. ✅

⚠️ Broad or overlapping tool descriptions can cause confusion and poor tool selection. Make each tool's purpose distinct.

7

The Complete Tool Loop 🔄

🔥 The Most Important Pattern

👤 User
🧠 LLM — "Use add_numbers"
🔧 Tool call
🐍 Python executes
Result: 30
🧠 LLM — "The answer is 30"

bind_tools()

llm_with_tools = llm.bind_tools([add_numbers])

Before: no tools → After: 🔧 add_numbers()

invoke()

ai_msg = llm_with_tools.invoke(messages)

Model returns tool_calls if it decides to use a tool.

The Simple Mental Model

User: "What is 7 + 5?" → 🧠 LLM → tool = add, x = 7, y = 5 → add(7, 5) = 12 → 🧠 LLM → "7 + 5 = 12"

That's it. LangChain/LangGraph code makes this loop easier to manage.

8

Why Use a Calculator Tool? 🧮

LLMs can do arithmetic, but normal programming is much better at exact deterministic calculations.

Trusting LLM:
393 × 12.25 = ??? (may be wrong)
Using tool:
multiply(393, 12.25) = 4814.25 ✅
9

Local Tools 🏠

Run inside your application. Best where traditional programming is more precise than an LLM.

🧮 Calculator 📅 Date calculation 🌍 Timezone 📐 Unit conversion

"Convert 100 miles to km" → miles_to_km(100) = 160.934 — Precise. ✅

10

API-Based Tools 🌐

Access live external data — information not feasible locally.

🌦️ Weather 📈 Stocks 🌍 Translation 🗺️ Maps 📧 Email 💳 Payment

Weather Agent Example

"What's the weather in Patna?"
🧠 LLM
🔧 get_weather("Patna")
🌐 Weather API
32°C, Sunny
"Patna is currently 32°C and sunny."

APIs Introduce Real-World Problems

❌ Go down ❌ Timeout ❌ Bad data ❌ Rate limits ❌ Auth required ❌ Format changes

Your agent needs to handle failures: reliability, security, fallback providers, graceful error handling.

11

Security 🛡️

Suppose your agent has:

🔧 delete_user() 🔧 send_money()

The LLM can potentially select these. That's powerful.

Power + Autonomy = Risk

Only give models tools whose execution can be responsibly controlled and whose benefits outweigh the harms.

7 Things to Remember 🏆

1️⃣

Tool

A capability the agent can use: def add(a, b): return a+b

2️⃣

@tool

Tells LangChain to expose the function as an AI-callable tool.

3️⃣

Description

Helps the LLM know when the tool should be used.

4️⃣

bind_tools()

Makes tools available to the model.

5️⃣

Tool call

Model says: "I want to call add(a=5, b=3)"

6️⃣

Your app executes

Your Python program runs: add(5, 3) → 8

7️⃣

Result → LLM → Response

Tool result goes back to the model, which generates the final answer.
